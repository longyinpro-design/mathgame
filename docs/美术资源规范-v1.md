# 统一美术资源规范 v1

日期：2026-09-08。本轮为 imagegen 生成的美术母版包与工程化规格。素材尚未经过 Godot 导入及运行时验收。

## 视觉方向

原创 16-bit 像素风数学冒险：苔藓石质遗迹、黄铜机关、青绿色能量与温暖羊皮纸 UI。面向学龄儿童，表达好奇、探索和有挑战的古代谜题。

所有生成批次复用 `assets/source/style-master-v1.png`。它是本轮选定的连续性参考，尚未由用户封版。世界地图允许装饰性的舞台式俯视；实际数学棋盘采用水平/垂直正交布局，视角不参与数学判定。

主角色设定：棕色短发、青绿披风、赭黄色上衣、深蓝裤、棕靴和挎包。狐狸伙伴：橙色毛、奶油色嘴部与尾尖、青绿围巾。角色服饰、轮廓和光源保持一致；六个章节通过地表与边缘装饰区分。

配色参考：深蓝 `#223247`、深绿 `#315C4A`、苔绿 `#789C59`、青绿 `#438C91`、赭金 `#D7AD55`、羊皮纸 `#F3E4C0`、赤陶 `#BF755B`、淡紫 `#9D91BD`。这些是艺术方向目标，当前图片未执行严格调色板量化。

## 源图和运行时资源的边界

当前 `assets/source/` 文件保留 imagegen 原始生成或修订结果。美术预览可以直接使用这些文件。运行时图集需要进一步整备，不能根据提示词里的尺寸自动假定实际尺寸和帧布局正确。

`art/素材清单-v1.json` 记录实际文件尺寸、颜色模式、alpha 统计、SHA-256、用途、提示词和已知问题。Alpha 的存在只说明透明通道存在；不自动证明无光晕、角色完全不透明或边缘已达成品质量。

当前已知：

- 主角 v1 的棋盘格烘焙在 RGB 背景中，因此不作为透明精灵使用；保留为生成过程参考。
- imagegen 已生成主角 v2 背景提取版本，实测为 RGBA，存在完全透明像素。它的实际尺寸与最初要求不同，三行不能直接等分为整数高度；需要逐帧定义区域和脚底锚点。
- 主角 v2 包含部分透明像素，需在亮、暗两种背景上检查角色实体、细节边缘与残留光晕。
- NPC 源图第一行的狐狸视觉方向为正面、向右、背面、向左；切片命名应按实际图片，不能直接套用提示词顺序。
- 多数母版使用不透明底色，尚未全部转换为透明独立部件。
- 特效源图实际为 1254×1254，不能直接按 4×4 等分为整数帧，需要校准或重新排版。
- 地表样本和背景图尚未验证无缝拼接；房间背景为装饰底图，不能从绘图格子直接推导数学坐标。
- 美术地图中的钟面、刻纹等装饰不承载教学数值；读时与数值任务必须使用引擎生成的准确元素。

## Godot 导入规格草案

最终采用 Godot 4.x；进入实现时固定具体版本和目标设备。本轮没有创建或测试 Godot 项目。

建议以 1280×720 横屏作为布局参考，分别验证电脑和平板的交互尺寸。实际像素缩放方案要通过首个机关场景验证，再确定基础画布。文字使用独立清晰的字体渲染，不依赖极小的像素字。

运行时资源建议：

- PNG RGBA：角色、机关和独立道具。透明像素不得带来可见底色或描边污染。
- PNG RGB/RGBA：完整房间背景与地图，按用途允许不透明。
- 角色基础尺寸目标：64×96；地形目标：64×64；大型机关使用其整数倍。它们是待首场景验证的目标，不是当前源图实测尺寸。
- 图集的每个切片记录明确 `region`、脚底/旋转 `pivot`、动画名和顺序。不同大小的源帧应先稳定锚点。
- UI 面板记录九宫格边距，中央区域留给 Godot 文本；按钮 hover、pressed、disabled 和键盘焦点要有可辨差异。
- 像素纹理使用 nearest 采样；是否启用 mipmaps、具体压缩和缩放方式按镜头范围与目标平台实测。
- 碰撞形状、可点击区域、天平支点和棋盘格位由场景定义，不以透明像素或 AI 绘制阴影代替。
- 算式、数字、分数线、坐标、提示和题目由 Godot 动态渲染。颜色之外也使用位置、轮廓和图形传达状态。

对应官方工作流：[AnimatedSprite2D / SpriteFrames](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)、[TileMapLayer / TileSet](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html)。

## imagegen 生成记录

本轮使用内置 `image_gen` 工具，没有使用 CLI 或 API key 路线。每张图的完整提示词保存在 `art/prompts/`；后续生成应引用本轮母版和对应角色/部件源图，分别说明参考图和编辑目标。

生成与验收顺序：风格基准 → 分类别生成 → 视觉检查 → 尺寸与 alpha 实测 → 对问题单独修订 → 保存源图、提示词及清单。当前不批量切图、不量化色板、不把源码规格误报为已完成的引擎验证。

## 封版条件

1. 对照基准，确认服饰、视角、轮廓、色彩和光源一致。
2. 独立部件在纯白、深蓝和实际房间背景上均无底色或光晕问题。
3. 动画逐帧无角色比例突变、肢体错误、基线抖动和帧顺序错误。
4. TileSet 在实际地图上验证边缘、角落与重复纹理。
5. UI 实际承载中文题目后验证长度、对比度和触控尺寸。
6. 将通过上述检查的运行时资源与其版本、用途一同登记，再标记为封版。
