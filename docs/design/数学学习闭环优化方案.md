# 数学学习闭环优化方案

日期：2026-09-21。状态：提案，待确认目标年级后定稿文案颗粒度。

## 0. 一句话结论

**当前是一个高质量的「数学谜题游戏」，还不是「能学到数学的游戏」。** 关卡侧（做对）做到位了，闭环后三步——命名、复现、迁移——一步都没走完。优化的主战场不在关卡里，在**通关之后**。

投入配比建议反转：暂停表现层皮肤投入，把资源压到「做完之后发生了什么」。

---

## 1. 现状盘点

### 已经做对的（不要动）

| 项 | 证据 |
| --- | --- |
| 规则确定性判定 | 所有棋盘状态由整数/离散结构判定，视觉不承担正确性 |
| 反馈对应真实状态 | 提示逐条说明缺口（`current_hint.gd`），不逐项判分、不自动摆放 |
| 三级提示 | `content_catalog` 校验每关 `hints.size() == 3` |
| 数学验算 | `docs/production/math_verification.json`、各关 `verification.json` |
| 概念标注 | 每关 `concept_ids` 非空，校验在 `content_catalog.gd:134` |
| 存档健壮性 | 坏档保留原文件、保存失败保留待保存候选 |

这些在同类产品里是上游水平。问题不在质量，在**闭环断了**。

### 断掉的（证据路径）

**断点 1 · 命名缺失。**
`scripts/core/game_session.gd:523 _settle()` 只做四件事：发奖励、推进世界事件、写 `learning_record`、播一句 `Story.REACTIONS`。
`concept_ids` 共 30 个，全部只写进存档，**从未在界面上出现过一次**。
孩子解完 FL02（三门借光）听到的是「苔团：你把借出去的光找回来了」——没有一句话告诉他「你刚才用的是倒推」。

**断点 2 · 复现不足。**
18 关共 30 个 concept_id、40 个概念槽位。分布：

- 出现 3 次：`cargo_planning`、`operation_order`、`information_choice`（3 个）
- 出现 2 次：`balance_conservation`、`reverse_state`、`systematic_routes`、`optimization`（4 个）
- **出现 1 次：其余 23 个**

一次性概念（`parity_invariant`、`area_perimeter`、`pigeonhole_counting`、`lower_bound`、`decision_tree`、`double_counting`…）练完即弃，等于没学。

**断点 3 · 迁移系统是死代码。**
`scripts/learning/challenge_selector.gd` 当前实现：

```gdscript
# The tutorial scaffold and exercise recommendations were removed from the game.
static func support_for(...) -> Dictionary:
    return {"show_scaffold":false,"offer_transfer":false,"variant_id":"base"}
```

`learning_record.gd` 每次通关写 8 个字段（提示层级、撤销次数、观察历史、transcript、`evidence_kind`…），`game_session.gd:373` 只在建新 run 时调用一次 `Selector.support_for()`，**没有任何消费者**。这是墓碑，不是系统。

`docs/production/world_and_adaptation.md` 第 4 节写的选择策略（支架保留、迁移挑战提示）一条都没落地。

**断点 4 · 提示在替代思考。**
`current_hint.gd` 的 L3 直接给下一步动作，例如 `machine_hint` 返回「下一个槽位装入『加5』」。演示完即满足提交条件，玩家的手没有动过。
同时 `learning_record.gd:17` 用 `highest_hint > 0` 把整关记为 `assisted_completion`——判定本身是对的，但因为断点 3 存在，**用过提示就永久降级，没有任何回流路径**。

## 2. 优化方案（按性价比排序）

### P0-A · 通关「发现卡」

**做什么**：`_settle()` 之后插入一屏 15–25 秒的发现卡，作为结算演出的一部分，不弹窗打断。

三行内容：

| 行 | 内容 | 示例（FL02 三门借光） |
| --- | --- | --- |
| 1 | 这招叫什么 | **倒着推** |
| 2 | 一句话解释（孩子的话，不用术语） | 不知道开头是什么，就从结尾往回走，每一步做相反的事。 |
| 3 | 它还在哪儿出现过 | 借粮前的三座仓（FL03）也用了这一招。 |

第 3 行直接消费 `concept_ids` + `learning.observations`，已通关的关卡名点亮，未通关的显示为「？」。

**改什么**：`story_catalog.gd` 加一张 `DISCOVERIES` 表（36 关 × 3 行）；`forest_release.gd` / 集市关卡结算加一个面板。**不动任何关卡规则，不需要重跑数学验算。**

**为什么是 P0**：这是唯一能同时修复断点 1 和缓解断点 2 的动作，成本几乎全在文案上。

**文案样例**（其余关卡同规格补齐）：

| 关卡 | 概念 | 命名 | 解释 |
| --- | --- | --- | --- |
| FL03 | `temporal_constraints` | 先问是哪一刻 | 两句「一样多」可能说的不是同一个时刻。动手之前先定住时间点。 |
| FL04 | `equal_substitution` | 用一样重的换着比 | 三架灯两两合称，把两条合重并排，重复算的那架就露出来了。 |
| FL08 | `exhaustive_partition` | 一袋一袋数，不重不漏 | 按第一次向右给每条路分组，每组装几条是定死的；对不上就是漏了或放错了。 |
| FL11 | `irreversible_resources` | 给下一趟留余地 | 配重比货少，就必须有一趟拼着走——拼的那一趟不是浪费，是留给后面的。 |
| FL12 | `strategy_blocks` | 凑整组留给对手 | 每次能取 1~3 颗，就把 4 颗凑成一组；对手取几颗，你就补齐这一组。 |
| FL14 | `parity_invariant` | 看奇偶，不用算完 | 每次都是 ±2，落点的奇偶永远不变；从 0 出发永远到不了 9。 |
| FL16 | `area_perimeter` | 一样长的篱笆，围出的地不一样大 | 长和宽越接近，围出的格子越多。 |

---

### P0-B · 修回迁移与支架（最小可用版）

**不要重建自适应引擎。** 只落地 `world_and_adaptation.md` 第 4 节的第 2、3 条：

1. **支架回流**：同一 `concept_id` 连续 2 关 `evidence_kind == "assisted_completion"` → 下一关开局自动带图形支架（数轴 / 分组框 / 合重对照表），关卡入口给一句「上次这里卡了一下，这次先看这个」。玩家可手动关掉。
2. **迁移挑战**：同一 `concept_id` 在 **2 个不同 `family`** 下有 `independent_completion` → 航图点亮一枚「迁移挑战」灯。可选、不阻塞主线、奖励等同主线。玩家可拒绝。

**改什么**：`challenge_selector.support_for()` 恢复真实实现（规则表驱动，不拟合能力分）；`market_hub.gd` / 营地加一个灯位。

**成本**：中。需要 UI 灯位 + 支架绘制。但**不改关卡规则、不改存档结构**（`learning.observations` 已经存了 `context_id`、`variant_id`、`evidence_kind`）。

---

### P1-C · 三级提示从「给动作」改成「给镜头」

**改什么**：L3 演示关键一步之后，**自动回退到演示前的状态**，玩家必须亲手点那一下才算完成。

现在：`machine_hint` 说「下一个槽位装入『加5』」→ 玩家照做 → 满足提交。
改为：演示动画播放 → 状态回退 → 玩家自己点 → 满足提交。

`highest_hint` 仍记 3，`evidence_kind` 仍是 `assisted_completion`（判定不变，诚实），但手是动过的。

**rationale**：完全替代思考的提示对「学到」是负资产；保留认知负荷的最小单位是「自己动手做那一步」。

**成本**：小。改提示返回后的状态处理，不动提示文本。

---

### P1-D · 数学手记页

按 `concept_id` 归档「我发现的办法」，三档状态：

| 档 | 判定 | 显示 |
| --- | --- | --- |
| 见过 | 有 `assisted_completion` 记录 | 名字可见，图标半亮 |
| 自己做出来的 | 有 `independent_completion` | 图标点亮 |
| 在别的地方也用过 | 该概念在 ≥2 个 `family` 有 `independent_completion` | 图标加一道光 |

直接读 `profile.learning.observations`，**不需要新数据结构**。

**rationale**：给「学到」一个可见容器。现在收集物是剧情纪念品（MK16 挑纪念物），不是数学——孩子没有「我的数学收藏」这个概念。

---

### P2-E · 给 23 个一次性概念补复现

不新增关卡。两条低成本路径：

1. **发现卡第 3 行**就是干这个的（已在 P0-A 内）。
2. **复盘回指**：在后续关卡的开场白里，让伙伴说一句「这有点像上次那个……」，显式勾连。

**排到 P2 的理由**：先有容器（P1-D）和命名（P0-A），复现才有意义。顺序反了就是往空气里写字。

## 3. 明确不做的事

| 不做 | 理由 |
| --- | --- |
| 加新的资源/经济系统 | 每个 source 都要有 sink；当前没有第二个 sink，加了就是通胀定时炸弹 |
| 隐藏「能力分」/掌握概率 | `world_and_adaptation.md:57` 已明确排除；记录是历史事实，不是评级 |
| 思考倒计时 / 连击 / 排行榜 | 直接杀死「沉浸于思考」这个核心目标 |
| 用答对速度或错误次数调难度 | 同上，且会诱导猜答案 |
| 继续堆表现层皮肤 | 当前表现层已足够；对 2–3 年级孩子的沉浸贡献，「我又用了一次老办法」远高于新皮肤 |
| 「上线后再调」 | 没有验证路径的数值一律标 [PLACEHOLDER] |

## 4. 待验证的数值（全部 [PLACEHOLDER]）

| 项 | 假设值 | 验证路径 | 错了会怎样 |
| --- | --- | --- | --- |
| 发现卡停留时长 | 15–25 秒 | 真人试玩计时 | >40 秒说明打断心流，改为可跳过+手记回看 |
| 单关时长 | 4–8 分钟 | `策划案-v1.md` 目标值，未实测 | 若实测 12+ 分钟，关卡需要拆分 |
| 支架触发阈值 | 同概念连续 2 关 assisted | 试玩观察卡点分布 | 阈值 1 太敏感，3 太迟 |
| 迁移触发阈值 | 2 个不同 family 独立完成 | 试玩观察误判 | 场景换皮会被误判为迁移，需人工核对 family 差异 |
| 目标年级 | 二至三年级（`策划案-v1.md`） | 需用户确认 | 年级决定全部文案颗粒度，错了 108 条文案重写 |

## 5. 验证：先定义「坏掉长什么样」

| 失败信号 | 含义 | 处置 |
| --- | --- | --- |
| A · 发现卡被秒关（平均停留 < 3 秒） | 文案没信息量，或它在打断心流 | 改为默认折叠，进手记可回看 |
| B · 用过提示的孩子，下一关同概念仍然用提示 | 支架无效 | 检查支架是不是只换了个皮肤，没降认知负荷 |
| C · 数学手记页打开率接近 0 | 容器没价值 | 砍掉，把内容并进发现卡 |
| D · 换情境时孩子不提旧办法 | 迁移没发生 | 这是最坏信号：说明命名和复现都失败了，要回头重做 P0-A 的文案 |
| E · 孩子能背出「这招叫什么」但解不出变式 | 只记住了名词 | 命名成了标签收集，去掉第 1 行的术语感，改用动作短语 |

**注意**：自动化检查（`tests/forest/run_checks.py`、`tests/market/run_checks.py`）只能证明规则与存档正确，**不能证明学习发生**。学习效果只能靠真人试玩观察，且观察指标要先定义（见上表）。

## 6. 需要拍板的问题

1. **目标年级锁定几年级？** 二至三年级（现文档口径）还是放宽到二至四年级？这决定 36×3 条文案的颗粒度，写错要全量重写。
2. **P0-A 要不要先做 6 关做样板？**（建议 FL02、FL04、FL08、FL12、FL14、FL16，覆盖 7 个概念、含 4 个一次性概念）跑一轮真人试玩再铺量，比一次性写 36 关更稳。
3. **P0-B 的支架绘制谁来做？** 数轴/分组框/合重对照表这三种图形支架需要新美术，是新增工作量，不是纯逻辑改动。
