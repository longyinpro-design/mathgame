# FL07 两阶段玩法重做

目标：用户指出两种装法对任何输入均等价，要求重新修复玩法。本轮从“选正确算法”转为“确认性能相同→为保养档案还原原机历史顺序”。

实现：第一阶段有两台候选试开按钮，两种均算性能验证成功；该成功不假称已查清历史顺序。第二阶段提前显示两行候选推算，让玩家选择有区分力的取证位置，再对照原机记录归档。错误归档反馈明确该装法仍能育苗，只是与原机历史记录不符。外部试验可选，不暗示能找到区分这两种等价算法的输入。

存档：复用order/tested/revealed字段，数学参数、奖励、最终归档条件与存档ID不变。已有观察的旧档直接续查原装，无需重新试开；玩家真实存档只读，试玩使用独立副本并仅在副本内重摆。

自审：这是边界明确的本关UI/反馈/试开动作改动。检查试开只能选择符合账簿的候选，性能成功不提前结算，原有直接观察记录仍兼容，FL05分支不受新增order试开参数影响。未启动子Agent，未提交或发布。

验证：新玩法窗口覆盖两种性能成功入口、1280×720/960×540、阶段保存重开、取证、错误归档与正确完成。规则测试用独立表达式2*x+4验证两种候选对1..10输入的一致输出。旧窗口夹具增加实际试开点击后继续原有断言，不删除原先的观察、等价性或完成检查。最终精确命令、检查数量、日志与候选SHA256见verification.json。

最终结果：22项、2576/2576 PASS。新玩法窗口63/63、P3规则54/54。整章窗口在全量运行中断言全过但退出时有资源待释放错误；参照其他窗口夹具等待场景释放后单项107/107复验无资源错误。production源码未因该测试收尾修复而改变，21项不受影响检查复用；完整原失败日志与两个运行收据保留。
