# 现役表现层优化交付

基线为 `63b2488d6a89402245860fc5fb711538884143cf`，候选实现身份见 `candidate.json`。原始代码体检对应旧提交，其未提交文件清单不作为当前工作区事实。本次不改数学规则、关卡数据、学习记录、奖励、持久化与美术资源。

## 实现范围

1. 建立原生可见窗口测量工具，记录森林及 MK18 的帧间隔、draw calls、CanvasItem 重绘、节点数和选择操作同步耗时。功能测试的最小化窗口不作为性能依据。
2. 静止转移台按状态变化重绘；货物观察签按真实对象位置更新，覆盖第七件物品、吊篮与卸货偏移；地面和稳定的24点机台停止无效重绘。
3. 三门/粮仓选中、24点选牌/交换只更新已有节点，规则提交仍走原事务与刷新路径。
4. 现役森林与集市共用表现分支生命周期：隐藏、暂停、失焦或模态时冻结对应时钟，恢复继续；森林异步演出改为宿主绑定 Tween，失焦时不会继续提交动作。
5. 森林主场景落地八个常驻节点；营地、地区、剧情、手记、伙伴、回访和设置七个页面拆入 `forest_pages.gd`。宿主从基线1080行减至933行，页面模块173行；导航与事务所有权不变。

保留可见动画的正常帧率。没有依据把全部动态表现强制降为30fps；历史章节、全项目局部变量注解、磁盘清理和18关整体场景化均不属于原报告推荐执行线。

## 测量口径与限制

同一台 Apple M5 Pro、Godot 4.7.2、macOS Compatibility，前后使用逐字一致的测量脚本。每场景预热120帧、采集180帧，60FPS上限。帧间隔包含VSync及系统调度；`TIME_PROCESS` 是引擎间隔监视器，不能当作逐帧CPU采样。CanvasItem重绘计数表示重建绘制命令，不等同GPU draw call；缓存绘制不意味着GPU停止提交画面。

预热后恢复逻辑焦点，并记录可见表现分支的采样前后时钟；活动样本时钟不前进时拒绝该次测量。该检查排除整个采样区间完全停滞，不能单独证明中途从未失焦。默认剧情读货运层时钟，战斗读战斗层时钟，避免把正确冻结的隐藏层误当活动层。

选择操作的旧版会销毁并重建节点，新节点不在原draw signal监听集合中，不能用选择场景的总重绘次数作前后比较。运动测量夹具只驱动表现位置；交易、保存及真实按钮路径由独立功能门禁覆盖。

本次自动化证据覆盖本机1280×720和960×540，不代表触屏、其他平台、目标儿童理解度、学习效果或发行验收。未发布、未推送。
