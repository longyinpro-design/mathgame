# 森林来信：策划与素材落实 v0.4

日期：2026-09-09。状态：首章连续试玩；依据 `策划案-v1.md`、`产品方向-v0.3.md` 和现有可运行素材完善。六岛与108关仍是内容方向，本次交付是一条由已完成场景组成的连续旅程。

## 本次设计重点

让玩家知道为何出发、正在帮助谁，以及数学操作完成后世界和伙伴发生了什么变化。保留 v0.2 的两阶段约束与 v0.3 的直接晶体操作，把营地、探索、遭遇和归来串起来。每次完成一个目标后，都有下一步可以执行；也可以回营地休息并恢复。

## 可玩流程

| 节点 | 玩家行动 | 数学与观察 | 场景结果与推进 |
| --- | --- | --- | --- |
| 探险营地 | 读守桥人的来信，带阿橙出发 | 地图指明本次森林路线 | 森林可进入；石灵路线需先送种 |
| 森林断桥 | 走近断桥、石碑、守桥人，收集三条线索 | 六石各用一次、顶点被两路共用、远端最多交换两次 | 线索写入笔记，供能台开放 |
| 近岸供能 | 用1～6使三边各为10，主动试运行 | 同时满足三条约束，观察顶点的重复计数 | 12节桥板展开一半 |
| 远岸供能 | 保留原布局，规划最多两次交换 | 新目标来自原解的确定变式；六种起始解均有解且至少需两次交换 | 桥全部展开，过桥送达种子 |
| 晨种村口 | 看见幼苗出现，听到古林石灵的消息 | 手记保留刚才发现的关系 | 阿橙默契增长一次，开放古林遗迹 |
| 古林遗迹 | 走近石灵，拖动或点选晶体，再合力施法 | 总数14不变，右侧比左侧多4；唯一分配为5/9 | 错误保留布局；成功解除护盾、石灵让路 |
| 石灵之约 | 主动领取信物，再带阿橙回营地 | 记录“移一枚，差改变两枚”及提示使用 | 一枚信物、第二次默契成长，营地新芽开花 |

森林结束页可以直接进入古林，也可以先回营地。完成后两个地点均可回访，已领取奖励保持唯一。主线没有倒计时；演出时长与玩家思考时间分别对待。

## 伙伴成长与记录

阿橙依次表现为“初次同行 → 渐渐默契 → 共鸣伙伴”。成长由送种、领取信物两次具体故事事件产生；用提示、尝试多次或重新进入场景不会减少成长，也不会重复发放。结成石灵之约后，营地伙伴与手记中出现徽记。

手记收录两次共同发现，显示供能次数、施法次数和主动提示层数。默契表示角色关系，不作为学习掌握度；没有根据速度、单次答对或提示次数给孩子贴能力标签。当前对话与手记全部由作者编写。

## 工程与存档

- 默认入口为 `game/journey.tscn`；`scripts/journey/journey.gd` 管理营地和场景衔接，`camp.gd` 绘制营地，`store.gd` 校验与保存整条旅程。
- 原章节和遭遇通过原有store接缝保存到同一份v4 JSON；原数学判定和旧独立存档实现保持各自职责。v4不迁移或覆盖v2/v3玩家记录。
- v4文件同时包含两段状态、归来标记和声音设置。加载时验证字段、整数、数学状态、章节前后关系；JSON数值先通过范围与整数检查，再规范化。
- 正常操作保存稳定状态；退出场景先重试保存，成功后才移除场景。保存失败保留当前内存和现场，显示可操作的重试按钮；损坏记录被保护。
- 通关和奖励由既有确定规则判断。回访不提供清空旅程的入口，不叠加信物或默契。设置可回看，场景动画期间返回按钮锁定。

## 验收与边界

跨场景39项、原森林33项、原石灵36项真实窗口检查均通过；960×540窗口的原生坐标点击也通过。截图覆盖新营地、手记、设置、森林结束、古林操作、奖励与归来。最终评审及具体候选记录见 `试玩实现计划.md` 和 `playtest/v4/`。

自动化验证覆盖过程与正确性，不代表孩子首次理解目标的难度、真实游玩时长、学习效果或所有设备表现。当前字体依赖本机系统字体；没有完成平板实机、跨平台发行与独立安装包验收。

后续扩展应先通过真人试玩确认这条循环：是否理解出发目标、愿不愿意主动找线索、是否关注阿橙变化、失败后能否调整。在此基础上，再制作新的原创伙伴及其实际可操作能力、增加经求解器验证的内容变式；在线AI仍需明确服务、数据与成本约束后进入实现。
