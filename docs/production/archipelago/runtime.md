# 六岛运行说明 · v0.8.0

## 内容与入口

六岛稳定编号共108个：FL、MK、GW、GV、FW、SO各01–18。各岛01–12和17–18为14关主线，13–16为可选支线。原森林的并行前置按其原目录保留；新三岛以作者目录定义前置。只有前岛全部主线确实完成，下一岛才开放。

`game/archipelago.tscn`是默认入口。原森林、集市、工坊所有场景保留；通过群岛进入旧场景时，独立顶栏提供群岛往返，原画面等比缩放而不覆盖原控件。直接打开原场景时不新增顶栏。

## 模块与所有权

- `catalog.gd`：108个身份、岛屿和主线关系、只读作者内容缓存、规则实例缓存
- `session.gd`：群岛唯一写入者，命令版本检查、当前机关、冻结参数与队伍、奖励／学习／重试事务
- `legacy_evidence.gd`：只读原档适配器；不迁移或改写原档
- `level_host.gd`：新三岛共享输入、对白、反馈、暂停、标记、确认与保存阻塞界面
- 各岛`rules.gd`：不访问文件／场景的纯规则；操作产生新状态，完成独立重算
- 各岛`world.gd`：只读实际棋盘，绘制真实物件、路径、数量与完成后果

规则模块不以提交答案字段或已完成布尔值发奖。首领阶段的历史构造／动作由本岛规则验证；分支在已提交状态中固定或确定推导，读档不换题。作者答案与独立枚举结果只放在tests。

## 档案、奖励与恢复

新档是`user://profiles/archipelago-v1/save-v1.json`，与三个原岛的档案分开。

新挑战保存稳定`run_id`、内容版本、参数快照、阶段／对白停点、实际棋盘、最高提示层、尝试次数、同行队伍、观察签事实和重玩标记。UI选中物件、鼠标、观察签坐标、演出时钟与撤销栈为会话临时数据。退出后恢复同一稳定棋盘和已提交阶段，临时选中不构成进度。

顺序为：检查命令与版本 → 在副本上算下一状态 → 同事务计算完成／奖励／学习 → 验证并写临时文件、替换正式档 → 安装成功状态 → 显示后果。保存失败保留原状态和同一待写候选，阻塞其它命令；重试不重新计算奖励。

每关首通奖励由稳定reward_id唯一记账。森林已有reward_id和journey_exp只在群岛投影显示，绝不向原森林再发经验、木片、物品或建设。集市／工坊新增的是群岛汇总纪念；也不写它们的原档。

旧森林档可能只有合法历史进度而没有保存解答棋盘。适配器先通过原ForestSession整档验证，再保留去重的原始来源快照，按来源引用记“历史完成”；已有实际结果棋盘则直接验证棋盘。集市／工坊须通过各自当前规则验证且stage为complete。只有一个完成字段、损坏档和未知版本都不能解锁岛屿。

## 伙伴、练习与营地

阿橙初始同行；苔团、折羽、扣扣、嗒嗒、棱角、水沫、星鹭分别随真实章节里程碑加入。群岛中最多选择两位伙伴，下一次新挑战冻结选择，已开始的机关不会被改队。主线基本操作与观察工具不会因队伍选择消失。原森林的具体能力／装备与三项付费营地建设仍由原森林系统管理；群岛不伪造那些系统的状态。

新三岛的观察签是玩家自己放置的非答案标记，不自动选合法落点。用过的提示与观察工具是事实记录；撤销棋盘不抹掉这些事实。

每次真正完成的run都有独立事实记录，含情境、作者版本、提示层、尝试、支架和重玩标记。重复同参数即使未用提示，也只记“本次未用提示”，不称为迁移或掌握。旧档导入不推断求助程度。曾用提示且还没有同关无提示完成事实时，提供可跳过的再练建议；只推荐已经制作、验证的内容，不现场生成变式。

六岛纪念展示依真实主线完成解锁来信架、交易角、小机器、拼石台、水庭花园和航路灯塔；这是群岛的非消耗型纪念展示，不等同原森林购买建筑，也不是新的付费经济。

## 验证与明确边界

本轮使用Linux Godot4.6.3与Dummy音频，分别验证离散数学、规则与事务、真实窗口输入、两种分辨率截图。旧GW06/07/11的格式化常量对白改为实例初始化以兼容4.6，文本与规则未改。

新三岛是有主题的引擎绘制场景，几何、水面、网络和机关随实际状态变化；没有声称源像素美术精修相同、所有角色都有逐帧动作或所有过场达到完整动画制作标准。真实儿童理解度、奥数难度与趣味、学习效果、触屏、其它平台、音频听感、安装包与发行仍须对应验收。

在线AI、账户／云档、多人、支付、排行榜和家长学习诊断依原设计属于后续独立决策，本版均未接入，也不上传玩家档案。
