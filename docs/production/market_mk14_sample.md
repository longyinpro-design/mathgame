## 为什么重做

v1 的题目是「为 5 与 8 两笔订单分别配一次秤」：两单之间没有任何约束，第二单只是把数字换了一遍，而「1、3、9 两盘都能站」这件事 v1 在第一单就教完了——剩下的只是照葫芦画瓢，且与 MK06/MK11 的「凑一个和」是同一个数学对象。重做保留三进制砝码这个载体，另加一条本章别处都没有的硬规矩：**头一单的摆法随便摆，往后每一单只能从上一单记进账里的那一式挪一枚砝码，碰第二枚当场被拦下**。这条约束把题目从「会不会配平」换成「哪一单能走在中间」：4、7、13 三单各自只有一种摆法，而它们两两之间要挪的枚数是定死的（4↔13 一枚、13↔7 一枚、4↔7 两枚），于是六条挑单顺序里只有两条走得完。v1 的两个数（5 与 8）在 v2 里根本不再出现。

## 目标

- 摊子上只有老货栈借出的三枚砝码 `WEIGHTS = [1, 3, 9]`（`COUNT 3`、`WEIGHT_TOTAL 13`）：1 用扁圆码 `weight_small`、3 用六角码 `weight_hex`、9 用最高那只阶梯码 `weight_stepped`。每一枚有「架上／货盘／对面那盘」三个去处（`OFF/GOODS/FAR`），一盘一个长度 3 的 0/1 数组记它；同一枚在两盘都记 1 就是把它偷偷用了第二遍，`validate()` 直接拒。
- 街上停着三单真货：`ORDERS = [4, 7, 13]`、`ORDER_NAMES` 订单一/二/三、`ORDER_TAGS` 桥头灯行/中街油铺/河下米行、`ORDER_KITS` `parcel_small`/`parcel_medium`/`parcel_large`（三只油纸包按单大小一号一号往上走）。数字是货单上写好的，玩家不填也不改（`order_caption(2)` 原样给 `订单三 · 13 单位 · 河下米行`）；**谁先上秤由玩家点车挑**（`CARTS = [cart_left, cart_middle, cart_right]`，热点 `cart_0..2`、键位 `A/S/D`），货盘上同一时刻只压着一单。
- 算术事实（无头穷举过，不写死在文字里）：`placements()` 列 27 种摆法，`span_units() == range(1,14)` 且 1..13 每一单都有 `arrangements_for(n).size() == 1`（`spans_all()`）——27 种摆法与 −13..+13 一一对应。三单之间要挪的枚数同样唯一：`moved_indices(4,13) == [2]`（只有 9 从架上到对面）、`moved_indices(13,7) == [1]`（只有 3 跨过秤梁到货盘）、`moved_indices(4,7) == [1,2]`（两枚）。这三条另拿一遍对 27 种摆法的独立扫描对过账（`disagree == 0`）。
- 于是**走得完的顺序只有 `4→13→7` 与 `7→13→4` 两条**：无头把 6 条排列全部真走一遍（`serve_orders()` 逐步 `choose → arrange → advance×3`），2 条到 `complete`、4 条断链。断链分两种，屏上说法也不同：`4↔7` 互为前后单时第二单**当场写不进账**（`validate()` 的 `within_one_move` 拒掉，玩家连秤都抬不起来）；从 13 开局则前两单都兑得出去，死在第三单——`stuck()` 为真，柜面那一幕当场把这件事说出来。
- 设计陷阱就是玩家最先走进的那条路：13 单位那一单最大、三枚砝码全站到对面那盘一眼就看得平，所以最诱人也**必须走在中间**；而 4 与 7 看着只差 3 单位，动的却是两枚（`distant_pair() == [4,7,2]`，回执最后一行 `4 与 7 只差 3 单位，却要动两枚砝码` 由它现算）。
- 独有回报：右下角那具迷你铜秤重演**玩家真正记进账里的最后一式**，回执逐单说清起手那一式与每一步挪了哪一枚、从哪一头到哪一头，最后一行是三单之间的算术事实。不写森林存档、不发森林奖励；航图点灯由 `chapter_progress.gd` 读本关存档 `stage == "complete"`。

## 机制与入账时机

- 幕序八幕（`STAGES`）`arrival → approach → ready → puzzle → weighing → result → delivery → complete`，动画三段（`ANIMATIONS`）`approach 1.8s / weighing 2.4s / delivery 3.8s`（`configure()`，`mk14_scene.gd:29`），沿用宿主的暂停、跳过与失焦自动暂停。开场三句是衡伯 → 扣扣 → 小岚（`LINES`）：扣扣第二句先把「砝码站在对面那盘不就行了」这个想当然摆到台面上，小岚第三句讲定「货压在左边这只货盘上，砝码两边都能站，一枚最多上一次秤。\n摆法我们不给你，秤也不提前说话——抬起来才知道。哪一单先上秤，你点车挑」——挑单这件事在玩家拿到第一下之前就已经说完。
- `puzzle` 一幕的说法分四态（`puzzle_line()`）：走死了 → `stuck_line()`；没接单 → `点街上那三辆车挑一单：A、S、D，或者点一下车顶板。\n接了单才轮到砝码——这一单只能从上一单那一式挪一枚。`；头一单（`served` 还空）→ `头一单随便摆：点砝码挪一格，摆好按「抬秤验收」。\n秤抬起来之前不预告平不平。`；往后每一单 → `上一单记下的那一式钉在秤座上方：这一单只许从它挪一枚砝码，第二枚一碰就被拦下。`
- 秤在摆放全程锁着制动：`braked()` 只要幕不在 `weighing/result` 就为真，`beam_angle()` 恒为 0.0；柜面式子牌只复述玩家摆出来的那一式（`Rules.equation(state)`，如 `货 13 = 砝码 9 + 砝码 3 + 砝码 1`；还没挑单时是 `点街上那三辆车，挑一单先上秤`），既不含「平」也不含「差」。哪头沉、两盘各多少、差几单位一律要等提交之后抬起秤来才作数。
- **柜面不判分**：`status_line()` 只有 `已交 %d 单 · %s`（后半句是「还没接单」或「这一单挪了 %d 枚」——这一枚数就是本关新规矩的账），两盘各压多少、哪头沉都不写在这里。`shortfalls()` 只管「手底下还没动手」两条：`街上三辆车还没有一辆被你点中：先挑一单，衡伯才把货搬上货盘。` 与 `三枚砝码都还在架上：先请一枚上秤，空盘配不出这一单的货。`；两条同时成立时宿主会拼成 `…（还有 1 处没有归位）`，整句 809 像素比口述板内框 798 还宽，靠 `AUTOWRAP_WORD_SMART` 折进第二行——实窗按 `get_line_count()` 与逐行高度复核它真的留在板里，而不是把字画到旁边的货上。
- **只许挪一枚是规则层的事实，不是弹窗**：`moved()` 拿此刻与上一单的记账摆法比（`diff_sides`），`can_touch()` 只放行「一枚都还没挪」或「碰的正是已经挪过的那一枚」；`place_weight()/return_weight()` 越界就返回空字典，画面随即去问 `touch_refusal()` → `%d 单位那一枚已经挪过了：一单只许挪一枚，先把它挪回原处。`（点名的是已经挪过的那一枚，玩家不必猜是哪一步越了界）。能动几枚还写在架上那一格的 tooltip 尾巴里（`这一枚已经挪过了，这一单只许挪一枚。`），不用点了才知道。把那一枚**挪回原处**就不算挪过第二枚，这一单重新从头挑——实窗走的就是这一条回退。
- 提秤不看对错：`advance()` 在 `puzzle` 只要 `ready_to_weigh()` 成立就把秤抬起来并 `weighs += 1`。抬起来之后 `result_lines()` 如实给两行（`货盘这一头沉下去了：货盘 10 单位，对面那盘 1 单位。` / `7 单位的货还压在盘上：两盘差 9 单位，秤没平，这一单就走不了。`），用的全是玩家自己摆出来的那几枚；配平了返回空数组、直接进交付。没有训斥模态、不弹「再想想」、画面上也没有「该点哪一枚」的记号。
- 记账只发生在交付放完那一格：`weighing` 平了才进 `delivery`，此刻 `served` 还没这一单、`built_*[order]` 还空着；交付动画把这一单的货搬回**自己那辆车**（`parcel_leg(index)` → `[起点, 终点, 走了几成, 起点那头, 终点那头]`，`carry()` 带 `CARRY_ARC 46` 的抛物线；`parcel_foot()` 画落点、`parcel_spot()` 给车顶板那句话，飞行过半就算落进新那一头），动画走完 `advance()` 才调 `booked()` 抄下这一式并把 `order` 收回 `NONE`——下一单接哪一单仍由玩家挑，账上那一式则钉在秤座上方当起点。三单都记完就是 `complete`，镜头退回整座庭院（1.0、偏移 0）。
- 交付那一刻的木牌说实话，且分两分支（`mk14_world.gd:414-418`）：`served` 还空着时写 `%s 签了收 · 这一式从架上摆起`，之后才写 `%s 签了收 · 只挪了一枚砝码`。头一单是三枚一枚一枚摆出来的，把它的收条写成「只挪了一枚」就是替玩家记下一件没发生过的事——这一条是本轮复核叫出来的，无头两条措辞各钉一个分支，实窗在头一单与第二单各读一次牌。
- 三条回退分得很清：`result` 之后 `next`（「回到秤前再摆」）回 `puzzle`，摆法原样保留、一枚砝码都不扣，那一次抬秤是发生过的事；撤销快照只存 `{goods, far, order}`（`snapshot()`），`restore()` 只在 `puzzle` 生效且结果必须重新通过 `validate()`，所以 `served/built_*/weighs` 退不动、快照里同一枚站两盘也退不回；「重摆」是**整条链重排**——`cleared()` 把三枚放回架上、三单货退回各自的车、`served` 与 `built_*` 全部清空，只留下 `weighs`（抬过几次秤是街上已经发生过的事），确认文案由 `reset_prompt()` 现算并随 `delivered` 改口：`三枚砝码放回架上、三单货退回各自的车？\n已经交出去的 2 单也会退回街上，重新排过，秤仍然锁着。`，一单没交时是 `…\n这一单还没交出去，秤仍然锁着。`。链子一环扣一环，留下任何一环都不算重摆，所以这话必须说在按钮前面。
- 走死了不藏：`stuck()` 为真时 `puzzle_line()` 直接给 `三单里只剩 7 单位那一单，可从 4 单位记下的摆法起，两枚砝码都得动。\n要接着走下去，就按「重摆」把三枚放回架上，从头挑一单。`（剩哪几单、从哪一式起、要动几枚、退路是哪颗按钮，全由 `remaining_units()`/`served`/`diff_sides` 现算），与 MK02、MK17 同一套诚实写法。走死的现场仍然可以接单、抬秤，秤也照样如实沉下去——只是这一单怎么走都走不通。
- 倾角只是演出：`tilt() = clampf(difference / FULL_TILT 3, -1, 1)`，画面按同一个符号换算成 `MAX_ANGLE 0.14` 弧度，从不参与判分；配平那一次是 `MAX_ANGLE * 0.55 * sin(progress·PI·2.4) * (1 - progress)` 的一阵轻晃（实窗按 `0.0 < |angle| < 0.09` 断过），没配平就一头沉到底并向货盘这头带负号（实窗按 `angle < -0.1` 断过）。砝码挪盘那一下由世界自己的时钟下落（`track_changes()/drop_at/drop()`，`DROP_TIME 0.24`、`DROP_LIFT 18`），挑单那一下的搬运同理（`pick_at`、`PICK_TIME 0.6`）；基类 `landing()/hide_while_moving()` 那条 0.28 秒的落地锁对 kit 关卡不生效（MK02/MK03 已记），本关不占它。
- 每步操作先原子落盘再生效（宿主 `commit()`），写盘失败弹「重试保存」、重试才把这一笔发布；换砝码、换单、撤销、重摆都会把上一句按旧现场说的话当场收回（宿主在 `apply_committed()` 里清 `message`），玩家看到的永远是此刻的账。

## 存档字段

- 独立存档 `user://profiles/market-mk14-1/save-v1.json`（`chapter_catalog.gd:48`；`configure()` 只在 `save_path` 为空时填默认值，试玩注入的 `/tmp` 路径不会被盖掉），schema 由 `scripts/market/mk14_rules.gd::validate()` 把关。
- 字段十二个：`sample="market-mk14-1"`、`stage`（八幕之一）、`beat`（0–2，只有 `arrival` 能停在半句）、`order`（0–2 或 `NONE = -1`，表示还没挑单）、`goods`/`far`（两条长度 3 的 0/1 数组，当前这一式）、`built_goods`/`built_far`（各三条，与订单数同长的**记账摆法**）、`served`（已经签了收的订单号数组，无重复、≤3 项，**顺序就是玩家挑单的顺序**）、`weighs`（≥0，抬过几次秤）、`hint`（0–3）。v1 那个 `delivered` 计数器换成了 `served` 数组——「第几单」不再够用，「按什么顺序兑的」才是这一关的账。
- 结构层拒读并把原文件交给 `save_repository._protect()` 保留的情形：非字典、别的关卡的 `sample`、未知 `stage`、`beat`/`hint`/`weighs` 越界或为负、`order` 不是 −1..2、盘数组短一截或多一枚（`[1,1,0,0]`）、把 2 当成「这枚上了两次秤」、半枚砝码（`0.5`）、`goods` 写成字符串 `"110"`、同一枚同时站在两盘、`served` 含重复或越界、`built_*` 条数与订单数不符、缺字段（少一个 `far` 或 `served` 都算损坏而不是默认值）。
- 语义层再拒：`stage != "arrival"` 却 `beat != 2`（凭空跳步）；`arrival/approach/ready` 里已经动过砝码、抬过秤或交过单；`order` 指向已经签了收的那一单（交出去的货不会再压回盘上）；`weighing/result/delivery` 却 `order < 0`；这四幕却 `weighs < 1`（没抬过秤却写着秤在半空）；`result` 幕立在两盘一样重的那一式上（结果牌不能压在平秤上）；`delivery` 幕两盘不平；`built_*` 里任何一笔记下的摆法其实配不平它自己那一单的货、或没交出去的那几格不是空盘；**`served` 里相邻两单的记账摆法差过一枚以上**（这就是本关的规矩本身，伪造一份「两枚都挪」的账读不进来）；此刻盘上的摆法离上一单的账超过一枚（`within_one_move`）；`complete` 却不是三单齐、或收摊时现场与最后一单记下的那一式不一致。JSON 把 1 读成 1.0 由 `Content.normalize_numbers` 归回整数，嵌套的 `built_*` 往返后一字不变，好档不被误判。

## 操作与键盘

- 鼠标热点八个，全部由 `build()` 经宿主 `add_hotspot()` 注册（`mk14_scene.gd:80-86`）：`rack_0/rack_1/rack_2`（`target(rack_spot(i), SLOT_SIZE 52, SLOT_LIFT 44)`）、`pan_1/pan_2`（按 `GOODS=1`、`FAR=2` 编号，所以没有 `pan_0`；`target(pan_cargo(side), PAN_SIZE 96, PAN_TOP 60)`）、`cart_0/cart_1/cart_2`（`target(cart_station(i), CART_SIZE 120, CART_LIFT 130)`）。每个 ≥48 逻辑像素、1280×720 画框之内、两两不抢同一个像素，且都不压到底部按钮排；命中区一律按梁锁着时的静止位置算（`pan_cargo()`），画面按当前倾角画（`live_cargo()`），两者永不各算一套。热点只在 `puzzle` 一幕存在，抬秤与走位期间连 `rack_0` 都点不到（实窗在 `weighing` 里逐颗验过）。
- tooltip 全中文且永不预告结果：架上一格是 `%s 还在架上：点一下请它上秤，先站到对面那盘，再点一次才到货盘 · 键盘 %d`，已在盘上的是 `%s 正站在%s：点一下挪去%s · 键盘 %d，或按 %s 让它直接回架`，越界时再补 `\n这一枚已经挪过了，这一单只许挪一枚。`；两只盘只念不动（`%s上站着：%s。` + 对面那盘补 `这一盘不装货，只站砝码。` + `要挪砝码就点架上那一格；两盘平不平，抬了秤才知道。`，空盘念成「空盘」而不是 0 单位）；三辆车各说各的现在（未接 `%s · %d 单位：点一下接这一单，货从车上搬上货盘 · 键盘 %s`、已接 `%s：这一单已经接了，%d 单位的货正压在货盘上`、已交 `%s：这一单早就配平交出去了，货在自己车上`）。
- 键盘：`1/2/3` 与鼠标走同一条 `do_cycle()`（一站一站挪：架上 → 对面那盘 → 货盘 → 架上，`NEXT = [FAR, OFF, GOODS]`，绝不一步跨过秤梁）、`Q/W/E` 把手里那枚请回架上（`RETURN_KEYS`，本来就还在架上时如实说 `%s 本来就还在架上。`）、`A/S/D` 挑街上那三辆车（`CHOOSE_KEYS`，与 `do_choose()` 同一入口）；宿主的 `Space` 抬秤验收、`Z` 撤销、`H` 请扣扣提醒、`X` 重摆、`Esc` 暂停动画，动画中另有「暂停动画 / 跳过当前动画」。`ready` 一幕的简报两行把这三组键位一次交清（`点街上那三辆车挑一单，货就搬上货盘；头一单的摆法随便摆。\n点砝码挪一格（架上 → 对面那盘 → 货盘），摆好抬秤。`）。每条「· 键盘 X」都由无头逐条兑现（点击与按键各跑一遍再比现场）。

## 边界与已知限制

- 美术全取 `art/market-kit-v1/manifest.json` 的 `oil` 站位与拆件，关卡里没有第二套坐标系：底景 `assets/runtime/market/kit-v1/backgrounds/oil-courtyard-clean-v1.png`；`oil` 的站位只有四个——`scale_foot 640,527`、`cart_left 348,384`、`cart_middle 607,384`、`cart_right 859,384`；代码用到的 kit 拆件十一件：`scale_stand`、`scale_beam`、`scale_pan`、`weight_small`、`weight_hex`、`weight_stepped`、`parcel_small`、`parcel_medium`、`parcel_large`（v2 三单三尺寸，v1 只用后两只）、`delivery_cart`（三辆车共用）、`receiving_tray`（既当砝码架也当纪念物底座），另有直接预载的扣扣两张 `koukou-v1/tie-parcel.png`、`koukou-v1/waving.png`。**没有新裁图、没有手写 manifest 已给的挂点**。
- 铜秤是三个静态 sprite 由一条挂点链接起来的：`stand.pivot → beam.pivot`、`beam.left_hook/right_hook → pan.suspension`（正好等于 `scale_pan` 自己的 `anchor_px`，所以画出来的盘永远脱不开梁钩）、`pan.cargo` 才是盘底放货那一点。座、梁、盘共用一个组装系数 `SCALE_FACTOR 0.85`（清单给的紧凑示尺寸 94/224 ≈ 180/431 ≈ 100/239 ≈ 0.42，照它立在 1280×720 的庭院里只有 90 像素高），与第五幕 MK11 那一具同值、同一套 `weight_*`——**但本关运行时不 preload、也不依赖 MK11 的任何文件**，判秤整个实现在 `mk14_rules.gd`（只有无头检查 preload `mk11_world.gd` 用来对这两个常量，注释里写明了这一点）。**没有摇摆骨架**：`draw_scale_frame()` 用 `draw_set_transform(pivot_at, angle, Vector2.ONE)` 让梁绕 `pivot` 整根旋转，两只盘只跟着梁端平移、自身保持水平；衡伯拔制动销、扣扣扶秤盘都只在台词里发生。
- 排布全是算术：砝码架自 `RACK_OFFSET (-330, 40)` 起三格 56 一排（`grid()`）；盘内那一横排 50 一格、以 `pan.cargo` 居中，头一格永远是这一单的货（哨兵 `PARCEL_SLOT = -1`），其后按 9、3、1 从大到小，读起来就是柜面那一式从左到右——一盘要站下「一单货 + 三枚砝码」四件，最外缘必须落在 `239×0.85 = 203` 像素宽的盘沿（±101.6）之内，货与砝码的宽度（`WEIGHT_WIDTHS [40,46,40]`、`PARCEL_WIDTHS [42,47,52]`）都被这条盘沿算死，无头拿满载那一式复核过；三辆车各自的车板位跟 `delivery_cart` 自己的 `cargo_left/cargo_right` 挂点走（`cart_scale() = suggested 206 / atlas 647`）；扣扣脚点与右下角的迷你铜秤都由 `scale_foot()` 加偏移推出（`KEEPER (-500, 33)`、`SOUVENIR_FOOT (470, 63)`），纪念物是同一套构件、同一条挂点链再整体缩 `SOUVENIR_SCALE 0.42`。
- **人物**：`oil` 场景没有人物的连续动画，清单也不给衡伯/小岚站位，两位只在台词里说话，画面上没有他们；三单的主顾只出现在车顶板、热点文字与货单里（陶姨本关一句台词也没有）。扣扣只有 `tie-parcel`/`waving` 两个离散姿态，`delivery` 过半或 `complete` 才换挥手那一张，她站的那一点由秤脚推出（`keeper_foot()`），不是站位。`KEEPER` 的横向 −500 是两头夹出来的：再往左，1.10 贴脸镜头下整只贴图（`tie-parcel` 327×244、`waving` 336×246，均按 0.5 画）的左沿就出框（−540 时切掉 43.9 像素）；再往右，她的不透明框右沿（tie 219.75 / waving 222.0）就压上 `receiving_tray` 的左沿 223.0，而那颗 `receiving_tray` 正是本关的砝码架。按贴图 `get_used_rect()` 量，这一档在贴脸镜头下摆放那姿的外框左沿是 +2.275 像素；挥手那一张宽 9 像素，同一镜头下外框左沿读到 −0.2，但贴图左边那 4 像素是全透明留白（换算后 2.2 像素），画出来的身子左沿仍在 +2.0 处，而且她只在 `delivery` 过半之后与 `complete` 亮这一姿——那两幕镜头已经拉回 1.0。
- **引擎画的部分**：回执那张板（`UIStyle.panel()` + `UIStyle.text()`，`mk14_scene.gd:137-142`）、架上空位的金色光圈（`socket()`）与其上的数字、两只盘名（`mark()`）、所有车顶板与读数板（`plaque()`）、封包与砝码上的单位数字、脚下阴影（`contact()`）都由代码画在世界坐标里；清单里没有砝码架、没有回执纸、也没有读数板。本关不点灯串，所以也没有 MK12 那套 `LANTERN_GLASS` 测算法。
- CJK 不依赖自动换行：`plaque()/words()` 从不折行，所以每块牌的字面都取自规则层同一份来源，无头按牌子内宽（`rect.size.x − 20`、牌上真正的 13/14/15 号）逐条量过，实窗再按同一套公式复核「牌不压牌、牌不压实物」；台词、提示与结果都写成「一行最多一处显式换行」并在画进屏幕前按渲染真正用的字号（`UIStyle.text` 把 20 抬 22、18 抬 22）量过宽度。回执板 `Rect2(24,76,306,182)` 上沿 76 躲开画到 68 的抬头板、右沿 330 躲开 338 起口的口述板、下沿 258 与左侧那辆车的车顶（画到 267）错开；六行 16 号字（主题落到 18 像素）行距压到 0 才是 126 像素，150 的内框刚好装下——实窗逐行取 `get_line_height()` 累加后与纸边比，没有一行挂在纸外。
- 无自动求解、无高亮答案、无提示罚分、无失败台账：`weighs` 只老实记抬了几次秤，被拦几次、差几单位都不入账；`result → puzzle` 之后现场一枚不减。
- **一处设计代价**：走死了没有半程回退，唯一的退路是「重摆」，而重摆会把已经签了收的那几单一起退回街上。这是这条链的必然结果——每一单都从上一单的摆法挪一枚记下来，留下任何一环都不算「重摆」；代价已经写进按钮前面的那句问话里，也让 `stuck_line()` 在被判定为走死的那一刻就说清退路，不留「玩家以为自己还有救」的空档。
- **v2 换掉的 v1 看得见的东西**：① 两单 → 三单，且三单之间加了「只许挪一枚」这条硬约束（`validate()` 从此检查 `served` 相邻两式的差）；② `delivered` 计数器换成 `served` 数组，底栏从「上秤 N 枚 · 抬 M 次」改成「已交 N 单 · 这一单挪了 M 枚」；③ 目标条从「两盘一样重这一单才走」改成把新规矩整条摊在屏上；④ 提示第三档从「示范这一单怎么摆」改成「示范谁走在中间」这一整条链的关键；⑤ 回执从逐枚迁移一句话改成起手一式 + 每一步挪了哪一枚从哪儿到哪儿 + 两单之差的算术事实；⑥ 交付木牌分「从架上摆起／只挪了一枚」两分支。
- **旧存档**：`sample` 与路径沿用 `market-mk14-1/save-v1.json`。v1 那份记录里没有 `served` 字段、`order` 的取值界也不同（0–1），v2 的 `validate()` 会把它判为不可读并走宿主的 `protected` 分支——原文件保留在原地，模态里一次「保留原档并重新开始」就从本关第一幕重走。这是本重设计唯一一处玩家可感知的代价。
- 入口 `game/market_mk14.tscn`（航图上 MK14 是待点亮的支线，开门条件 MK11 完成），或双击 `启动千灯集市MK14样板.command`。从航图进来完成后给「返回千灯航图」，单独启动本关给「回千灯航图」（`Rect2(690,646,280,54)`，`mk14_scene.gd:146`）；摆到一半从航图进来时底栏另有「千灯航图」一枚。
