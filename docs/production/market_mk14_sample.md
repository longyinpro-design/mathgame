## 目标

- 摊子上只有老货栈借出的三枚砝码 `WEIGHTS = [1, 3, 9]`（`COUNT 3`、`WEIGHT_TOTAL 13`），造型与第五幕那具秤上的同一套：1 用扁圆码 `weight_small`、3 用六角码 `weight_hex`、9 用最高那只阶梯码 `weight_stepped`（`WEIGHT_KITS`）。每一枚有「架上／货盘／对面那盘」三个去处（`OFF/GOODS/FAR`），一盘一个长度 3 的 0/1 数组记它，同一枚在两盘都记 1 就是把它偷偷用了第二遍，`validate()` 直接拒。
- 街上接连送来两单真货：`ORDERS = [5, 8]`、`ORDER_NAMES` 订单一/订单二、`ORDER_TAGS` 桥头灯行/中街油铺、`ORDER_KITS` `parcel_medium`/`parcel_large`（8 单位那一单明显大一号）。数字是货单上写好的，玩家不填也不选（`order_caption(1)` 原样给 `订单二 · 8 单位 · 中街油铺`）；货压在指定的货盘上，玩家只挪砝码、不解锁新砝码。
- 1、3、9 是一组三进制砝码：`placements()` 列出 27 种摆法（每枚三个去处），`span_units() == range(1, 14)` 且对 1..13 每一个 n 都有 `arrangements_for(n).size() == 1`（`spans_all()`）——27 种摆法与 −13..+13 的整数差一一对应，所以 1 至 13 的每一单都只有一种摆法配得平。本关只走 5 与 8 两单：`5 + 3 + 1 = 9`、`8 + 1 = 9`（`FIVE_GOODS [1,1,0] / FIVE_FAR [0,0,1]`、`EIGHT_GOODS [1,0,0] / EIGHT_FAR [0,0,1]`），不要求逐个摆一遍（`market_chapter.md:238`）。
- 这一关的陷阱就是人人都想的那第一步：把砝码统统放到对面那盘。只往对面堆能配出的量是 1、3、9 的子集和 `one_pan_sums() == [0, 1, 3, 4, 9, 10, 12, 13]`，5 与 8 都不在其中——总得有一枚站到货物这头来。第二级提示把这张清单念给玩家听，但不替他挪。
- 玩家做的三件事：点架上那一格就把那一枚往前请一格（架上 → 对面那盘 → 货盘 → 架，`NEXT = [FAR, OFF, GOODS]`）、点两只盘或三辆车只把玩家自己摆出来的东西照念一遍不动现场（`read_pan()`/`read_order()`）、摆好按「抬秤验收」。独有回报只有本关自己那一幕的结局：右下角那具迷你铜秤重演玩家真正记进账里的那一式，回执逐枚说清谁留在原地、谁挪了地方（`migration_parts()` → `1 留在货盘 · 3 从货盘挪到砝码架 · 9 留在对面那盘`）。不写森林存档、不发森林奖励；航图点灯由 `chapter_progress.gd:40-47` 读本关自己的存档 `stage == "complete"`。

## 机制与入账时机

- 幕序八幕（`STAGES`）`arrival → approach → ready → puzzle → weighing → result → delivery → complete`，动画只有三段（`ANIMATIONS`）`approach 1.8s / weighing 2.4s / delivery 3.8s`（`configure()`，`mk14_scene.gd:23`），沿用宿主的暂停、跳过与失焦自动暂停。开场三句是衡伯 → 扣扣 → 小岚（`LINES`），逐句「继续听他们说」推进：扣扣第二句先把「砝码站在对面那盘不就行了，哪头沉哪头轻，谁看不出来？」这个想当然摆到台面上，小岚第三句讲定「货压在左边这只货盘上，砝码两边都能站，一枚最多上一次秤。\n摆法我们不给你，秤也不提前说话——抬起来才知道」；第三句之后 `approach` 才把镜头推到秤前。
- 秤在摆放全程锁着制动：`braked()` 只要幕不在 `weighing/result` 就为真，`beam_angle()` 于是恒为 0.0（`mk14_world.gd:212-219`）；`puzzle` 一幕柜面只复述玩家摆出来的那一式 `Rules.equation(state)`（`货 5 + 砝码 3 + 砝码 1 = 砝码 9`、什么都没摆时是 `货 5 = 空盘`），既不含「平」也不含「差」（无头与实窗都按这两个字断过）。哪头沉、两盘各多少、差几单位一律要等提交之后抬起秤来才作数——这就是「提交在盘面读数之前」这道制动。
- **柜面不判分**：`shortfalls()` 只管「手底下还没动手」这一条——`三枚砝码都还在架上：先请一枚上秤，空盘配不出这一单的货。`；提秤不看对错，`advance()` 在 `puzzle` 只要 `ready_to_weigh()` 成立就把秤抬起来并 `weighs += 1`。抬起来之后 `result_lines()` 如实给两行：`%s沉下去了：货盘 %d 单位，对面那盘 %d 单位。` 与 `%d 单位的货还压在盘上：两盘差 %d 单位，秤没平，这一单就走不了。`，用的全是玩家自己摆出来的那几枚；配平了它返回空数组、直接进交付。没有训斥模态、不弹「再想想」、画面上也没有「该点哪一枚」的记号。
- 三条回退分得很清：`result` 之后 `next`（「回到秤前再摆」）回 `puzzle`，摆法原样保留、一枚砝码都不扣，那一次抬秤是发生过的事；撤销快照只存 `{goods, far}`（`snapshot()`，`mk14_scene.gd:127`），`restore()` 只在 `puzzle` 生效且结果必须重新通过 `validate()`，所以 `order/delivered/weighs` 退不动、快照里同一枚站两盘也退不回；「重摆」的确认文案由 `reset_prompt()` 现算（宿主在弹窗打开那一刻才读它，`level_host.gd:269-274`），随 `state.delivered` 改口：`三枚砝码全部放回架上？\n已经配平交出去的那一单不会重来，秤仍然锁着。`，第一单还没交出去时是 `…\n这一单还没交出去，秤仍然锁着。`，`cleared()` 只清空两盘，问过的提示等级保留。挪不动时也各自说清：`这一枚现在挪不动：秤还没走到跟前，或它已经站在你要去的那一盘。`、`%s 本来就还在架上。`。
- 记账只发生在交付放完那一格：`weighing` 平了才进 `delivery`，此刻 `delivered` 仍是上一格的值、`built_goods[order]` 还空着；交付动画把这一单的货搬上交货车（`cart_bed(2, index)`），同时把下一单的货推上同一具秤，两单都走同一条 `parcel_leg(index) → [起点, 终点, 走了几成, 起点算站在哪儿, 终点算站在哪儿]`（`carry()` 带 `CARRY_ARC 46` 的抛物线；`parcel_foot()` 画落点、`parcel_spot()` 给车顶板那句话，飞行过半就算落进了新那一头），动画走完 `advance()` 才调 `booked()` 抄下这一式、`delivered += 1`、`order += 1` 回 `puzzle`——第二单开局时三枚砝码还留在原地，玩家只需要挪。两单都记完就是 `complete`，镜头退回整座庭院（1.0、偏移 0）。
- 倾角只是演出：`tilt() = clampf(difference / FULL_TILT 3, -1, 1)`，画面按同一个符号换算成 `MAX_ANGLE 0.14` 弧度，从不参与判分；配平那一次是 `MAX_ANGLE * 0.55 * sin(progress·PI·2.4) * (1 - progress)` 的一阵轻晃（实窗按 `|angle| < 0.09` 断过），没配平就一头沉到底并向货盘这头带负号。砝码挪盘那一下由世界自己的时钟下落（`track_changes()/drop_at/drop()`，`DROP_TIME 0.24`、`DROP_LIFT 18`），撤销与放回只是消失、不演第二遍；基类 `landing()/hide_while_moving()` 那条 0.28 秒的落地锁对 kit 关卡不生效（MK02/MK03 已记），本关不占它。
- 每步操作先原子落盘再生效（宿主 `commit()`），写盘失败弹「重试保存」、重试才把这一笔发布；换砝码、撤销、重摆都会把上一句按旧摆法说的话当场收回（宿主在 `apply_committed()` 里清 `message`），玩家看到的永远是此刻的账。

## 存档字段

- 独立存档 `user://profiles/market-mk14-1/save-v1.json`（`chapter_catalog.gd:48`；`configure()` 只在 `save_path` 为空时填这个默认值，`mk14_scene.gd:22`，试玩注入的 `/tmp` 路径不会被盖掉），schema 由 `scripts/market/mk14_rules.gd::validate()` 把关。
- 字段十一个：`sample="market-mk14-1"`、`stage`（八幕之一）、`beat`（0–2，只有 `arrival` 能停在半句）、`order`（0–1）、`goods`/`far`（两条长度 3 的 0/1 数组，当前这一式）、`built_goods`/`built_far`（各两条，与订单数同长的记账摆法）、`delivered`（0–2）、`weighs`（≥0，抬过几次秤）、`hint`（0–3）。
- 拒读并把原文件交给 `save_repository._protect()` 保留的情形：非字典、别的关卡的 `sample`（写成 `market-mk11-1` 也算外来）、未知 `stage`、`beat` 越出 0–2、`hint` 越界或为负、`order` 指到没送来过的单、`weighs` 为负或带小数、`delivered` 越出 0–2、盘数组短一截或多一枚（`[1,1,0,0]`）、把 2 当成「这枚上了两次秤」、半枚砝码（`0.5`）、`goods` 写成字符串 `"110"`、同一枚同时站在两盘、缺字段（少一个 `far` 算损坏而不是默认值）。
- 语义层面再拒：`stage != "arrival"` 却 `beat != 2`（凭空跳步）；`arrival/approach/ready` 里已经动过砝码、抬过秤或交过单（含「开局就把 9 画上秤」）；`puzzle/weighing/result/delivery` 的 `delivered != order`（第二单开工时第一单还欠着）；`weighing/result/delivery/complete` 却 `weighs < 1`（没抬过秤却写着秤在半空）；`result` 幕立在两盘一样重的那一式上（结果牌不能压在平秤上）；`delivery` 幕两盘不平；`complete` 里某一笔记进的摆法其实配不平它自己那一单的货、或账上那一格是空盘、或收摊时现场与最后一单记下的那一式不一致。JSON 把 1 读成 1.0 由 `Content.normalize_numbers` 归回整数，嵌套的 `built_*` 往返后一字不变，好档不被误判。

## 操作与键盘

- 鼠标热点八个，全部由 `build()` 生成、经宿主 `add_hotspot()` 注册（`mk14_scene.gd:71-76`）：`rack_0/rack_1/rack_2`（`target(rack_spot(i), SLOT_SIZE 52, SLOT_LIFT 44)`）、`pan_1/pan_2`（按 `GOODS=1`、`FAR=2` 编号，所以没有 `pan_0`；`target(pan_cargo(side), PAN_SIZE 96, PAN_TOP 60)`）、`cart_0/cart_1/cart_2`（`target(cart_station(i), CART_SIZE 120, CART_LIFT 130)`）。每个 ≥48 逻辑像素、1280×720 画框之内、两两不抢同一个像素，三格架的命中框还整排落在 `receiving_tray` 的 174 宽之内；命中区一律按梁锁着时的静止位置算（`pan_cargo()`），画面按当前倾角画（`live_cargo()`），两者永不各算一套（`mk14_world.gd:130-133`）。热点只在 `puzzle` 一幕存在，抬秤与走位期间连 `rack_0` 都点不到。
- tooltip 全中文且永不预告结果：架上一格是 `%s 还在架上：点一下请它上秤，先站到对面那盘，再点一次才到货盘 · 键盘 %d`，已在盘上的是 `%s 正站在%s：点一下挪去%s · 键盘 %d`；盘上是 `%s上站着：%s。`（对面那盘补一句 `这一盘不装货，只站砝码。`）再跟 `要挪砝码就点架上那一格；两盘平不平，抬了秤才知道。`，空着的那盘念成「空盘」而不是 0 单位；车是 `%s：%s。点一下让扣扣把这单再念一遍。`，交货车是 `交货车：已经签了收的 %d 单都停在这儿。`。
- 键盘：`1/2/3` 与鼠标走同一条 `do_cycle()`（一站一站挪，绝不一步跨过秤梁）、`Q/W/E` 把手里那枚请回架上（`RETURN_KEYS`，`ready` 那一幕的简报第二行就把这条交给玩家：`点一下挪一格；按 Q、W、E 让手里那枚直接回架。`）；宿主的 `Space` 抬秤验收、`Z` 撤销、`H` 请扣扣提醒、`X` 重摆（宿主底栏那颗按钮上写着）、`Esc` 暂停动画，动画中另有「暂停动画 / 跳过当前动画」。每个热点 tooltip 末尾那句「· 键盘 %d」由无头检查逐条兑现（只有架上那三枚写这句话）：三种现场（三枚全在架上／一枚站在货盘／一枚站在对面）× 三枚砝码共 9 处，把「点这一下」与「按那个键」各演一遍再比现场，写错键或点了是另一回事都当场报错。
- 按钮与坐标：`puzzle` 一幕由宿主给出 `撤销 Z Rect2(24,654,124,46)`、`重摆 Rect2(162,654,110,46)`、`请扣扣提醒 Rect2(286,654,168,46)`、`抬秤验收 Rect2(1020,646,235,54)`（`submit_label()`）、状态文字 `Rect2(470,656,300,42)`、摆放中途可走的 `千灯航图 Rect2(786,654,124,46)`；非动画幕走 `stage_labels()` 的那一枚 `next Rect2(982,646,274,54)`（「继续听他们说 / 走到摊前 / 开始配秤 / 回到秤前再摆 / 再配一次」）。镜头 `zoom_stages = ["puzzle","weighing","result"]` 三幕贴着铜秤与砝码架 1.10、偏移 −64/−43，`ready` 由宿主的同一条规则接着贴住（`puzzle` 在 `zoom_stages` 里就不弹回，免得两下硬跳），`approach` 渐进收拢，`delivery` 从第一格就往回收、四成五的时长（3.8s 里约 1.7s）回到整座庭院并保持——这三条都在宿主 `update_camera()` 里统一负责（`level_host.gd:104-116`）。抬头板 `Rect2(24,20,410,48)`（内框 382，`level_host.gd:158-160`）、口述板 `Rect2(338,98,826,86)`、目标条 `Rect2(442,20,790,48)` 在 `arrival/delivery/complete` 三幕由宿主收起。
- 单行栏与三级提示：`goal_line()` `两盘一样重这一单才走 · 1/3/9 各一枚 · 两盘都能站`，`status_line()` `上秤 %d 枚 · 抬 %d 次`——提交之前只报玩家自己做过的事，两盘各压多少、哪头沉都不写在这里（本章契约里说的备注栏在本关就是这个钩子，没有另外的 `notes()`）。`hint_texts()` 三档、每档刚好两行并装进口述板内框 798：`两盘一样重，这一单才走得掉。\n货压在货盘上，砝码两边都能站，一枚不能用两遍。` → `先只把砝码全站到对面那盘：凑得出 0、1、3、4、9、10、12、13。\n里面没有 %d——总得有一枚站到货物这头来。` → `这一单的摆法只有一种：货 5 + 砝码 3 + 砝码 1 = 砝码 9。\n点一下架上的砝码，让它一站一站挪过去。`，第三级那句由 `arrangement_caption()` 从 27 种摆法里现算（跟着 `state.order` 换成 `货 8 + 砝码 1 = 砝码 9`），是数学事实不是作者另写的答案；不减奖励、不代挪、不画高亮，`hint` 到 3 封顶。
- 柜面木牌由世界层 `signs()` 给（`mk14_world.gd:381-413`）：三张车顶板（248 宽、14 号）只写「哪一单、几单位、现在在哪」——`订单一 · 5 单位 · 上秤了`、`订单二 · 8 单位 · 在车上`、`交货车 · 已交 %d 单`，那半句「在哪」逐字读的是 `parcel_spot()`，与货此刻真正站的那一格同一个来源（无头按 63 个现场复核过），`complete` 一幕整排收起；两只盘底贴 `货盘`/`对面那盘`（`mark()` 居中，不是木牌）；`puzzle` 一张 `Rules.equation(state)`（340 宽）加一张 `三枚砝码 · 点一下挪地方`（248 宽，钉在 `rack_foot().x` 正下方，挪动架子它跟着走），`weighing` `制动已松 · 秤杆抬起来`，`result` `两盘差 %d 单位 · 这一单还不能走`（与台词板报同一个差），`delivery` `%s 签了收 · 砝码一枚没换`，`complete` 是 `迷你铜秤 · 两单的摆法` 加两笔记进账的真摆法。

## 边界与已知限制
