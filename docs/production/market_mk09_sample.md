## 目标

- 街上从左到右五个摊（`STALLS` 取 manifest 的 `stall_left/stall_midleft/stall_middle/stall_midright/stall_right`），与 `ACTORS ["甲","乙","丙","丁","戊"]`、`GOODS ["布","油","纸","铃","绳"]`、`GOODS_FULL ["布卷","灯油","纸卷","铜铃","捆货绳"]`、`KIT_GOODS ["cloth_bolt","oil_bottle","paper_roll","brass_bell","rope_spool"]` 同下标：每摊门口挂着你自己那件货，门前摆一只 `receiving_tray`，门面上刻着 `ACCEPT [[1,3],[2],[0],[0,4],[3]]`——甲能收油或铃、乙只认纸、丙要布、丁能收布或绳、戊只认铃。没有一摊肯收自己手上那件（检查逐条数过 `ACCEPT[i].has(i)` 为零）。
- 数学真值是一张整体对应：`lines[收货摊] = 出货摊`。`mk09_rules.gd:3-5` 的头部注释与检查同时钉住——120 种完整牵法（`permutations()` 枚举出的 5 阶全排列）里**只有 1 种**成立，就是 `SOLUTION [1,2,0,4,3]`：甲←乙、乙←丙、丙←甲 转成三摊一圈，丁←戊、戊←丁 对换一次，`cycle_lengths(SOLUTION) == [3,2]`、`shape(SOLUTION) == SHAPE_CYCLE "三摊转一圈，两摊对换"`。120 种里 44 种把五件货全挪动（错位排列），24 种把五摊挤成一条大环（`cycle_lengths == [5]`），**24 种全部被拒**且每一条的第一句都点名是 `SHAPE_RING "五摊挤进一个大环"`；把 7776 种草稿形状（每格 `-1..4`，含重复与自牵）全扫一遍也只数出同一个解。
- 玩家真正做的动作只有三个：点一摊挂着的货（拿在手里，再点同一摊就放手）、点另一摊门前的收货盘（牵好一条线；盘上原来那条自动回到街上）、点有线的收货盘把那条线拉回；五件货各走一次之后按 `一次交上这条线` 一次交上整条街。规格点名的三种错法都允许被真的牵出来——把货绕回自己摊、把同一卷布同时许给两家、把五摊挤成一个大环——因为只有在提交那一刻才由 `shortfalls()` 逐条点名，草稿本身不是错误。
- 状态栏与街面 tally 牌只报此刻的账（`线 %d / 五 · 满意 %d / 五`、`线 %d 条 · 满意 %d 摊`），永远不说「你错了」；`satisfied()` 与 `drawn()` 由规则层现算，画面不判分。
- 独有回报只有本关自己那一段收束：五摊各自点头之后檐口亮起街上第一段灯串（`lantern_string` 加五点玻璃光晕），回执复述玩家真的入账的那五条线并给出口诀；不写森林存档、不发森林奖励，航图点灯由 `chapter_progress.gd` 读本关 `stage=="complete"`。`tests/market/run_checks.py:69` 给本关写的限制原文是 `the ring belongs to this level, no cross-stall balance or camp resource`。

## 机制与入账时机

- 幕序七幕 `STAGES = arrival → approach → ready → puzzle → exchanging → delivery → complete`，带动画的只有 `ANIMATIONS = ["approach","exchanging","delivery"]`，时长由场景 `durations` 给：`approach 1.7s / exchanging 3.2s / delivery 3.4s`（检查里另有一条守着 `"puzzle" not in ANIMATIONS`：牵线不是动画）。开场三句（`LINES`：扣扣 → 小岚问「五摊一起换，还得两两凑成一对吗」→ 扣扣「你们牵线，一次换完」）逐句按 `继续听他们说` 推进，第三句按钮换成 `当众叫齐五摊`；`ready` 是一个不带动画的停点（`开始牵线`）。暂停、跳过与失焦自动暂停沿用宿主（`level_host.gd:75-78` 只在 `state.stage in rules.ANIMATIONS` 时因焦点丢失而冻结并把按钮改成 `继续动画`）。
- **入账只有一处，且写在规则头部注释里**（`mk09_rules.gd:6-8`）：`lines` 只是街面上牵着的线，一件货都还没挪；只有按下 `一次交上这条线` 并通过 `shortfalls()` 之后，`advance()` 才 `booked = lines.duplicate(true)` 并把 `hand` 归 `-1`、进 `exchanging`。每摊最后拿着什么、谁把货许给了谁，永远由这两个数组现算——`goods_after(plan)`（规则层，未牵线的那一格货仍算留在原摊）→ `world.goods_held()`，画面与按钮文案不存第二份归属，所以把一条线拉回（`cut_line`）不会留下幻影货权。检查用一条 25 格穷举（每个 giver × 每个 receiver）复算「牵上再撤销，街上什么都不剩」，并断言 `goods_after(空) == [0,1,2,3,4]`。
- `is_booked()` 才是通关判据：五格都非负、没有一摊收自己、一件货不许两家，且每格都落在 `ACCEPT[receiver]` 里；`solved(state)` 就是 `is_booked(state.lines)`。`exchanging/delivery/complete` 三段各自再要求 `is_booked(booked)` 且 `lines == booked`，所以演出途中街上的线就是入账的那一批，改不动也换不了。
- **柜面不判分**：`shortfalls()` 只在按下提交之后说话，宿主 `level_host.gd:203-207` 取第一条并附 `（还有 %d 处没有归位）`，用词全是玩家自己牵的那几条——`%s同时许给了%s：一件货只能有一个新主人。`（实机串 `布卷同时许给了丙摊、丁摊：一件货只能有一个新主人。`）、`%s摊的线绕回了自己：%s留在原摊，不算换出去。`（`甲摊的线绕回了自己：布留在原摊，不算换出去。`）、`%s：先想想哪两摊能自己对上。`（`五摊挤进一个大环：先想想哪两摊能自己对上。`）、`%s摊还没有接到线：它%s。`（`甲摊还没有接到线：它能收油或铃。`、`戊摊还没有接到线：它只认铃。`）、`%s摊接到的是%s，可它%s。`（`丙摊接到的是油，可它只认布。`）。大环那一格先说结构、再逐摊补五条（检查数到 `ring.size() == 6`）。被拒之后 `stage`、`lines`、`booked`、`hand` 一个字节都不动，没有训斥模态、不弹「再想想」、画面上也没有「该点哪一块」的记号。
- 只有拿起/放手/牵线/拉回会改现场：`pick()` 再点同一摊即放手、`connect_line()` 只写一格（原来的那条自动回收，名字避开 `Node.connect`）、`cut_line()` 只把那一格打回 `-1`、`clear_street()` 一次清空整条街。场景层里 `choose_good` 用 `commit(next, history)`（历史不追加＝拿起与放手不占撤销步数），`choose_tray` 走宿主的 `place()`（追加 `snapshot()` = `{lines, hand}`）。拿不起/牵不动时各说一句手感话：`这一摊的货现在拿不起来。`、`手里还没有货：先点一摊挂着的那件，再点收货盘。`、`这条线拉不动。`
- `exchanging` 的 3.2 秒里五件货一起起飞、各算各的相位：`carry_plan(p)` 用 `clampf((p - 0.08 * giver) / 0.55, 0, 1)` 错开出货摊，沿自己那条线从 `good_spot(giver)` 弧到 `tray_spot(receiver) - (0, TRAY_RISE)`，途中减去 `sin(phase·PI) · ARC_LIFT[receiver] · 0.5`；`in_flight()` 把 `phase < 1` 的算作在空中、`phase == 1` 的按收货摊记 `landed`，状态栏 `已落定 %d / 五件` 直接引这份世界状态。相位为 0 时每一件货的 `at` 与 `home` 距离小于 0.5（实窗逐条比过），所以画面上不会出现「已经消失又还没到」的空档。
- `delivery` 的 3.4 秒里 `draw_lanterns()` 的强度是 `smoothstep(0.1, 1.0, progress)`（`complete` 恒为 1.0），五盏玻璃各自 `clampf(strength * 5 - index * 0.8, 0, 1)` 一盏盏跟上；扣扣的姿态由 `draw_figure()` 判 `complete` 或 `delivery` 且 `progress > 0.6` 才从 `KOUKOU_TIE`（`tie-parcel.png`）换成 `KOUKOU_WAVE`（`waving.png`）。目标条在 `arrival/delivery/complete` 三幕由宿主收起（`level_host.gd:162`）。
- 每步操作先原子落盘再生效（宿主 `commit()` → `repository.write_profile(candidate, rules.validate)`），写盘失败把这一笔压在 `pending` 并弹 `重试保存`，重试成功才发布；`apply_committed()` 顺手清空 `message`，所以撤销、重摆之后不会留着按旧摆法说的那句话。落盘失败注入用 `repository.fail_at = "open"/"flush"`，实窗与无头各验一次「失败的换货提交一格都不入账」（`state.stage == "puzzle"` 且 `booked` 全空），重试之后才整批入账。
- 新牵上的那条线独占宿主 0.28 秒的落纸锁：`begin_land(previous)` 只在前后都在 `puzzle` 时把 `land_place` 记成 `"tray"` 与那一格，`landing("tray", i)` 期间 `add_hotspot()` 一律 `disabled = modal or transient > 0`（实窗按真实按下-抬起抓到 `game.transient > 0` 且 `good_0/tray_0` 同时置灰）。刚落线只在盘口亮一下 `socket()`——落下的是这条承诺，货还挂在原摊。撤销/重摆的确认文案：`把街上的线全部拉回？\n一件货都还没挪动。`（`继续牵线` / `全部拉回`）、`重新体验五摊换货这一幕？`（`留在街上` / `重新体验`，宿主再补一行 `只重置本关，不改变其他关卡与森林岛进度。`）。

## 存档字段

- 独立存档 `user://profiles/market-mk09-1/save-v1.json`，schema 由 `scripts/market/mk09_rules.gd::validate()` 把关；`configure()` 只在 `save_path` 为空时填这个默认值（检查断言注入的 `/tmp` 路径活过 `configure()`）。
- 字段七个且只有七个（`fresh().keys().size() == 7`）：`sample="market-mk09-1"`、`stage`（七幕之一）、`beat`（0–2，只有 `arrival` 能停在半句）、`hint`（0–3）、`lines`（街上的线，`-1..4`）、`booked`（真正换出去的那一批）、`hand`（手里拿着哪一摊的货，`-1..4`）。`hand` 是要落盘的：`puzzle` 幕攥着一件货是合法存档，但 `stage != "puzzle"` 时 `hand` 必须是 `-1`。
- 拒读并把原文件交给 `save_repository._protect()` 保留的情形（检查逐条构造）：非字典、`{}`、`[]`、字符串、`5.0`、别的关卡的 `sample`、缺 `sample`、未知 `stage`（`"swapping"`）与数字 `stage`；`lines` 里出现 `-2`、`5`、`1.5`、`"4"`、`null`，数组短一截或多一格，缺 `booked` 或缺 `hand`；`hint == 4` 或 `-1`、`beat == 3` 或 `"2"`、`hand == 5`。
- 语义层面再拒：`arrival/approach/ready` 却带着草稿线或已入账的批，或 `hint != 0`；`puzzle` 却 `booked != empty_lines()`（不存在「先换好再改线」）；`exchanging/delivery/complete` 却 `booked` 为空（凭空伪造）、`booked` 里含重复许给两家/自牵/大环/一摊都不满意的批、或 `lines != booked`（演出途中把某条线换成 `[1,2,0,4,4]` 记不进）；`stage != "arrival"` 却 `beat != 2` 由 `arrival` 的逐拍推进保证。草稿的宽容与入账的严格是分开的：`plan(1,2,0,0,-1)` 这种双重许诺在 `puzzle` 里是合法存档（`validate()` 放行）、却永远通不过 `advance()`。JSON 把 3 读成 3.0 由 `Content.normalize_numbers` 归回整数。
- `restore()` 只在 `puzzle` 生效，且快照必须同时带 `lines` 与 `hand`、长度与值域合法、回退结果重新通过 `validate()`：缺 `hand`、缺 `lines`、四格数组、`9` 越界一律拒绝回退；`exchanging` 之后不许用快照把已经入账的换货重新打开。实窗另有一条：重读存档 `game.state == on_disk` 且 `hint` 用过的等级一起回来。

## 边界与已知限制
