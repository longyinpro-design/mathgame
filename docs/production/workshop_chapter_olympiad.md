# 齿轮工坊：三年级奥数关卡改版

2026-09-22。用户已认可 GW01「被蒸汽抹去的货单」的难度，并要求按此水平继续修改后续关卡。本文是 GW02～GW18 的新玩法依据，替代原设计相同编号的数学规则、目标与解法；保留原稿的人物弧线、场景路线与章末出海方向。当前只完成设计模型，未将这些关卡实现为可玩场景。

参照：已实现的 [GW01契约](workshop_gw01_sample.md)。原章节稿在 `.scratch/workshop-design-20260922/docs/production/workshop_chapter.md`（6f97064）；其中 GW01 的23根整托引入已经由现行24根倒推货单替代，后续台词按新货单衔接，不能沿用旧数字。

## 难度与制作原则

- 以整数加减、乘除、倍与一半、余数、时间格为知识边界，不要求方程、同余、最小公倍数、排列组合公式或调度术语。作者可用程序验证，玩家应能用画图、列表、替换、倒推、分类与排除解答。
- 每关必须说明需要发现什么关系；增加数量、候选按钮或操作次数本身不算提高难度。保留少量较短的关卡调节节奏，但不能把原基础题换大数字后交付。
- 正常界面只给规则和玩家自己的试验记录；不自动填关键中间量。所有约束开局可查，失败显示真实违反的条件，不能偷偷添加限制。
- 数量、时间、标签由引擎绘制；现场试验改变真实托盘、机关、灯和车。批量操作、撤销、逐步运行、重排、回看都可用，不增加限时点击。
- 四档主动提示统一为观察方向、关键关系、局部示范、完整示范。提示不影响通关资格；仅最后一档允许完整答案。正文解答是作者资料，不能放进玩家默认货单。
- 接受全部合法解，不能硬编码示例顺序。有限候选题要允许实际验证，但不把所有候选结果一次自动列出。
- 最终确认仍由玩家主动操作。设计模型验证只证明题目可解、判定明确，不证明儿童体验或学习效果。

## 统一时间与库存约定

以下所有时间都是从第0拍开始的整数时刻。持续 d 拍、从 s 开始的工序占据 `[s,s+d)`，完成时刻为 `s+d`；同一时刻先处理完工、取走和腾位，再接入与开工。没有等候空间的规则会单关明确；未禁止等待的地方可以等待。已经完成的货不能留在压机上充当额外仓位。

暂存位按货物完成前工序到开始后工序之间占用，直接交接不占用额外时间。双机同刻分别加工不同物件合法。所有“最晚”包含该时刻；所有“第一次/最早”必须排除更早合法方案。

## GW02 · 留样之后，还缺多少

**场景与规则。** 护栏需要27枚可安装卡销。共有8片铜料，全部使用；每片选四孔模或七孔模，一次产出4或7枚。两种模都要使用，且每种模第一次加工的一整批必须封存检测，不能用于护栏。之后的整批都安装，不另留余料。

**玩家操作与验收。** 给8片铜料选择模具，可批量指定相同模具；试压时按所排顺序演出，首次遇到各模的批次进入两个透明留样盒。8片用完、两盒各有对应一整批、安装数恰好27才通过。封存批次不是额外铜料，不能把留样同时算作安装。

**思考与作者解。** 先把4+7枚样品补回，总产量应为38。假设8片全用四孔，得到32；换一次七孔多3，差6，所以七孔2片、四孔6片。28种位置排列全部合法，没有换模成本。只凑27而忘记留样不合法。

**提示阶梯。** 样品也是产量 → 补回两盒共多少 → 全用小模与目标差多少 → 38−32=6，每换一次增加3，共换两片。

**剧情结果。** 护栏修好，玩家可登观察台。嗒嗒发现“做出的数量”和“能拿去安装的数量”需要分别记。发现卡：先把拿走的补回来。

## GW03 · 相遇了，还不能交接

**规则。** 吊台第2拍首次到达，以后每3拍一次；小车第3拍首次到达，以后每4拍一次；放行灯第3拍首次亮，以后每5拍亮一次。每次到达或亮灯只持续该时刻，不能停留等候。只有两机同时到达且灯同时亮，才可交接。求1～40拍中第一次合法交接。

**操作。** 可在三条节拍带标记自己的预测，指定试验时刻；运行只展示选定时刻附近的实际事件，也可逐拍回看。通过须选最早合法时刻，不要求手工点满40格。

**作者解。** 两机相遇在11、23、35拍；灯亮在3、8、13、18、23……，所以首次是23。11拍只满足两条规则；不能把周期相乘直接当答案。

**提示。** 先找两机共同的时刻 → 再查这些时刻的灯 → 11拍灯亮吗 → 首次23拍。发现卡：条件要一起成立。第一托货已完成交接；余下两托转入下一班船，新班次从第0拍重新计时，期限更紧，引出调起点。

## GW04 · 两班船，都要赶上

**规则。** 小车在4、8、12、16拍到达，每次接走一托。吊台原在2、8、14拍到达，周期6拍；开工前可整体延后0、1或2拍，此后不能再调。GW03之后余下的两托货在新班次第0拍已备好，必须在第16拍结束前通过两次真实相遇送完；本关没有GW03的放行灯限制，换了独立直通轨，开局说明。

**操作。** 设延后量，并选两次交接时刻。每次交接只能消耗一托，重复选择同一时刻不算第二次。

**作者解。** 不延后只在8拍相遇；延后1拍无相遇；延后2拍在4、16拍相遇。因此延后2拍，两次分别4、16。只找到第一次4拍还没有完成整单。

**提示。** 看完整两班 → 比较三种起点的相遇记录 → 原起点只有一次 → 延后2，4和16交接。嗒嗒亲自按住启动杆，旧灯轴真正出海，随后通过玩家对话加入。发现卡：一张计划管到最后。

## GW05 · 七拍能做完吗

**规则。** 三件工具都在0拍就绪，都须先钻孔再抛光。一台钻机、一台抛光机，每台一次一件，不能中断；机间暂存不限制。

| 工具 | 钻孔 | 抛光 |
| --- | ---: | ---: |
| A | 3拍 | 1拍 |
| B | 2拍 | 3拍 |
| C | 1拍 | 2拍 |

**操作与目标。** 排两条工序带，在第7拍结束前完成全部。允许不同机的工序重叠，禁止同机重叠或抛光先于钻完。

**作者解。** 抛光共6拍，最早第1拍开始，因此7拍已经是下限。让抛光一直有活：钻C0–1、B1–3、A3–6；抛C1–3、B3–6、A6–7。整数时刻下只有这一套7拍计划。单纯先做钻得最久的A不能达到下限。

**提示。** 哪台至少要忙多久 → 抛光最早何时开始 → C先做好能接上谁 → 给出完整两轨示范。修理街的折窗依次打开。发现卡：先找做完的下限。

## GW06 · 产量一样，工时不同

**规则。** 需恰好31枚扣环；小模每炉3枚，大模每炉5枚。每炉1拍，换模另用1拍，首次装模免费。原料充足，整炉加工，不丢弃；第8拍前全部完成。

**操作。** 编排最多10炉的工单并试运行，画面分别记录产量、加工拍和换模拍；不能把同一拍既算换模又算生产。

**作者解。** 数量组合只有小2大5，或小7大2。后者光加工就9拍；前者7炉，还剩1拍只能换一次模。两种合法顺序为小小大大大大大，或大大大大大小小。大小交错虽然产量对，时间不够。

**提示。** 先列产量组合 → 哪种光加工就超时 → 剩下一拍能换几次 → 同类集中，两种顺序。发现卡：把额外花费算进去。减少开炉次数，灯架合拢。

## GW07 · 检修前，先留好位置

**规则。** A/B/C/D按顺序经过压机和冷却机，压制各1拍、冷却各2拍。两机一次各一件；中间仅一个暂存位，先来先冷却。冷却机检修占用 [4,5) 一拍，工序不能与检修区间重叠，也不能暂停后接着冷却。压机不能当仓库。要求最迟第11拍完成全部。

**操作。** 同时安排压制和冷却开始时间，检修格从开局固定显示。试运行因占位超限或撞检修而停时，显示具体物件及那一拍。

**作者解。** 第一件最早1–3冷却；检修前放不下第二个完整2拍冷却，后三件最早5–7、7–9、9–11，所以11是下限。一套压制计划为0–1、1–2、4–5、6–7；冷却为1–3、5–7、7–9、9–11。接受所有达到11拍且不溢位的方案，不锁示例压制时刻。

**提示。** 冷却机哪段不能用 → 检修前能做几件 → 倒看第二件何时取走，第三件何时能入位 → 示例双轨。嗒嗒松开加速杆，屋顶晾晒线展开。发现卡：停机前就要安排等待。

## GW08 · 两张旧单，锁定一块槽板

**规则。** 同型旧托盘每托装5～16根整数灯轴。第一张记录：35根装完满托后剩3根；第二张：47根装完满托后剩7根。没有损耗，余下数量必须小于每托容量。

**操作。** 提出槽数，分别重演两张记录；可以保留候选与排除记录。两张都吻合才通过。

**作者解。** 补掉余数，32与40必须都能整分。第一张允许8、16，第二张允许8、10，交集只有8。只看任一记录都不能确定。不能把“可被整除”与“合法余数”分开忽略。

**提示。** 先去掉零散数 → 两张满托总数分别多少 → 比较两份候选 → 8槽。旧槽板与维修日期一起支持“设备换过，表没同步”的剧情，数学本身不证明谁犯错。发现卡：一条线索不够就合起来看。

## GW09 · 既不漏灯，也不错站

**规则。** 环上12盏灯编号0～11，从0出发，每次固定走2～8格之一，顺时针且途中不改步长。希望首次回0前经过所有灯各一次；旧报时记录还写着“第3次跳动后停在9号灯”。起点不算第1次跳动。

**操作。** 设步长和预测第3站，逐跳运行，记录经过的灯。通过须全覆盖且第3站为9，两条同时成立。只跨过而未停下的灯不算访问。

**作者解。** 全覆盖的候选只有5、7；步长5第3站为3，不符合旧单；步长7第3站为9，轨迹0、7、2、9、4、11、6、1、8、3、10、5、0。步长3虽然第3站9，却会漏灯。

**提示。** 先检查看似对的3格会不会回早了 → 找不漏灯的候选 → 再核对第3站 → 7格完整示范。发现卡：局部对，还要检查整圈。报时信号终于覆盖所有工段。

## GW10 · 最急的那单，为什么不能先开

**规则。** 一张维修台一次一单，不能中断。A/B/D第0拍就绪，C第1拍送来；所有订单最晚8拍完成，且各有自己的期限。

| 单 | 用时 | 最晚完成 |
| --- | ---: | ---: |
| A | 2 | 5 |
| B | 3 | 8 |
| C | 1 | 3 |
| D | 2 | 6 |

**操作。** 排顺序及开工时间，逐单验收。不能只看最终8拍，也不能在C尚未到时开工。

**作者解。** 总工作量正好8拍，没有空等余地，所以不能等到1拍先做C。可行顺序只有A→C→D→B，或D→C→A→B，均连续从0开始。最早截止是提醒，不是不用考虑到料时间的口诀。

**提示。** 总共要忙几拍 → 等C会损失什么 → 先塞一件2拍订单，再做C → 两种完整计划。发现卡：紧急程度和到达时间一起看。居民取回工具并摆好午饭。

## GW11 · 两张船票，倒排到同一张台

**规则。** 两批材料均第6拍到。A须装配2拍、冷却3拍、装船1拍；B须装配3拍、冷却2拍、装船1拍。A只能第12拍开始装船，B的船票可选第13拍或第14拍开始装船，必须预先确定其中一班。各批三个工序必须首尾相接，无中间等待。共用一张装配台，一次一批；冷却架可容两批，吊机一次一批。

**操作。** 排两批三段流程，检查各自船票、无缝衔接以及共享装配台。材料到达不自动开工。

**作者解。** A装船12–13、冷却9–12、装配7–9；B装船14–15、冷却12–14、装配9–12。B若选13拍船票，则装配8–11、冷却11–13、装船13–14；单批无缝、吊机也无冲突，却与A装配7–9重叠。必须选14拍，两批才刚好在9拍交接装配台。材料第6拍到后先等1拍。

**提示。** 从各自船票往回排 → 先还原两种船票的冷却 → 比较两个候选装配区间与A是否冲突 → 选14拍的完整计划。发现卡：倒排之后，还要合并检查。弥师傅认可这次有依据的等待。

## GW12 · 两班合起来，槽数才找得到

**规则。** 第一班23枚、第二班24枚同型标准件。托盘容量牌丢失，已知每托3～12枚整数；两班用同一种托。每班结束只交走所有满托，余料完整留到下一班。交接册确定：两班一共交9个满托，最后还剩2枚。余料盒容量11，足以容纳所有允许槽数的合法余数，不能把隐藏盒容量当提示。

**操作。** 先提出槽数，再实际执行两班：第一班留多少、第二班接入后送多少。切班由玩家确认，不能复制、丢弃余料。

**作者解。** 两班共47，扣最终2，9托装45，所以每托5。第一班交4托留3，第二班合成27交5托留2。把最终2误当第一班剩余是典型反例。

**提示。** 先把两班合并看 → 最后余下的不在9托里 → 容量确定后分别恢复两班 → 5槽、先留3、最后留2。发现卡：先看总账，再还原每一班。嗒嗒把余料写进交接册，安心坐下吃饭。

## GW13 · 两只鸟，到底叫了几次（GW04后可选）

**规则。** 两只玩具鸟第0拍一起叫，此后分别每4、6拍叫一次。观察从0到24拍，包含两端；同时叫只算一个“听到叫声的时刻”。问总共几个有叫声的时刻，以及其中几个只有一只鸟叫。

**操作与解。** 在时间尺上圈出认为重合的时刻，提交两个数量，按本人标记与实际声音逐拍对照。甲叫7次、乙5次，共同在0、12、24三次：不同鸣叫时刻9，独鸣时刻6。只求7+5会重复，共同时刻对独鸣要从两只的次数中都扣去。0拍漏算也会错。

**提示。** 同拍只算一次 → 先圈重合 → 区分总时刻和独鸣 → 9与6及完整列表。发现卡：重复的部分要分清。小鸟留在休息桌，保留人物支线气氛。

## GW14 · 第三张记录才有用（GW08后可选）

**规则。** 维修盒中有20～80枚。按4一托剩3，按6一托剩5，按5一托剩2；三张都是同一盒、不取走物件的复测记录。

**操作与解。** 可列候选，再用三种托复演。前两条允许23、35、47、59、71；第三条留下47。可想“再补1枚，便能按4或6整托”，再核对第三种。只满足两条不能验收。

**提示。** 前两条都差一枚成整托 → 找共同候选 → 第三张排除哪些 → 47。发现卡：保留所有尚未排除的可能。维修盒得到正确数量牌。

## GW15 · 最早的一次观察（GW09后可选）

**规则。** 机器周期可能为3、4、5拍之一，开局0件，第一件在第一个周期结束时出现。机器身份开局固定。你只能打开窗口观察一次累计出料数，允许在第1～12拍选时刻。要求选择最早的一个时刻，使无论是哪种机器，都能仅凭那次数量确定周期。

**操作与验收。** 先锁观察时刻，再开窗，最后挂周期牌。系统既检查策略能否区分全部三种机器，又检查实际周期牌；碰巧猜中隐藏机器但观察不能区分其他情况，不算成功。失误后可重试，身份不重抽。

**作者解。** 第9拍的三种数量为3、2、1，全部不同；1～8拍每次至少两种相同。第12拍也能分，但不是最早。第10拍为3、2、2，晚一点不一定更有用。

**提示。** 观察前就要考虑三种可能 → 比较同一时刻的三份累计数 → 8拍还混淆谁 → 9拍。发现卡：先选能分清的观察。折羽留下出料窗素描。

## GW16 · 找全四种午休曲（GW12后可选）

**规则。** 每首曲子恰好4段，每段可长2、3或4拍，总共12拍，恰好两段是3拍。曲子循环播放，相邻段长度不得相同，末段与首段也相邻。固定起拍点；旋转后的段序只要不同，算另一首。

**操作与验收。** 排铃句并试听，保存互不相同的合法段序，收齐所有4首。不能靠重存同一首充数；界面不预填4种排列，允许按“第一段是什么”分类记录。收集完后任选一首留作章末午休曲。

**作者解。** 两个3占6拍，另两段只能2与4；两个3必须隔开。首段2时1首，首段4时1首，首段3时2首，共4：2/3/4/3、4/3/2/3、3/2/3/4、3/4/3/2。把首尾当不相邻会多算。

**提示。** 另两段合计几拍 → 两个3怎样隔开 → 按首段分类 → 四种完整段序。发现卡：分类才能不重不漏。

## GW17 · 巡轨兽：空出第一拍

**规则。** 四辆工具车共用一段承重轨道，一次一辆，不可中断。第0拍开始规划，全部最晚第9拍驶离，且各有独立期限。

| 车 | 最早可发 | 占轨 | 最晚驶离 |
| --- | ---: | ---: | ---: |
| A | 0 | 3 | 7 |
| B | 1 | 2 | 4 |
| C | 3 | 1 | 5 |
| D | 6 | 2 | 9 |

**操作与解。** 规划后由巡轨兽逐段放行，不能只验最后一车。唯一整拍计划：等0–1，B1–3，C3–4，A4–7，D7–9。A先走会卡住B；B后先A会让C迟到；为等D而把A挪后也不行。空一拍来自期限约束，不是额外口令。

**提示。** 哪辆车的窗口最窄 → 第0拍发A会怎样 → B后谁不能再等 → 完整时刻表。发现卡：有依据地留空。巡轨兽折下路障，工具进入总机船坞。

## GW18 · 百臂总机：两种船期，一套准备

保留原稿的三机、两级单格暂存和真实出海演出，将“收到通知后再改”升级为“先做一套兼顾两种通知的计划”。所有可能从开局公开，不靠猜分支。

**公开规则。** 库存7件，森林F一批2件、山谷V一批3件、集市M一批2件，不拆批、不超量。

- 压机加工2件批次用1拍、3件批次用2拍，一次一批，不中断；本台无换模成本。
- 冷却每批2拍，一次一批，依出压机的顺序处理。
- 压机到冷却间仅1批暂存位，冷却到吊机间也仅1批；两台机器都不能充当额外仓库。
- 吊机每批1拍；F必须第3拍开始吊，M必须第9拍开始吊。V的实际吊运点只可能是第6或第8拍，身份开局固定，第3拍收到确认，重试不重抽。
- 第10拍开船。玩家要提交同一份压制、冷却计划，在V早班和晚班下都可交货。吊运点按实际班次取对应值，其他已承诺工序不能随着通知改变。

**操作与验收。** 工作台有“早班推演”“晚班推演”两页，同步引用同一份工序草稿。可分别逐段试验，看哪一个暂存架发生冲突；两页都合法才锁定正式计划。正式运行到第3拍停下读通知，玩家确认后继续该计划。已兼顾两种情况的方案无需改动。失败回规划，不消耗/复制库存，不改变通知身份。

**作者示范。** 压制F0–1、V1–3、M3–4；冷却F1–3、V3–5、M6–8；F3–4吊运、M9–10吊运，V按6–7或8–9。晚班在8拍取走V，同时M冷却完成入位，合法。

若M在5–7冷却，早班可行，晚班第7拍V未走而M也到位，暂存超限；总产量和最终10拍都对，仍不合格。M改为6–8或7–9均可。示例不是唯一解，任何同一压制/冷却计划同时满足两分支都应接受，不能强制指定压制顺序或强制玩家留某一特定空拍。

**提示。** 一张方案要经历两种情况 → 早班通过不代表晚班通过 → 检查7拍冷却后暂存架 → 给出兼顾两班示范。发现卡：把不同情况都想一遍。

最后由玩家拉动确认交接杆，三处实际接收记录齐全才开船。收尾镜头跟随真实执行轨迹，嗒嗒挂上休息牌；不是答完算式后播放无关胜利动画。

## 验证与后续制作

模型脚本：[workshop_olympiad.py](../../tests/design/workshop_olympiad.py)。回执：[verification.json](../playtest/workshop-olympiad/verification.json)。规则数字、解集合、关键反例以脚本枚举核对；脚本绑定本文和自身的SHA-256。GW05/07的最早时刻另有正文下限论证，不能把“在窗口内搜到答案”直接当最优性证明。
