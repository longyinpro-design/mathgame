# GW10 · 最急的那单，为什么不能先开

2026-09-25。按 [GW01契约](workshop_gw01_sample.md) 同一套三年级奥数难度与制作原则实现。核心思考是「分类排除、逐单期限」：最早截止的 C 第 1 拍才到料，不能机械地先做它。不是原章节里的基础排序题，也不声称已通过儿童难度实测。

## 可玩契约

一张维修台一次一单，开工后不能中断。A、B、D 第 0 拍就绪，C 第 1 拍才送到；四单最晚第 8 拍完成，另各有自己的期限：

| 单 | 用时 | 最晚完成 |
| --- | ---: | ---: |
| A | 2 | 5 |
| B | 3 | 8 |
| C | 1 | 3 |
| D | 2 | 6 |

总工作量正好 8 拍，没有空等的余地，也不能在 C 到料前开工。补上到料时间后，可行计划只有两套：A 0–2、C 2–3、D 3–5、B 5–8，或 D 0–2、C 2–3、A 3–5、B 5–8。

- 玩家排的是每单的开工拍；验收顺序按开工拍从早到晚自然定出（同拍按 A、B、C、D），画面与判定只看这一份顺序。
- 开工拍、四单的占台区间、到料闸与各自的最晚完成线全部由规则模块现算，画面不另存一份会走样的表。
- 提交时逐单验收：到料、撞台、逾期，按顺序念出第一处真实违反的条件，例如「C 第 1 拍才送来，第 0 拍还开不了工。」「第 3 拍还占着台：A 的 3–5 还没走完，D 就要开工。」「A 到第 6 拍才完，超过最晚 5 拍。」。不偷偷添加限制，也不把总工作量这类中间量自动填进界面。
- 四档主动提示依次为：四单用时加起来要忙几拍 → 等 C 会损失哪一拍 → 第一件从 A、D 里挑一件 2 拍的接上 C → 两种完整计划。默认不显示解。
- 开局草稿故意把最急的 C 排在第 0 拍：第一次提交就能听见「还没到料」的真实原因；草稿不是解，重摆可以随时退回它。

## 操作与存档

- 启动 `启动齿轮工坊GW10样板.command` 或 `game/workshop_gw10.tscn`。
- 鼠标完整可玩；点左边任意一张单选中它，「提前 1 拍 / 推后 1 拍」调整它的开工拍，←/→ 换单，Q 提前 1 拍、W 推后 1 拍，Z 撤销，X 确认重摆，H 主动提示，Space 逐单验收。保留 Tab/Enter 焦点操作。
- 新独立存档 `user://profiles/workshop-gw10-1/save-v1.json`，不读写、不删改其它关卡档案。持久化四单的开工拍表、由它定出的验收顺序、阶段、对白停点与提示级别；越界开工拍、重复或与开工拍对不上的验收顺序、旧版本一律判为损坏档。
- 沿用 SaveRepository 事务、失败重试和损坏档保护。单独临时测试档不接触玩家进度。

## 场景与后续

沿用第二批母版的屋顶修理街背景（`rooftop-repair-street-stage-v1.png`）与压机、启动杆、嗒嗒母版；小岚由宿主常驻现场。四张维修单并排挂在时间尺上，每单画出到料闸（C 第 1 拍到料）、最晚完成线与占台区间；撞台、未到料与逾期只标出玩家自己排出来的样子。交付演出扫过一条验收线，四单按做完的先后依次盖上「已验收」。失焦和模态暂停表现。

标题栏用缩短的「最急的那单，不能先开」：目录里的全名「最急的那单，为什么不能先开」在 410 宽的标题牌上会折行；全名保留在目录卡片与「回看与发现」里。

修理街的午饭摆好之后，下一关 GW11 要把两批货倒排到同一张装配台。只完成 GW10，不扩展跨岛解锁或伙伴加入。
