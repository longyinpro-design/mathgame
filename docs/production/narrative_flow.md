# 森林岛叙事流程重规划 · 剧情触发关卡

日期：2026-09-16。状态：**已进入实施；第一幕样板与全章节点已接入，验证范围见执行计划和运行时说明**。用户明确希望关键剧情触发关卡，过关后继续剧情，以动画连接场景，主流程不需要自行走路。用户已追加授权：先实现第一幕完整样板，再扩展整章。本文保留叙事与验收契约，实际实现进度只记执行计划。

本提案接替旧方案中以自由行走、靠近物件和地区选择推进主线的设计方向。下文的六幕、对白和镜头是制作契约；当前可玩行为仍见 [运行时说明](runtime.md)。开发状态只记录在 [执行计划](../试玩实现计划.md)，本文不另建完成队列。

## 1. 重规划的核心

定位调整为：**有伙伴成长的剧情解谜冒险**。玩家的主要参与是观察、选择、解谜与关心角色，旅行由镜头和角色演出完成。

主循环：**发生事件 → 明确眼前困难 → 在现场解谜 → 结果改变现场 → 角色作出下一步行动 → 新事件**。

当前代码里的三个割裂来源：

- `scripts/ui/forest_release.gd` 的 `request_level()` 先进入地区再调用 `walk_to()`；关键行动被找入口和走到物件的流程隔开。
- `draw_completion()` 主要用奖励横幅和一句反应收尾，下一处从同地区可用关卡里选择，无法表达跨地区的剧情因果，也可能把支线放到主线推荐位置。
- `scripts/content/story_catalog.gd` 保存地区状态和短对白，但还没有负责“这段剧情结束后进入哪一关、完成后接哪一场戏”的流程。

改后的入口是“继续故事”。新旅程直接从树梢站开场；继续存档回到当前剧情停点或未完成机关。地区地图保留为已到地点与回忆展示，营地在幕间自然出现，主线不通过地图选关、地面点击、靠近距离或 E 键推进。

过关后由当前故事节点接续后果演出，抵达下一句对白或剧情选择时停下。玩家可以读完再继续、随时暂停；“自动衔接”不等于自动翻过台词或替玩家开始操作。按钮使用现场行动，如“帮站长装好吊篮”“看看灯架”，而不是“进入 FL04”。

## 2. 一条贯穿全章的故事

主线建议：**把一袋种子送进沉睡的森林，并让森林里的生活重新连接起来。**

开场，小岚和阿橙只知道要送种子。送达后，站长递来夹在包裹中的来信：村里等着播种，古林却迟迟没有传回春天的回声。两人循着线索帮助苔团、村民、磨坊师傅和折羽，逐步得知唤醒树心需要大家恢复运作、一起把种子送到内庭。终章让前面帮助过的人以灯光、机器、邮路与送来的种子共同回应。

这封信是新的叙事编排，复用现有 `seed_letter` 收藏；收到收藏仍发生在 FL01 首通。开场不提前发放信物或未来伙伴。已有三位伙伴、五处环境、数学规则和首通奖励作为制作资源复用。

六幕不是六张选关列表。每幕包含起因、推进和一个结果；一幕中的多个机关可以构成同一件事的不同阶段，解完后直接在现场接戏。

| 幕 | 核心事件与角色变化 | 嵌入关卡 | 幕尾演出与下一步 |
| --- | --- | --- | --- |
| 一 · 种子与来信 | 帮站长送达包裹，听到失去回声的消息；循光遇见守着三门的苔团 | FL01 → FL02 | 三门同时亮起，苔团主动同行；镜头沿光穿过树林，落到晨种村 |
| 二 · 村里的灯 | 村民准备恢复播种，但借粮记录混乱，夜路的三架灯也无法校准 | FL03 → FL04 | 分粮重新有序、三灯依次亮起；林婆婆托大家去旧磨坊恢复育苗，幕间回营歇脚 |
| 三 · 磨坊重新转动 | 师傅依次核对装法、辨认机器、组合24点能量；阿橙从急着试变为先观察 | FL05 → FL06 → FL07 | 育苗机带动整座磨坊，待寄的信和物资装好；折羽匆匆赶来，带出邮路问题 |
| 四 · 把消息送出去 | 帮折羽整理遗漏路线，再处理落石路口与两封信的共同路径；折羽加入 | FL08 → FL09、FL10（两者均完成） | 两封信沿玩家给出的合法路线飞出，远处居民回信；大家约好向古林送种 |
| 五 · 给下一步留余地 | 新吊篮需要保留后续可用配重；守门人邀请对局，阿橙开始懂得替伙伴留后手 | FL11 → FL12 | 吊篮送达，对局结束；自动转入营地休息与阿橙成长邀请，再赴内庭 |
| 六 · 让春天回应 | 石灵先试炼团队应变，再让路；树心幻影要求辨明真身并留下合击资源 | FL17 → FL18 | 树根成桥、种子抵达树心；森林各处逐一恢复，营地庆祝并收到航图 |

FL09/FL10 保留原有并行关系：折羽在剧情中询问先处理哪一处；默认可以按 FL09 → FL10 演出，另一顺序同样接得上。完成一处只报告这一处的结果，两处齐备才进入送种约定。支线不参与这个汇合条件。

## 3. 每关怎样从剧情中发生

原则：入关前能看见问题，出关后能看见自己解决了什么。目标与硬约束在操作时始终可查；长对白不承担全部规则说明。普通关沿用当前“解开机关即通关”的完成条件，不恢复旧设计里的额外证明板。

| 关卡 | 触发事件与镜头落点 | 解开后必须发生的事 |
| --- | --- | --- |
| FL01 第一袋种子 | 站长发现种子还在下站，小岚与阿橙需要随种子上去；镜头从上站滑向联动吊篮 | 依实际装载与到站结果表现卸货；站长接过种子，交出种子来信，再引出三门线索 |
| FL02 三门借光 | 苔团守着光量不齐的三门，石灵说明三次借光约定；镜头贴近同一座光台 | 三门按玩家的正确轨迹达到等亮，苔团走出光台边，与小岚结伴去村里 |
| FL03 三座粮仓 | 林婆婆与村民记得两次借粮后的相等，却把两个时刻混在一起；翻开现场粮账 | 按玩家恢复的记录回放两次借粮，村民确认账目；对话自然转到将亮未亮的灯架 |
| FL04 三架灯 | 回家的村民等着灯亮；灯架保留两两合称记录，需要找回各架读数 | 三架灯点亮，居民沿灯回家；照出通往磨坊的路牌，而后进入本幕休息 |
| FL05 磨坊账簿 | 师傅打开两页旧记录，装配台缺少正确模块顺序 | 玩家装好的机器第一次运转；师傅转向另一台铭牌遗失的育苗机，带出 FL06 |
| FL06 育苗机 | 三种候选机有相似表现，现场只允许一次辨识试验 | 使用本次固定机器的真实输出表现结果；阿橙记下观察，师傅指出最后一台还缺原装顺序记录 |
| FL07 磨坊的24点 | 最后一架育苗机需要24点能量，四枚数字为1、4、5、9 | 玩家用完四枚数字，按实际四则运算和括号算式得到24，机器转动，磨坊全面开工 |
| FL08 分邮袋 | 磨坊的消息等着寄出，折羽发现自己总在重复旧路、遗漏其他走法 | 邮袋整理齐全，折羽提出同行；下一句带出两个具体路口的问题 |
| FL09 落石路口 | 居民准备把落石安置在路口的一个位置，希望尽量保留送信方式 | 落石移到玩家选中的最优位置，保留下来的路线可见；两个并列最优解均使用实际选择演出 |
| FL10 两封信 | 两位信使需要同时出发，路线各自能走还不够，中途不能相遇 | 播放玩家已找到的一组合法配对，信分别送达；六组收集仍由原机制完成，不改成只找一组 |
| FL11 轻装订单 | 古林外的新吊篮有明确容量、载重和到站退出规定，大家需要把旅客和种子分趟送上去 | 每次到站与退出按真实局面演出，最后接“大家都到了”的现场对白；固定六物件及身份不换皮增减 |
| FL12 守门对局 | 守门人在出发前邀阿橙一行下一盘，约定赢下对局便为大家引路 | 守门人履约，阿橙回想此前的送种和育苗经历；通过短转场接到营地的同心叶结邀请 |
| FL17 石灵试炼 | 石灵提出最后的接招约定，三枚符石、封盘和变招直接在现场展开 | 胜利后石灵抬起树根搭桥，队伍在镜头中走过，直接抵达树心；无需玩家点地面过桥 |
| FL18 雾冠树心 | 幻影围住芽眼，种子库存可见；伙伴提出先辨别再合力唤醒 | 按有效观察与真正成功的合击触发复苏，回望此前帮助过的地方，归营获得航图 |

现有关卡是可复用的谜题库，玩家看到的是事件。磨坊三题按“修好磨坊”的连续三段呈现，邮路两题按“让信送达”的两个分支呈现，避免每次都出现标题页、结算页、选关页。若样板证明同一幕重复，应先改事件与操作节奏；删关、合并数学任务或改变奖励依赖另行修订数据契约。

## 4. 第一幕的具体样板

| 送达 | 站长接住种子；阿橙跳下篮子。包裹边露出折好的信，站长把信递给小岚 | 奖励轻提示归档；玩家按自己的速度读信 |
| 线索 | 来信：“种子已经备好，可古林还没有传来春天的回声。”阿橙看向远处忽明忽暗的三道光 | 点“去看看那三道光”；镜头掠过枝叶，角色短暂穿行 |
| 初遇 | 苔团抱着光晶抬头，石灵介绍三次借光。镜头由角色切近三门，场景位置连续 | 点“帮苔团点亮三门”进入 FL02；入关对白不透露 11/7/6 |
| FL02 | 光晶数量、借光次序和目标留在现场，每次回响表现真实数量变化 | 玩家解谜；失败留在光台，不重播初遇 |
| 结伴 | 三门均亮，苔团松开一直护着的光晶：“我也想看看，这些光会照到哪里。”三人面向远处村庄 | 入队结果来自首通结算；对白后继续进入第二幕，也可在此暂停 |

样板完整覆盖“两段剧情、两个关卡、一次跨景、一次伙伴加入”。先用现有场景与角色动作检查连续体验，再补特写和逐帧动作；仅平移静态立绘不能算作正式演出品质验收。

## 5. 动画与节奏

动画承担三种明确工作：解释发生了什么、呈现解谜结果、连接地点。角色可以在镜头中行走，玩家不负责赶路。

| 演出类型 | 建议长度（制作目标，未试玩验证） | 表现要求 |
| --- | --- | --- |
| 对白中的动作 | 1–3 秒 | 抬头、递信、看向目标、犹豫等，与一句话同一信息点；台词由玩家推进 |
| 场景转移 | 2–5 秒 | 镜头跟随信、光或角色，使用前后景遮挡/淡转；只表达必要的空间变化 |
| 普通过关后果 | 3–6 秒 | 种子落地、灯亮、机器转动、信送出；以真实解答和世界状态驱动 |
| 加入、成长、首领收尾 | 8–15 秒 | 留出准备、行动和角色回应；长段拆成可停的镜头，不一次锁住整个段落 |

- 每幕可以有纯剧情与安静休息，不要求每段对白后都马上接题；过关后先让结果被看见，再给下一件事。
- 机关操作动画继续服务推理，不用蒙太奇隐藏借出多少、路线经过哪里或资源花了多少。
- 演出均提供“跳过本段”；跳过落在正确的最终画面，保留关键目标与对白回看，不会多发奖励或跳过谜题。重复关前戏默认缩短。
- 台词可点击推进，必要目标不因气泡消失而丢失；静音仍能理解，颜色之外保留位置、形状和文字信息。
- 暂停与失焦冻结表现。返回故事时续接最近稳定镜头，不重置谜题；具体回放规则见下节。

## 6. 支线、营地和回访怎样留下来

四条支线改成角色在合适停点的邀请，选项为“现在帮忙 / 稍后再来”。不强制弹出整页支线清单，错过当场邀请也不会永久失去内容；已开放邀请收进手记，可以直接进入短前情与机关，无需走路找 NPC。

| 支线 | 保留的开放前置 | 推荐邀请时机与故事回报 |
| --- | --- | --- |
| FL13 两趟足够吗 | FL01 | 站长在第一幕结伴后请托额外运输，手记也可从 FL01 后保留邀请；完成获木章，回到原主线停点 |
| FL14 五步石径 | FL08 | 整理邮袋后，阿橙注意到信使的小石径；修路后留下路带，返回邮路分支选择 |
| FL15 异晶天平 | FL06 | 育苗机辨清后，师傅收起一盒重量异常的晶体；默认在磨坊幕尾再提醒，避免打断 FL06 → FL07 |
| FL16 借墙花圃 | FL10 | 信送达后的居民回信邀请设计花圃；完成给出设计图，回到当前主线停点 |

营地成为幕间场景，优先安排在 FL04 后、邮路幕尾、FL12 后与结局。这里可聊天、换队、看收藏和自愿建设；点击“继续故事”直接接回停点。也允许菜单主动休息，未完成机关按现有语义暂存，不用先过关才能退出。

FL12 后自动安排阿橙成长邀请；玩家可当场系叶结或稍后再来，成长仍须满足原经历条件，不能挡住 FL17。建设保留原开放条件和费用；能否当场购买按实际木片余额显示，不承诺每个幕间都足够。FL16 花圃设计图不等于付费营地花圃，未建设时演出不能画成已建成。

剧情演员与最多两位的机关技能队伍分别管理：必要角色在剧情中有到场交代；关卡工具仍按开始时冻结的队伍。不能为了连续演出擅自换队、变更货运对象，或让未加入的伙伴使用已解锁技能。

回访入口在手记与章节回忆里，直接显示已恢复现场、回放或“再玩一次”。重玩不能推进当前主线停点、重复入队或发首通奖励。

## 7. 实现需要的最小接缝

以下接缝已按独立叙事状态实施；精确字段见运行时说明。

| 位置 | 责任调整 |
| --- | --- |
| `scripts/content/story_catalog.gd` | 从散落短句扩充为显式故事节点：稳定节点 ID、角色、镜头/对白、关联关卡、前置、成功后的目标节点、支线返回点 |
| `scripts/progression/story_progress.gd` | 只计算当前节点、选择、关卡完成后的接续与分支汇合；使用实际完成事件，不按地区列表顺序猜下一关 |
| `scripts/core/game_session.gd` | 在现有提交边界保存故事停点；关卡结算仍由这里统一处理，剧情播放不直接写奖励或存档 |
| `scripts/ui/forest_release.gd` 与演出视图 | “继续故事”成为入口，镜头/对白交接到机关；替换主线走近交互与关后“下一处机关”导航，保留机关规则、提示、设置和队伍入口 |
| `scripts/persistence/save_repository.gd` 及相关校验 | 如需新增叙事字段，明确版本和旧档迁移；复用现有失败候选/重试机制，不在 UI 临时推断已播放状态 |

流程为 `剧情节点 → 挑战 → 已提交的完成结果及后果节点 → 演出 → 下一剧情节点`。同一事务记录首次奖励和待演出的后果节点；进入下一节点的确认另作一次稳定提交。保存失败时留在原已提交状态，不先把下一段剧情演成事实。

新增的是独立叙事状态，不能把剧情节点塞进当前要求与 `completed_levels` 一致的 `world.events`。至少需要当前节点/稳定镜头、已处理节点、分支选择、支线返回点与叙事版本；精确字段及升级格式在实施前冻结。

恢复与跳过必须满足：

1. **关卡未完**：恢复同一 `ChallengeRun`、隐藏局面、操作状态与队伍，不先重播整个前情；主动离开则保留主线停点与挑战。
2. **刚过关、尚未看完后果**：恢复到已提交的后果节点，从最近稳定镜头重放或跳过；不再次结算，也不直接漏掉入队情节。
3. **演出看完**：确认下一节点保存成功才推进。连点、跳过和重开不能重复推进；镜头中途退出允许重放一小段纯表现。
4. **支线或回访**：保存主线返回点。支线暂存、完成或退出后都能回到原故事；重玩不改变主线位置。
5. **旧档没有叙事字段**：先保护原字节，再依据已完成关卡、有效的活动/暂存挑战、入队与成长事实计算迁移候选。未完活动关优先续玩；分支已完成一处就接另一处；已全部过主线就到结局后的营地。旧档已结算但没有观演记录时给可跳过的短回顾，不假称此前看过新演出。未知或矛盾状态明确失败，不重置玩家进度。

## 8. 制作顺序与验收

后续建议按完整片段推进，详细状态继续写入唯一执行计划：

1. **第一幕样板**：定稿分镜与节点，完成 FL01 → FL02 → 苔团加入 → 晨种村的连续体验，并打通保存、跳过、暂停与重开。
2. **全章接续**：按六幕接入现有谜题，完成 FL09/FL10 双顺序、幕间营地、成长与支线返回；统一主线入口和回访。
3. **演出与整章验证**：补齐角色关键动作、音画、结局回望，验证所有主线与四支线，完成独立评审和实际试玩。

验收重点：

- 新旅程可从开场到结局连续推进，全程不需要点击地面、靠近热点或选择地区找下一关。
- 每个挑战都有可见的触发事件、当前目标和完成后果；看完动画，玩家能说出“刚才帮助了谁，接下来为什么做这件事”。这一条需要真人试玩，自动化不能替代。
- FL09/FL10 两种先后顺序都成立，完成一处不提前说两处都通；跳过四支线仍能通关，邀请可以稍后接回。
- 过关、入队、成长和建设按真实状态演出；两种 FL09 最优位置、实际 FL10 路线和 FL18 合击结果都不会被固定分镜改写。
- 挑战中、刚结算、后果动画中、分支选择、支线中、旧档迁移与保存失败处重开可恢复；奖励不重复，未完成谜题不被跳过。
- 第一幕用实际窗口操作检查普通播放、全部跳过、逐句慢读、静音、暂停/失焦及 1280×720 / 960×540；全章再跑受影响的现有规则与持久化检查以及新的流程检查。

新故事流程使用独立的规则/恢复和窗口测试；历史自动化不充当新演出的证据。程序与窗口通过也不证明真人叙事节奏或儿童体验已验收。
