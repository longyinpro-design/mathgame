# MK04 不可能兑现的收据 — v1 样板契约

2026-09-20，第二岛「千灯集市」第四关。关卡规格来自 `docs/production/market_chapter.md` 第 123–129 行与本关之后的关键戏（第 254–262 行）。只新增 MK04 一套文件，不改 `kit_world.gd`、`level_host.gd`、`chapter_catalog.gd`、MK01/MK02/MK03 与共享测试脚本。

- 题目：柜面上钉着三张单。两张是双方各留原章的已核实原约 —— 1 卷布换 2 瓶油、3 瓶油换 1 只铜铃；第三张是扣扣的转抄件「3 卷布换 3 只铜铃」。玩家用真货物把 3 卷布沿前两条换到底，再和第三张对照，从候选 2／3／4 只里给它改签。
- 数学真值：3 卷布 → 6 瓶油 → 2 只铜铃，解唯一；要凑够单上写的 3 只铃需要 9 瓶油，也就是 4.5 卷布，柜面上换不出来。可执行约定只有两条（`RULE_COUNT = 2`），转抄件永远不进这个范围，所以任何路径都刷不出货，不会形成兑换循环。
- 证据分层写死在文案里：实换只证明**收据不一致**；「原单写 2、转抄写 3」才证明这次错在**转抄**。剧情台词与完成回执都不把数字不对说成偷货，衡伯撤回指责、扣扣承认抄错并主动加入。
- 每件货物只有一个归属：柜面布堆、台面油瓶、右柜铜铃。存量、可换组数、缺口全部由 `cloth_left()`／`oil_loose()`／`bells_loose()`／`affordable()` 从已生效的 `a`、`b` 算出，画面与按钮文案不另存计数，撤销与重置不会复制库存。
- 兑换先入账再演出：点「换 1 组／全换完」只写 `stage="exchanging"` 和待生效的 `[约定编号, 组数]`，动画结束才由 `advance()` 把组数记入 a/b；世界层 `shown_state()` 也在 `progress >= 0.5` 才翻图，画与账同一时刻一致。改签同理，走 `stage="correcting"` 与 `proposed`。保存失败或中途退出不会发布幻影兑换，重载从同一演出继续。撤销快照只存在内存，不写档。
- 整批搬运沿用 MK02 的做法：`carry_plan()` 一处算出被抬走的每一件货物的脚点，整批以同一相位离开原堆、飞向扣扣爪边、途中收紧到五分之四，`hide_while_moving()` 同时隐藏原位。第三张单的拒绝理由常显，不写「已禁用」。
- 提交只在主动「核对收据」后判定。缺口按承诺逐条说明，一次只报第一条：布没换完 → 台面剩油 → 铃数不对 → 还没改签 → 改签数与实换数不符。最后一条会把玩家刚做过的那一遍复述回去（`改签写的是 3 只，可你刚换出来的是 2 只：3 卷布 → 6 瓶油 → 2 只铃。`），3 只这个错答因此可达且必然在提交处失败，而不是被按钮挡死。
- 交互骨架：开场三句逐句推进 → `approach` 镜头把三张单并排拉近（两张原约各两枚红方章加金框、转抄件只有一枚蓝圆章并标「扣扣抄的」）→ 实际操作三种真货物 → 改签候选 → `delivery` 演出把两只铃送到衡伯那一侧、扣扣走上来、衡伯递出空白货签 → `clarify` 四句澄清 → `complete` 回执按实际组数复述两条原约与改签结果。
- 美术：底景、`cloth_bolt`、`oil_bottle`、`brass_bell`、`receipt_blank` 全部取 `art/market-kit-v1/manifest.json` 拆件，manifest 是唯一坐标来源。三处柜台 425/645/877（y 499）与扣扣站位 659,424 直接引用 `scenes[nursery].stations`；`anchor_px` 只在 `kit()` 里乘一次缩放。单张纸宽 120、纸顶 = 脚点 − 宽×308/237，柜面 y 抬到 396 以免托盘（顶约 402）盖住章印。章印与所有文字由引擎绘制，不使用烘焙文本。
- 存档字段 `user://profiles/market-mk04-1/save-v1.json`，schema 由 `mk04_rules.gd` 的 `validate()` 把关：`sample="market-mk04-1"`、`stage ∈ STAGES`、`beat` 只在 `arrival`(<3) 与 `clarify`(<4) 非零、`hint ∈ 0..3`、`a ∈ 0..3`、`b ∈ 0..2`、`correction/proposed ∈ {0}∪{2,3,4}`、`3b ≤ 2a`（换出去的铃不能比换进来的油多）、`exchange` 最多一对且必须合法、`arrival/approach/ready` 不得有货、`puzzle` 不得留待生效动作、`delivery/clarify/complete` 必须已经满足全部承诺。越界、一个货物两个归属、未完成却写成 `delivery/complete` 一律拒读并由 `save_repository._protect()` 保留原文件。
- 操作与键盘：Q 按原约一换 1 组、A 换满、W 按原约二换 1 组、S 换满、T 或点第三张单看拒绝理由、1／2／3 选改签候选（再点已选中的那个可撤回）、Space 核对收据、Z 撤销、H 提示（三档，无扣分）、Esc 暂停。改签候选与三张单的热点均为 ≥48×48 逻辑像素（`target()` 生成，随镜头一起缩放）；`puzzle/exchanging/correcting` 三阶段镜头缩放 1.10、偏移 −64/−43。
- 入口 `game/market_mk04.tscn`，或双击 `启动千灯集市MK04样板.command`。从航图进来用宿主的返回键，单独启动这一幕时完成后追加「看航图 · 点一盏灯」。
- 已知限制：manifest 没有章印拆件，两枚方章与一枚圆章是引擎 `draw_rect`／`draw_circle` 画的占位图形，风格待美术批次二统一；衡伯没有角色拆件，只以台词、递出的空白货签和飞走的铜铃出现，关键戏里他撤诉那一刻没有可辨认的脸。场景标题在标题板上用短名「对不上的收据」（目录里仍是全名「不可能兑现的收据」），因为全名与「千灯集市」并列会超出 394 宽标题板；中文标签一律用显式换行、不依赖自动折行，`tests/market/mk04_test.gd` 逐条量过每块板子（对白 798、题干 762、标题 366、状态 300×42 一行、回执纸 456×208 六行）。`UIStyle.text_size()` 会把 18/20 抬到 22，所以一行 22 号 CJK 实际占约 36px：宿主原先给对白板的 56px 内框只装得下一行，本轮已把台词板抬到 `Rect2(338,98,826,86)`（内框 74，见 `scripts/market/level_host.gd:160`），本关的四条长文（REFUSAL、complete 台词、提示一与提示三）也顺手改成不超过 708px 的单行，两种写法都不再压边框。自动化不代表儿童真实理解度或触屏验收。
