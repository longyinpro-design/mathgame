# MK03 封箱里的重量 — v1 样板契约

2026-09-20，第二幕第二张查货台。只新增 MK03 自己的规则、世界、场景、入口、启动器、无头检查与本契约，`kit_world.gd`、`level_host.gd`、`chapter_catalog.gd`、`chapter_progress.gd`、`market_hub.gd`、`market_bridge.gd`、MK01/MK02 与美术清单一律未改。

## 目标

- 育苗铺的两类封箱不能拆开，却要重新挂上实际重量，才找得回扣扣那次的原单。柜面上摊着两次公开称量：`2红箱+1蓝箱=14 斤`、`1红箱+2蓝箱=13 斤`；同类封箱一样重、且为正整数。
- 玩家做的三件事：点记录二把它**叠**到记录一上、消去两份里都出现的 `1红1蓝`，由 `14-13` 读出「红比蓝重 1 斤」；再从左、右两排 1–7 号封箱重签里**各挑一枚挂上**钩子；最后按「挂签复秤」松制动。解唯一：红 5、蓝 4。
- 设计陷阱是单条件近 miss：`4/6`、`6/2` 只兑现记录一，`7/3`、`3/5`、`1/6` 只兑现记录二，提交一律不过——两条同时成立才算数。
- 复用森林岛已有的等量关系作迁移入口，全程不出现代数符号；方程只供作者验算。挂签只服务查货，过关立刻找原单，不再补独立证明表。

## 机制与入账时机

- 幕序 `arrival → approach → ready → puzzle → reweigh → delivery → complete`，三段演出 `approach 1.6s / reweigh 2.6s / delivery 4.2s`；台词由玩家逐句「继续听他们说」推进，第三句后 `approach` 才把镜头推到柜面（与 MK02 同一套暂停、跳过、失焦自动暂停）。
- **柜面不判分**：`record_caption(index)` 与 `difference_caption()` 只吃记录编号、不吃玩家挂的数，因此任何挂法下公开记录的说法一字不变（检查对 64 组挂法逐一比对文案哈希）。玩家按下「挂签复秤」之后才由 `shortfalls()` 逐条说明：先说叠合、再说空钩，最后说哪条记录没兑现、玩家挂的数实际合出多少，一次只讲第一条并给出剩余条数。
- 叠合是场景里的真点击，不是文本框：点记录二那张纸，它滑到记录一上、被消去的 `1红1蓝` 划掉，空出的 `counter_right` 台面摆出差量卡（`14 - 13 = 1 斤`）。`fold()` 幂等——已经叠好时同一个热点变成「分开重摆」，`stacked` 只允许 0/1，叠不出第二份证据。
- 复秤之前秤始终锁着制动（`braked()`，梁恒水平），挂错不会靠画面倾斜泄底；只有 `reweigh` 那两秒梁才摆并回到水平，左盘按记录一、记录二依次装上该条的封箱组、右盘装上等重砝码。
- 通过后 `delivery` 从柜台下翻出原单（写着两条记录与玩家挂的两枚号），`complete` 的回执按玩家真正做过的动作复述：红挂几号、蓝挂几号、消去了哪一组、两条各合出多少斤。
- 每步操作（叠、挂、换签、取回、用提示）先原子落盘再生效；写盘失败弹「重试保存」，重试才把这一步发布，撤销/重摆/提示都不改变已成立的事实。撤销快照只存内存。

## 存档字段

- 独立存档 `user://profiles/market-mk03-1/save-v1.json`，schema 由 `scripts/market/mk03_rules.gd` 的 `validate()` 把关。
- 字段：`sample="market-mk03-1"`、`stage`、`beat`（0–2 台词）、`stacked`（0/1 记录是否已叠合）、`red`/`blue`（0＝钩子空着，1–7＝挂上的重签号）、`hint`（0–3，与 `hint_texts()` 条数同界）。
- `snapshot()` 只含 `stacked/red/blue`，`restore()` 只在 `puzzle` 内生效且结果必须重新通过 `validate()`；空钩不按 0 斤计分，所以没挂满两枚时不会「顺手凑出」一条成立的记录。
- 拒读并保留原文件（`protected`）的情形：别的关卡的 `sample`、未知 `stage`、非 `arrival` 却 `beat≠2`（凭空跳步）、`arrival/approach/ready` 却已有叠好的记录或挂上的签、`reweigh/delivery/complete` 却没解出、越界/负数/小数的重签号、`stacked>1`、`hint` 超上限、缺字段与非字典记录。整数被 JSON 读成 5.0 由 `Content.normalize_numbers` 归回 5。

## 操作与键盘

- 鼠标：点记录二（叠合）→ 点签架上的重签挂到对应箱钩（再点一次取回，或直接点箱钩取回）→「挂签复秤」。柜面上 17 个热点：`fold`、`crate_0`、`crate_1`、`tag_0_1..7`、`tag_1_1..7`。
- 键盘：`1–7` 红箱重签、`Q W E R T Y U` 蓝箱重签、`A` 叠合/分开、`Space` 挂签复秤、`Z` 撤销、`H` 请扣扣提醒、`Esc` 暂停动画；动画中另有「暂停动画 / 跳过当前动画」。
- 命中区一律 ≥48 逻辑像素并随镜头同步缩放：重签 52×52、箱钩 62×62、单张记录纸 124×124、叠好的纸垛 150×150；镜头在 `puzzle/reweigh` 缩放 1.10、偏移 −64/−43。
- 「重摆」只把两枚重签放回签架，保留已经叠好的记录与锁着的秤——已发生的推理不被没收；提示三级（提醒关系 → 缩小关键选择 → 给出 5/4 这一步），不减奖励。

## 边界与已知限制

- 美术全部取 `art/market-kit-v1/manifest.json` 拆件：`scale_stand/scale_beam/scale_pan` 共用系数 0.36（`attachments_px` 的 pivot、left/right_hook、suspension/cargo 逐级对接），`crate_red/crate_blue`、`weight_stepped/weight_hex/weight_small`、`receipt_blank` 加 nursery 底景与扣扣两态；柜台 425/645/877（y 499）与站位 659,424 直接引用 `scenes[nursery].stations`。**没有新裁图、没有手写坐标**，差量、编号、原单文字由引擎绘制。
- 1–7 号是柜面上的实物库存上限，不是提示；两条记录同时成立时仍是唯一解。因此「红 7 · 蓝 0」这类越界组合在场面上不可成立（0 号位表示没挂签），设计上不把它当近 miss。
- 短时演出计时：`kit_world.landing()/hide_while_moving()` 这条路过去在 MK02、MK03 都不生效（`apply_committed()` 先问 `begin_land` 时 `world.state` 还指向旧字典，`land_place` 恒为空）；本轮工作树里已有别的交付把共享基座改成先写 `world.state` 再问谁落地，我没有改动任何共享文件。本关不占用宿主的落地锁，挂签升起与纸叠合各用世界自己的时钟（`track_changes/rise/fold_progress`，0.28s 起挂、0.34s 叠合），两种基座下演出一致。
- CJK 文本不依赖自动换行：台词条内显式 `\n`（最多两行），柜面短标签用 `plaque()/words()` 画在世界坐标里，最宽的一条放在 196px 盒位内（复秤读数牌已按 14px 复核宽度）。本关的开场三句与提示一/三都是两行，而宿主的台词条内框原先只有 56px 高——`UIStyle.text_size()` 把 20 号抬成 22 号，一行 CJK 实占约 36px，第二行会压过木板下沿约 9px；本轮把 `level_host.gd:160` 的台词板抬到 `Rect2(338,98,826,86)`（内框 74），MK03 无需改文案即已在 `01-arrival.png` 里两行都落在板内。
- 无自动求解、无高亮答案、无提示罚分、无失败重播；错误只留在机关里，不弹训斥模态。
- 入口 `game/market_mk03.tscn`（航图上 MK03 已可从「尚未制作」转为待点亮的第二桌，解锁条件为 MK02），或双击 `启动千灯集市MK03样板.command`。从航图进来完成后给「返回千灯航图」，单独启动本关给「回千灯航图」；不改森林存档 schema、不发森林奖励。
