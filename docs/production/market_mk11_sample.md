# MK11 砝码也能站在货物旁 — v1 样板契约

2026-09-20，第二岛「千灯集市」第十一关，第五幕「公平不只是一样多」的第一场（`act=5`、`kit="oil"`、`after="MK10"`）。关卡规格来自 `docs/production/market_chapter.md` 第 179–185 行。只新增 MK11 一套文件（`scripts/market/mk11_rules.gd`／`mk11_world.gd`／`mk11_scene.gd`、`game/market_mk11.tscn`、`tests/market/mk11_test.gd`、`启动千灯集市MK11样板.command`、本文件），不改 `kit_world.gd`、`level_host.gd`、`chapter_catalog.gd`、`chapter_progress.gd`、`market_hub.gd`、`hub_world.gd`、`market_bridge.gd`、`tests/market/run_checks.py`、MK01–MK10／MK12+ 与森林岛共享层，也不改 `art/market-kit-v1/manifest.json` 与 `assets/**`（`oil` 场景的 `levels` 本就已列 MK11，因此本关不需要任何 manifest 变更）。

## 目标

- 题目：育苗铺陶姨要为灯会分装**恰好 7 单位**灯油，自己的罐子没有刻度；老货栈的衡伯只借出 **1、3、9 三枚砝码，每枚最多上一次秤**。两边盘面**都能站砝码**，油只准进左边那只指定货盘，空接油罐的皮重已经归零。玩家自己摆砝码、自己一格一格接油，按下「抬起这杆秤」之后才看秤说话。
- 数学真值（穷举 3 枚 × 三个去处 = **27 种摆法**，检查里逐条比对）：两盘按带符号的差来记，`difference() = 对面砝码合计 −（货盘砝码合计 + 货盘里的油）`。1／3／9 是一组三进制砝码，27 种摆法的纯砝码差恰好与 **−13..+13** 一一对应（两条断言：27 个差互不相同；每个整数被命中恰好一次），于是 0..13 每一个整数量都**只有唯一一种摆法**能把秤压平。7 的那一种是货盘「油 7 + 砝码 3」、对面「砝码 9 + 砝码 1」，`7 + 3 = 9 + 1 = 10`，两盘各压 10 单位。
- 规格点名的默认想法「砝码只能放对面」被显式量过：把三枚全站到对面那一头，能压平的量只有 **0／1／3／4／9／10／12／13**（`naive_amounts.sort()` 与 `[0,1,3,4,9,10,12,13]` 逐字比对），**7 不在里面**。而「三枚全放对面」恰恰是玩家最自然会先试的那一步（提交闸口不拦它），提交后秤如实报「对面那盘沉下去了：货盘 7 单位，对面 13 单位。」——近失踩到的是真实的失衡，不是被系统挡回去。
- 与 MK03 不重复：MK03 是两份公开称量记录叠合消元、再给红蓝箱挂重签复秤（读的是总数与消去）；本关**提交之前一个数字都不报**（两盘的描边读数只写「货盘 · 油压在这头」／「对面那盘 · 只站砝码」，状态板只写玩家做过的事），判的是「同一枚砝码站在哪一头」这个符号选择，不做消元、不给候选结果表。第五幕支线 MK14（`5+3+1=9`、`8+1=9`）直接复用本关的 `signed_sum(goods, far)` 记法，检查里对 27 种摆法逐一比过 `difference() == signed_sum()`。
- `complete` 的复述只有玩家真正摆出来的那两盘：衡伯的验看单 6 行，两盘各自的重述取自 `Rules.terms()`／`pan_total()`，画面与回执都不另立第二套说法。

## 机制与入账时机

- 八个字段里只有 `goods`／`far`／`oil` 是现场，合计、哪头沉、倾角、式子、判词**永远**由 `mk11_rules.gd` 现算，世界层一克都不另存；因此「拿起来又放回」不可能留下幻影读数。`return_weight()` 一次把两盘同一格一起写回 0，两盘永远不同时记同一枚。检查里 27 种摆法逐条走「按目标位一枚枚请上秤 → 全部放回台面」，中间态与末态都要 `validate()` 得过（`all 27 placements are reachable and every one wipes clean`）。
- 提交闸口只管「手底下还没动手」，不判数学：`shortfalls()` 只有两条物理职责——「接油罐还空着：先拧开油壶，一格一格往货盘里接。」与「三枚砝码都还在台面上：至少请一枚上秤，空秤称不出任何约定。」。检查穷举 27×14 = **378 份现场**，断言被拦下当且仅当 `oil == 0` 或一枚砝码都没上秤；再把 378×6 次字符串扫描钉死这两句里不得出现「差／多／沉／不平／答案／7 单位」任何一个词——摆放过程中没有任何一处会预告该接多少。
- 抬秤之后才说话，且各说各的职责：`advance()` 在 `puzzle` 只写 `weighs += 1` 并进 `weighing`，**盘面与油一滴不动**。`weighing`（2.4s）里 `beam_angle()` 先按 `tilt()` 如实沉到底、再带阻尼回静止位；不平或接错数就落 `result`，判词分两条（`result_lines()`）——秤那条点名沉下去的那一盘并把两盘合计读回来（`beam_line()`），约定那条只说「多了 N 单位」／「还差 N 单位」（`promise_line()`）；平了且确实 7 单位就直接 `delivery`（3.6s）→ `complete`。`result` 的唯一出路是回 `puzzle`（检查里专门断言这一步不往前，另一步「读判词不扣油」也断言）。平秤却接错数（`1 + 8 = 9`、`3 + 6 = 9`）两种情形单独立项，秤杆不背锅。
- 五个动作都以 `validate(next)` 收尾、只在 `puzzle` 放行：`place()`（请上某一盘，原来站在对盘就是「挪过来」）、`return_weight()`（放回台面）、`cycle()`（点一下走一格：`台面 → 对面那盘 → 货盘 → 台面`，`NEXT` 的第 0 项就是所有人默认的那一步，再点一次才是本关要教的那一下）、`draw_oil()`／`pour_back()`（一格 1 单位，罐满 13 单位就拒）。被拒的动作返回 `{}`，宿主一律先写档、写成功才改内存并落下（`level_host.place()`），所以保存失败时历史与现场一起停在原地。台词阶段（`arrival/approach/ready`）与三个结算阶段全部拒绝改动，`arrival` 连键盘也闲置（四条 `is_empty()` 断言）。
- 无自动求解、无高亮答案、无提示扣分、无失败惩罚：`hint` 三档主动索取，上限 `HINT_TIERS = 3` 与 `hint_texts().size()` 对齐（检查两头都量过），第三档示范「把 9 单独留在对面、让 3 站到灯油这头、再把 1 补到对面」这一步该往哪儿想，但不替玩家按下。取满三档之后现场仍然合法、仍然一次抬秤就交付（检查里连着跑 `advance → delivery → complete`）。
- 撤销快照与现场同源：`snapshot()` 只交 `goods`／`far`／`oil` 三键，`restore()` 只在 `puzzle` 生效并要重新 `validate()`。抬过几次秤是已经发生过的事，快照里没有它也就改不动它（`restore(...).weighs == 3` 一条专门断言）；`weighing/result/delivery/complete` 四幕一律拒撤销。检查对 27 种摆法 × 每枚 × 两个去处 + 放回逐条 `restore(moved, prior快照) == prior`，坏快照（缺 `oil`／缺任一盘／`oil` 是浮点或 14／同一枚记在两盘）四种拒收单独立项。
- `重摆` 只擦现场：`cleared()` 把两盘与罐子归零，`stage` 与 `weighs` 原样留着（检查里 `cleared(puzzle,2) == pose(空,空,0,"puzzle",2)`），弹窗文案就这么写；`重新体验` 才另起一幕。

## 存档字段

`user://profiles/market-mk11-1/save-v1.json`，八个字段：`sample="market-mk11-1"`、`stage ∈ [arrival, approach, ready, puzzle, weighing, result, delivery, complete]`、`beat ∈ 0..2`（开场三句，离开 `arrival` 后必须停在 2）、`goods=[1 单位在货盘?, 3 在货盘?, 9 在货盘?]`、`far=[…]`（两个长度 3 的 0/1 数组）、`oil ∈ 0..13`、`weighs ≥ 0`、`hint ∈ 0..3`。

`mk11_rules.gd::validate()` 拒读并把原文件交给 `save_repository._protect()` 保留的情形（检查里 **52 条 schema 判定**，其中 **45 条是拒收**、含 6 种非字典载荷）：外来 `sample`（`market-mk03-1`）、未知／缺失 `stage`、`beat` 为负／字符串／越过 2、`beat` 停在半句话上却写成后面的幕、`hint` 越档或为负或浮点、`goods`/`far` 长度不是 3 或值为 `2`／`-1`／`1.0`／`"1"`／整个键缺失、`goods`／`far` 不是数组或为 null、**同一枚砝码同时站在两盘**（含「三枚全用两遍」那份）、`oil` 为 14／负／小数／字符串／缺键、`weighs` 为负／小数／字符串、`arrival/approach/ready` 却带着油、抬秤记录或盘上砝码、`weighing/result/delivery/complete` 里 `weighs < 1`、`result` 却已经解开（「结果牌还立着」与「这一秤已兑约」不能同时成立）、`delivery/complete` 里那两盘不平或油不是 7（伪造回执）。`legal_snapshot()` 另把「没有两盘／油不是整数」的撤销快照挡在 `restore()` 之前。

## 操作与键盘

- 鼠标：点台面或盘上「已经站着砝码」的那一格 → 它往前走一格；点盘里空着的那一格 → 把留给它的那枚直接请上来；点台面上那格而它已经上秤 → 放回台面；点陶姨车上的油壶 → 接一格；点提斗或罐口 → 倒回一格；`抬起这杆秤` 提交；`撤销 Z`；`重摆`（先弹确认）；`请扣扣提醒`；动画中可 `暂停动画`／`跳过当前动画`。挪不动时被明说：「这一枚现在挪不动：先把它放回台面，再决定它站哪一头。」／「3 单位 已经站对面那盘了。」／「接油罐已经空了：先点油壶接一格。」
- 键盘：`1`／`2`／`3` 让 1／3／9 单位那枚往前走一格，`Q`／`W`／`E` 把对应那枚放回台面，`A` 接一格，`S` 倒回一格，`Space` 提交，`Z` 撤销，`H` 提醒，`X` 重摆（宿主底栏那颗按钮上就写着「重摆 X」），`Esc` 暂停（动画阶段）。纯键盘可通：`2` `2`（3 走到货盘）→ `1`（1 上对面）→ `3`（9 上对面）→ `A`×7 → `Space`。每条悬停句末尾写的「键盘 X」都由无头检查逐条兑现：三种台面（全在台面／一枚站在货盘／一枚站在对面）× 12 枚热点，把「点这一下」与「按那个键」各演一遍再比现场，写错键或点了是另一回事都当场报错。
- 热点全部由 `target()` 生成、`add_hotspot()` 注册，共 **12 枚**，都 ≥48×48、都在 1280×720 内、两两不重叠（检查逐条量过）；贴近之后（`zoom_stages` 的 1.10 缩放）再按 `get_global_rect()` 量一遍，仍 ≥48×48 且落在 y 166..646 之间，不压对白板也不压右下角出口按钮行。油壶／提斗 `target(挂点−(0,4),56,30)` → 56×56，罐口与六格盘面槽 `48×48`，台面三格 `52×52`。
- 坐标只从 manifest `oil` 的站位与拆件挂点推出，关卡不另立第二套：`scale_foot 640,527` 与铜秤三构件共用 `SCALE_FACTOR = 0.85`（manifest 的组装约定，不各自套 `suggested_width` 再强行对接）→ 支点 (639.15, 270.3)、左右挂勾 (481.05 / 794.7, 270.3)、盘面 `cargo` 点 y≈444.55；`scale_beam` 的 `left_hook`/`right_hook` 随倾角绕支点旋转，`scale_pan` 只平移、自身永远水平。三车取 `cart_left/middle/right = 348/607/859,384`，宽度 200／132／172；油壶与提斗用 `delivery_cart` 的 `cargo_left`／`cargo_right` 挂点。台面是 `scale_foot + (-340, 33)` 上宽 200 的 `receiving_tray`，三格 `BENCH_DX = [-56, 0, 56]`；盘上三格相对 `cargo` 的横移 `SLOT_DX`＝货盘 `[-25, 25, 75]`、对面 `[-50, 0, 50]`，接油罐固定在最左 `POT_DX = -75`，因此货盘那三格天然给油罐让开。扣扣 `scale_foot + (420, 73)`、交付落点 `scale_foot + (260, 33)`。

## 边界与已知限制

- 陶姨与衡伯没有集市人物拆件（`market_asset_handoff.md` 批次一只交 `koukou-v1`），两人全程只以台词、木牌与「陶姨的油车」出现；扣扣只有 `tie-parcel`／`waving` 两个离散姿态（缩放 0.5），不是连续动画，位置由 `scale_foot` 推出（`oil` 场景没有人物站位）。
- 不做拖拽：点一下走一格是本关刻意的教学装置（第一格正是默认想法，第二格才是突破），代价是「一步跨到想放的那一盘」需要两次点击；空槽直接请上来这条短路一直在，所以熟练玩家没有多余步骤，`1`／`2`／`3` 与 `Q`／`W`／`E` 也各留了一条直路。
- 油只能一格一格接、上限 13 单位（三枚砝码总重）：再多的油本来就不是这杆秤能兑的约定，撞上时明说「接油罐最多接满 13 单位：三枚砝码全压上秤也就这些，再多这杆秤就兑不了了。」不存在小数油格，也不存在「先接个大概」以外的表达手段——`pour_back()` 就是那一步。
- 判分只有一条：`solved() = oil == 7 且 difference() == 0`。没有步数、没有用时、没有扣分，`weighs` 只是街上发生过的事。倾斜幅度是纯演出：`tilt()` 把差按 `FULL_TILT = 3` 截到 ±1、`MAX_ANGLE = 0.2` 弧度，从不参与判定；提交前 `braked()` 恒真、秤杆永远水平。
- 本关不做 1..13 逐个称一遍的表（那是 MK14 支线明确不要求的事），也不给「另一份 7 单位」留第二条解：三进制砝码的唯一性由检查穷举钉死（27 种摆法里对 7 只命中 1 份，且那一份的货盘上必有一枚砝码）。
- 铜秤没有专属摆动骨骼：`scale_beam` 用 `draw_set_transform` 整体旋转、`scale_pan` 只平移（manifest 承诺的组装方式），因此不承诺链条与盘沿的次级形变；批次二若给出秤的拆件，只需替换 `draw_scale()` 的三个 `id`。
