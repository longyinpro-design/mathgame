# 森林岛：让送种子的旅程真正发生在场景里

日期：2026-09-19。状态：**用户已授权按本方案实施；实际进度与验证见执行计划。规则与存档契约保持兼容。**

依据：本轮试玩反馈、当前脚本、v07 留存画面及[第二岛场景化设计](market_art_direction.md)。承接[叙事流程](narrative_flow.md)中“剧情触发机关、解开后接戏、主线无需自行赶路”的方向。本文设计表现与体验，不替代当前关卡判定；实施进度统一记入[执行计划](../试玩实现计划.md)，不另设开发队列。

## 原图融合修订（2026-09-19）

用户试玩否定了统一叠加木台/石台的方案：即使消除文字遮挡，大片新地面仍破坏原画构图。以下原先“补承重地面”的建议以本修订为准：优先在原图已有路面、台阶、平台上设置不可见站位与交互锚点；确需新增可视物件时逐场景匹配透视、光照和遮挡，不再铺统一整宽地台。

首个完整样板为 FL03：原图三间屋就是三粮仓，仓门接收点击、小数量签跟随仓门；人物站在原有石路，以路程驱动步态推粮车。原图、数学规则、奖励与存档格式保持不变。入村/入关/结果剧情使用同一坐标系，控制与对白放在石路下方。最终验收要同时看真实输入、守恒/存档和实窗截图；几何测试通过不等于美术融合通过。

其他地区按各自地形再设计，不能把本村锚点平移复制到树梢、磨坊或深谷。当前交付范围与后续顺序只记既有执行计划。

## 1. 诊断：故事已连接，空间与行为尚未连接

目标体验是：**我和伙伴送一袋种子进森林，沿途帮助居民恢复生活，最后让春天重新回应。** 玩家记得站长接种子、苔团终于放下担心、村民能够回家、磨坊把物资送出去；数学是实现这些行动的方法。

现有实现已经有六幕故事、真实关卡收据和部分永久场景变化。本次问题在这些环节之间：

| 现状证据 | 体验后果 | 重构要求 |
| --- | --- | --- |
| `story_stage.gd::_update_pose()` 对不同地区统一使用约 y=450 的站位；v07 `story-opening.png` 中人物脚下是远景树海 | 人物像贴在画面上；加脚底阴影也不能制造不存在的平台 | 每处场景先设计承重地面，再放人物与机关；按镜头设置站位 |
| `companion_actor.gd` 按时钟播放三帧走路；剧情位移独立插值；地区队伍按固定偏移一起移动 | 脚步无法稳定对应位移，队伍缺少各自行动 | 步态跟随实际路程，停步落脚；伙伴有路径与跟随间距 |
| 剧情、机关分别布置；`puzzle_boards.gd` 用通用大面板承载多类操作 | 入关像打开另一套答题页面，背景只提供气氛 | 同一机关从远景进入近景，实际操作其部件，结果发生在原位置 |
| 递信由固定坐标插值，信封用矩形与线绘制；木牌样式也用于通用结果字幕 | 道具缺少持有者、支撑和用途，外观换皮仍像浮层 | 道具具有位置、挂点、状态和去向；系统字幕与实体木牌分清职责 |
| 灯亮、磨坊暖光等变化部分只在地区页呈现；正常主线走故事页 | 玩家帮助过的地方有变化，但主线可能看不到 | 后果先在当前故事镜头发生，此后近景、远景、回访保持一致 |

以上动态问题是源码可见的机制风险与用户反馈相互印证；本轮查看的是留存截图，未重新录制逐帧运行画面。具体脚底偏移、速度与素材帧质量，实施时须实机量测。

## 2. 森林岛自己的生活与感情

森林岛关键词：**托付、照料、慢慢恢复的日常**。材质以旧木、麻绳、苔石、纸、树根为主；动作以抬、递、扶、拉、种为主；声音以脚踩木板、绳索受力、水轮、门环、虫鸟为主。第二岛的交换、称量、签收与灯会保持独立风格。

三个持续可见的线索贯穿全岛：

- **种子袋**：开场在下站，送达后站长拆出信；后续送往古林的是居民准备的新一批种子，保留相同叶纹封签以表示合作。FL18 的15颗是该机关明确给定的库存，不伪装成全章共用背包资源。
- **来信与回信**：最初有人等待春天，邮路恢复后有人回应，终场站长拿出航图与去育苗铺的送种委托，为千灯集市开场接棒。保留既有航图奖励与时点，新增台词属于提案。
- **有人继续生活**：站长整理下一趟货；村民点灯回家；磨坊师傅把育苗盘送上推车；折羽把真正的信交给居民。每件事解决后，都有一个人开始做此前做不了的事。

角色差异必须发生在行动中：阿橙先迫不及待伸手，后来会等同伴准备好；苔团起初护着光晶，之后愿意放下它帮助搬种子；折羽初见忙乱地整理邮袋，结尾能停下来认真核对寄件人。对白只补充动作无法传达的意思。

每个地区安排一段没有答题要求的短暂生活：上站听绳铃、灯下喝汤、磨坊旁看幼苗、邮亭听回信、营地给阿橙系叶结。点击可以触发小动作，玩家也能直接继续。无奖励催促、无额外打卡、无必须看完的重复动画。

## 3. 空间先行：先有能站的地方，才有角色动画

保留现有远景的构图、色彩与气氛；为故事发生区补足可操作的中近景。

| 地点 | 可承托的空间 | 前中后景与镜头用途 |
| --- | --- | --- |
| 树梢站 | 下站木台、上站栈台、联动吊篮与两侧绳轨 | 远处树海，中景双站，前景栏杆；开场同时看懂上下关系，装载时靠近篮口 |
| 三门林台 | 三座嵌入石壁的门、连续石台、明确连接各门的光槽 | 队伍站在台边；门脚接石基；切近仍能看到苔团与同一门环 |
| 晨种村 | 粮仓院、灯架工作台、通向住宅的路 | 粮袋从仓门取放；灯架连接村路，亮灯后居民经过，远景窗灯接续亮起 |
| 旧磨坊 | 育苗车间地板、固定工作台、机器底座与传动带 | 角色站台前，卡槽属于机器；水轮与育苗出口留在视野边缘 |
| 林间邮亭 | 拣信桌、分层邮袋架、峡谷栈道与路口 | 桌上模型准确呈现路线拓扑；实际道路的广角镜头回应已提交方案 |
| 古林内庭 | 守门石台、石灵根座、树根桥、环绕芽眼的落脚区 | 试炼盘嵌入地面；树根真正连到对岸，镜头确认桥成形后队伍再通过 |

背景分为远景、可站立层、人物/活动机关、前景遮挡和光效。栏杆应能挡住角色小腿；人物经过柱子时前后关系正确；机关支架与绳索不能只存在于背景画里而活动件悬空。

不需要为主线新增自由探索系统。旅行仍通过短镜头完成，只制作必要的路径、停点与交接动作。无法自然走通的长距离用有空间依据的镜头切换连接。

## 4. 人物与道具：每个动作都要接触到东西

### 行走、停步与站立

- 每个场景定义地面、站位、路径、前景遮挡；角色根节点代表脚底接地点。不能用全场统一 y 值代替地面。
- 先核验现有图集逐帧的脚底 pivot、朝向与步幅，再补缺帧。小岚至少有完整的左右踏步和停步姿势；苔团的短跳、阿橙的步态、折羽的地面动作各自设计，不共用频率与滑动幅度。
- 地面移动量推进步态相位；接近目标时减速并落在稳定支撑帧，停止后转待机。转向发生在起步/拐点；手持物跟随实际挂点。
- 影子投在承托面上，角色身体可呼吸、跳起，影子不跟着离地。折羽飞行须有起飞、落点与高度变化；普通站立不加持续漂浮。
- 对话中只让正在说话的人做主要手势，其他人注视或短暂回应。同行伙伴各自从路径上的不同位置起步，不整排平移。
- 无障碍缩短动作或跳过后，角色直接抵达合法落点、道具进入确定的最终持有状态。

### 信封、木牌与小组件

| 对象 | 属于世界的状态和动作 | 信息呈现 |
| --- | --- | --- |
| 信封 | 夹在种子袋封绳中 → 站长取出 → 两人交接 → 小岚拆封 → 收进信袋 | 可打开阅读近景，保留信纸边缘和角色手部；正文由引擎排版，随时回看 |
| 木牌 | 有木桩、钉子或挂绳；角色翻牌、挂新签后才改变内容 | 只承载当地用途：站名、载重、订单、方向。通关说明放手记或字幕，不做悬空木牌 |
| 光晶 | 在门座槽内、搬起、沿光槽移动、入槽；一颗只有一个位置 | 数量准确、转移依据实际规则；不能用装饰飞粒代替真实库存 |
| 种子袋/邮包 | 在地面、在手中、在篮里、到站卸下、收纳 | 对象身份和首通奖励保持原契约；动画不得多画一份“同一物件” |
| 拉杆/门环 | 有支点、可操作范围、按下/复位；角色伸手或鼠标直接操作 | 鼠标、键盘、点选替代拖动共用同一行动；关键限制常显 |
| 对白/工具栏 | 对白靠近当前说话者或稳定底栏，工具栏保持固定位置 | 不把设置、撤销、帮助强行藏进道具；大段规则可展开，目标与硬约束不被隐藏 |

递信必须看见“伸手—接触—松手”：信先属于站长，接触时转给小岚。阅读放大可以采用近景切换，不把信从两个人之间自动飞到屏幕中央。身体、手部与道具层级共同制作，不能仅补一张信封贴图。

## 5. 18关的场景载体与真实后果

下表是表现映射，不是新数学契约。当前实现和最新专项修订优先于历史正文：特别是 [FL08/FL10 重设计](../playtest/playthrough-repairs/route-redesign.md)已把“枚举全部路线/六组配对”改为复核邮袋及同时通行上限；旧存档仍按自己的冻结版本恢复。

| 关卡 | 玩家眼前正在做的事 | 机关如何成为场景的一部分 | 结果及后续生活 |
| --- | --- | --- | --- |
| FL01 | 和阿橙把种子送到上站 | 双站、绳轨、篮底、装卸区真实相连；重量标牌挂在对应对象旁 | 按实际到站状态卸货；小岚从篮口走上栈台，站长取信 |
| FL02 | 帮苔团稳住通往村子的光 | 光晶嵌入门座，敲实体门环后按规则沿槽借光；总24与目标等亮仍可查 | 三门不再闪烁；光沿石路通往村庄，苔团收拾自己的小包走来 |
| FL03 | 替林婆婆理清粮仓旧账 | 仓院缩景与账页同框；玩家摆初态和记录时刻，查看时明确是旧账回放 | 核清后村民才开始今天的分粮，避免把历史演算当作重复搬动现存粮食 |
| FL04 | 让等着回家的人有灯可用 | 灯架在院中的合称台试称；读数牌随实际试称揭示，三架各有调节位 | 提交正确后挂回灯柱；一位村民提篮走过，亮灯照出磨坊方向 |
| FL05 | 修好育苗机第一段 | 两页记录夹在机壳，运算模块插入两个有顺序的实体槽；保留预测/试机操作 | 真实输出通过机器出口呈现，师傅把第一盘幼苗移走 |
| FL06 | 用一次试验认出失去铭牌的机器 | 三张候选说明与玩家预测签摆在试验台；先预测再投送，错误照原规则处理 | 师傅按实际识别结果挂回铭牌，阿橙把观察记入手记 |
| FL07 | 校准最后一台育苗机的24刻度 | 1/4/5/9为机器原配的四枚符牌，两输入槽、运算拨片、结果槽形成真实机台 | 每次合成按所选顺序收回两牌、生成结果牌；全部使用且恰24才接通传动，育苗盘送出 |
| FL08 | 帮折羽复核错放和漏掉的邮路记录 | 三层邮袋、可翻看的路线签、玩家填写的数量签都在拣信桌上 | 把错签移正、补漏签后装袋；折羽放下慌乱，带着邮袋加入 |
| FL09 | 为落石选择最少妨碍送信的位置 | 栈道模型上摆预测签，四处预测齐全再试放揭示；实际峡谷暂不变动 | 确认合法最优方案后，居民把真实落石移到玩家所选位置 |
| FL10 | 安排互不占用中途节点的邮路 | 邮亭路线模型上选择同行集合，并给出当前要求的上限理由 | 邮鸟按实际合法路线送信；不引入速度、错峰或反应操作去绕过节点约束 |
| FL11 | 把居民合送的物资运入古林 | 四件上行货和三块配重在站台准确可数；两位/载重5/到站退出标牌靠近篮口 | 每趟按状态卸下，到站退出者不再出现在候选区；三趟完成后大家会合 |
| FL12 | 接受守门人关于留后手的邀请 | 双方围坐在石桌前，用真实棋子操作；三起局及关键回应记录做成可展开对局记录 | 对手履约领路；阿橙的成长回应落在随后营地戏中，不重复讲解策略 |
| FL13 | 回访帮站长改进一趟额外货运 | 复用树梢站但标清本关公开条件与两趟目标，不带入FL11退出/载重限制 | 站长把两趟安排夹在工作板上，保留当前最优性证据要求 |
| FL14 | 和阿橙试走一段有步幅约定的石径 | 石径旁用脚印筹码规划五步，再让阿橙演示；三目标与改一步的任务都保留 | 可达轨迹在真实石面走出；不可达说明由玩家选择，不演成强行跳过去 |
| FL15 | 帮师傅找到一颗偏重光晶 | 九晶盒、双盘秤、三分支预测板属于同一工作台 | 依据真实称量倾斜；保留覆盖所有隐藏位置的计划，不能缩成碰巧猜中 |
| FL16 | 给邻居围出借墙的花圃 | 十二段围栏在墙边试排，五种宽度的试验记录可回看；面积按已试结果显示 | 试齐并选出真最优后，居民沿玩家围定的花圃播种，回访可见 |
| FL17 | 接住石灵变招，换来通往树心的桥 | 三符、封盘和回应发生在嵌地石盘上，石灵的动作有预备与落点 | 依胜局放下真实连接两岸的树根；队伍过桥再切树心镜头 |
| FL18 | 留够种子，与伙伴唤醒真正的芽眼 | 15颗机关库存、侦察、真伪回响与合击目标靠近对应实体显示 | 仅有效胜利触发复苏；每个伙伴承担动作，镜头依次回访灯路、磨坊、邮亭 |

FL07 仍然是一项带数字的魔法机器校准任务。运算符、完整括号、负数/分数中间结果保持准确；用符牌承载数值，不把负数误画成“负数袋种子”。机器的24目标须在剧情前就有清楚铭牌，避免解完后才编理由。若可玩样板中它依然被感知为插入的24点小游戏，应单独讨论机制与故事动机，不能声称美术改造已解决一切。

## 6. 第一幕怎样演：制作质量样板

沿用“送种子 → 拆信 → 三门借光 → 苔团加入”的原故事范围，升级空间、接触动作和连续镜头。这是优先制作建议，尚未开始实现。

1. **看到眼前的事。** 远景交代上下站。下站种子袋放在木台，小岚脚踩木板，阿橙试着碰一下拉绳；上站的站长挥手。台词只说“先把种子送上去，村里还等着呢”。公开规则在靠近机关后完整展示。
2. **接手原来的吊篮。** 镜头靠近篮口，配重、装载区和重量签已在同一个场景；玩家点物件再点篮位，或拖动。以手部取放或简短贴近运动表示搬运，连续小操作不每次等待一段完整搬运动画。
3. **看见自己完成的运输。** 松闸先绷紧绳索，再升降，刹车轻响，篮底停齐栈台。人物从正确篮口下篮；种子袋到站卸下。非最终一趟不提前演全员到齐。
4. **一封信改变目的。** 站长扶稳种子袋、取出夹信，伸手递给小岚。玩家点信封拆开，看到“种子备好了，古林还没有传来春天的回声”。读完收信，阿橙顺着信角的绿光抬头。
5. **到达有人的地方。** 镜头跟绿光经过树枝，再在三门的连续石台落下。苔团正在护住忽明忽暗的光晶；队伍沿台边短距离走近并落脚停住。玩家自行推进对话、开始帮忙。
6. **操作刚才看到的三门。** 镜头靠近原门座；苔团仍在边缘看着玩家。摆光晶、敲门环、看真实转移；失败留在现场，保留原有撤销与重摆。
7. **结果变成关系。** 门光稳定，接通村路。苔团先确认三道门，再放下紧抱的光晶袋，主动拾起行装跟来。邀请对白由玩家推进，入队来自原首通状态。
8. **带着变化离开。** 三人背影沿亮起的小路走向村口；苔团回头看一次仍亮着的门。下一个场景从村民迎接开始，不回到标题/奖励/选关页。

制作目标：单次操作反馈约0.15–0.4秒，重要结果约2–5秒，长演出分为可跳过的小段。时间只是初始调校值；不得覆盖必要的读数、转移步骤或角色落点。对白不自动翻页，试错不重播入场戏。

## 7. 资源与工程切入点

制作顺序建议：**树梢站完整样板 → 三门与入队闭环 → 用磨坊验证数字机关也能融入 → 按六幕推广 → 终场回望。** 每段都覆盖动作、输入、错误反馈和保存恢复，不能先把18关统一套皮肤再验收。

首批美术交付要围绕第一幕：上下站地台/栏杆/遮挡层，分层吊篮与绳轨，三门石基/门环/光槽；小岚走停、取放、接信、拆信，站长递信，阿橙上下篮，苔团护光与收包同行；信封、信纸、封绳、木牌的可操作状态。现有图集能修则修，缺失动作按动作表补齐。单张概念图和姿态拼图不能视为连续动画资源。

| 当前模块 | 后续责任调整 |
| --- | --- |
| `forest_world.gd` / 场景资源 | 持有承托面、对象位置、遮挡、分层背景和地区恢复状态；故事与回访共享相同成果 |
| `companion_actor.gd` / `npc_actor.gd` / 图集元数据 | 逐帧脚底校准、移动驱动步态、停步、朝向、手持物挂点；缺动作明确制作 |
| `story_stage.gd` | 按每个镜头的真实场景锚点编排角色与交接，不给所有地点套同一排坐标 |
| `forest_release.gd` / 各机关展示组件 | 以近景、交互焦点切换连接剧情与机关；世界对象身份与姿态连续，减少整页UI重建的视觉跳变 |
| `story_catalog.gd` | 保持故事节点与关卡钩子；补人物目的、场景后果与岛际衔接，逐句核对当时已完成的状态 |
| 规则、会话与存档模块 | 继续拥有真实状态、合法性、结算和恢复；表现只消费已提交结果，跳过不再结算一次 |

可复用同一场景节点，也可由同一场景描述在不同镜头重建；选择最小可行方式，以玩家看到的连续性为验收标准。无需先搭建通用剧情编辑器、物理引擎模拟或完整导航系统。

对象从地面→手→篮→站台的表现归属唯一。若角色本身是货运对象，搬运时只显示篮内角色，避免世界演员与货物图标同时代表同一人。装饰性回放不改变库存。未保存成功不展示成功后果；恢复从已提交动作落点或确定的镜头检查点继续，不能重复发奖励或递出第二封信。

## 8. 怎样证明这次调整有效

**先验收一个可玩的连续片段，再扩大制作。** 功能测试通过不等于人物落地、剧情成立或玩家产生感情。

- 画面/录像：站台存在，脚底落在承托面；不同帧、朝向、窗口尺寸下均不跳脚。慢放行走检查接触脚是否滑动；进出篮、交接信、停步与遮挡逐项看真实运动。
- 连续性：入关、失败、过关与对白切换时，同一门、篮、信保持位置、尺度关系与状态；无瞬移复制；正常主线必然看到结果，非靠回访才能看到。
- 规则：本次候选的关卡判定、最新FL08/FL10形态、FL11七件货单、FL07四牌及首领真实资源均保持；道具化不删除推理证据、不提前亮答案。
- 操作：至少在1280×720和960×540验证；所有关键对象可点选、键盘访问，拖动有替代；正文可阅读回看，限制与目标常显，前景不遮住操作区。
- 恢复：装载中、到站后、递信前后、三门未完成、入队后测试保存恢复；暂停/跳过/缩短演出与不跳过得到相同业务状态，错误不会靠重播剧情消失。
- 体验：首幕试玩后不先提示答案，询问“你来做什么”“苔团为什么愿意跟来”“你刚才改变了哪里”。观察玩家是否会自发描述人、物与结果，是否知道下一步的目的；记录原话，不以会背关卡名称作为成功。
- 第一幕成立后用FL07做第二个样板，专门验证最抽象的数字机关；若这两种样板仍割裂，先调整动机、承托空间和动作节奏，不直接批量推广。

本方案已进入首轮实现：第一幕共用吊篮现场、角色地面与步态、手持信件、三门结果连续、磨坊实体操作台，以及全岛共用地面/工作台已落地。具体完成范围、最终候选验证与保留限制见[执行计划](../试玩实现计划.md)和[本轮交付记录](../playtest/scene-integration/README.md)。本文各节保留设计目标与改前诊断，不表示所有定制动作或真人体验验收均已完成。
