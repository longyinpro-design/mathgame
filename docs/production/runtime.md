# 森林岛运行时与验证

本文记录森林岛章节开发版的实际引擎结构、存档边界和验证入口。制作契约继续由本目录的关卡、首领和RPG文档拥有；本页不代替真人试玩、平板验收或发布许可。执行进度只维护在[原计划](../试玩实现计划.md)。

## 可玩范围

正式入口为 `game/forest_release.tscn`，默认打开故事停点，包含六幕剧情、营地、五个地区回访入口、FL01–FL18、阿橙/苔团/折羽、最多两位同行、阿橙同心叶结、三项营地建设、任务物与四条支线收藏。已解决关卡可以从手记回看对白并再次体验；重玩产生新的尝试记录，不重复首通奖励。

普通关以解开机关为通关条件；两场首领使用实际战斗回合。FL02不是旧双盾题。普通关由规则判定机关状态；首领由实际回合、有效观测、库存和合击动作结算。没有在线AI、账号、支付或云存档。

## 模块与内容

- `scripts/content/content_catalog.gd` 读取已验算的 `forest_levels.json`，索引稳定ID、奖励与前置关系；拒绝未知机制、无效奖励和循环前置，去掉作者的 `expected` 验算报告。当前运行时版本为 `forest-runtime-1`。FL07的新规则为 `twenty_four`，原 `machine_ambiguity` 定义仅用于历史记录兼容。
- `scripts/mechanisms/` 按货运、转移、机器、邮路、策略、支线和首领分开实现纯规则。`mechanism_rules.gd` 只选择对应机制。随机隐藏情形由会话在创建挑战时选择，规则本身不调用随机数。
- `scripts/core/game_session.gd` 拥有档案、命令顺序、待保存候选和本次撤销栈；界面提交意图，不能直接发奖励。`quest_progress.gd`、`roster_progress.gd`、`learning_record.gd` 分别处理任务投影、关系/能力及学习事实。
- `scripts/ui/forest_release.gd` 协调页面、输入和演出，机制操作板与绘制在独立UI文件中。所有页面共用一个音频实例，音乐与森林环境音分别有一条循环。挑战页只显示目标与机关；没有分步对照教程页、流程横幅或练习建议入口。目标行写清该关的数学规则与硬约束；各板面把数学过程显示出来（转移的每步算式与相等判定、灯架逐条合重 ✓/✗、试机三台结果对照、落石每处"留下N条"、花圃用料与面积、货运件数/载重与趟数）。操作按钮与反馈使用场景语言（敲响门环/启动机器/送信出发），不使用"试运行/核对"一类测试用语。
- `story_catalog.gd` 定义稳定节点、入关缘由、后果对白和角色。`story_progress.gd` 处理节点确认、FL09/FL10分支汇合、支线/重玩返回点与结果快照；主线不再根据地区列表猜下一关。
- `story_stage.gd` 复用角色动作图集与场景，表现卸货、递信、拆信、穿林、等亮与结伴。动画时间不参与规则判断；“跳过本段动作”只落到当前场景最终帧，下一段对白仍需确认。暂停、失焦冻结演出；切菜单后返回继续当前表现，重启重放当前稳定节点。
- 解开关卡时先完成既有机关动画，再自动进入已提交的后果节点；不再经过主线结算横幅/地区选关。营地的“继续故事”接回当前停点，手记提供已开放支线和已完成关卡回访，无需走近物件。
- `challenge_selector.gd` 的 `support_for` 保留为存档字段兼容，恒返回 `show_scaffold=false`；教学支架与推荐练习已从游玩中移除。

货运只接受当前冻结的六物件、重量和初始站位；FL11再加容量2、载重4与到站退出，FL13只加容量2。改变这套物件身份需要新的规则版本，不能只改JSON而继续调用旧货运内核。

## 表现层生命周期与局部更新（2026-09-22）

`game/forest_release.tscn` 持有森林、货运、战斗、24点、剧情、音频、UI与浮层的常驻节点；`forest_pages.gd` 只构建营地、地区、剧情、手记、伙伴、回访和设置页面，导航与事务仍由原宿主拥有。场景骨架可在编辑器查看，机关内容继续由各自的操作板构建。

`presentation_layer.gd` 用原生继承式 `process_mode` 管理整个表现分支：隐藏时冻结，重新显示时续接。剧情暂停/失焦冻结子演员与背景；森林失焦还冻结宿主绑定的 Tween，包括两封信与影子探路。集市宿主把暂停、模态及焦点状态同步给世界时钟；已失焦暂停的正式演出仍由玩家点击继续。恢复表现不会重新发出数学命令或写存档。

三门/粮仓选择与24点选牌只更新现有节点；规则提交、切页及退出时刻回看仍走原刷新路径。静止转移台、未完成且指针已稳定的24点机台、无动态灯光的地面层保留绘图缓存。观察签按实际货物数量及当前位置计算，包含第七件货物、吊篮升降和卸货位移。

专项入口为森林与集市的 `presentation_playtest.gd`，已分别登记在原森林 runner 与集市航图门禁。可见窗口性能测量独立运行：`python3 tools/performance/run_benchmark.py docs/playtest/optimization-20260922/measurement.json`。它使用独立临时档、不抢桌面焦点，固定60 FPS上限，并记录真实帧间隔、引擎监测量和绘图指令重建次数；不能用最小化功能测试替代可见窗口性能测量。

## 存档与事务

默认正式档为 `user://profiles/local-1/save-v1.json`，`schema_version=1`。它独立于v1–v5试玩档，首版不自动导入试玩进度。`suspended_runs` 按关卡ID保存尚未完成的现场；切换到其他已开放关卡会先暂存当前挑战，继续主线不需要先解完支线。恢复复用同一run、隐藏情形、证据和帮助事实。

每个稳定命令在副本计算、聚合结算和校验后，写同目录临时文件、flush并检查错误，再替换正式文件。保存成功后才安装内存状态和播放演出。失败时保留原状态与同一个待保存候选，遮罩阻止后续命令；“重试保存”不重新计算奖励。这里只承诺已测试的逻辑保存/替换行为，不声称通过设备突然断电验证。

活动挑战保留参数快照、内容版本、队伍与能力配置。更改营地队伍只影响下次挑战。撤销栈只保留当前连续操作段；切到另一机关后或重启，恢复最后提交的稳定状态，仍可确认重摆。提示、尝试和学习帮助事实不随撤销或重摆抹去。

新增独立 `story.version=1`，字段为 `node`、`seen`、`choices`、`run_id`、`return_node`、`return_run_id`、`excursion`、`results`。当前节点就是最近稳定镜头；`results` 保存实际完成状态，经现有数学规则再次校验后用于演出。故事播放不写 `world.events`、奖励或队伍。结算与待播放后果在同一个候选内提交；继续与跳过后的节点确认使用节点ID及revision拒绝旧点击。

没有 `story` 的正式v1档先完整校验旧规则，再备份原字节和hash，依据活动/暂存机关、完成与伙伴事实迁移；未完活动机关优先，其次恢复主线暂存现场，旧完成记录没有新观演证明时落在短回顾，整章已通先到营地短回顾 `legacy_recap`，确认后进入终章营地停点。迁移保存失败继续保留精确候选，源文件变化则保护原档。

本机发现过一份开发中途生成的空白正式档：无完成、无活动/暂存挑战，世界部分恰好只有五个旧字段。仅对这一个已核验形状，先保存原始字节备份 `.before-world-layout-<后缀>`，再补两个尚未使用的空世界字段并保留设置；保存失败不安装，源文件变化则停止并要求重新读取。这一空白形状修补不猜测未知数据；另有上述正式v1叙事迁移。两者均不导入旧试玩档。

损坏、未知版本、参数不匹配及进度/奖励/经济不一致的记录会被保护。界面提供重新读取；玩家明确确认新旅程时，先把原记录原样移到 `.protected-<唯一后缀>` 文件，再创建空白手记。保留失败时不新建、不覆盖。此流程有独立临时文件测试，不在测试中操作真实玩家记录。

第七关替换使用新参数快照区分内容，保持其他关卡的 `forest-runtime-1` 不变。`legacy_fl07.json` 冻结旧规则、奖励与概念；加载时检查该资产和新关奖励一致。旧完成记录按旧规则验证，旧learning保留原context/concept，不伪造为24点。旧active/suspended FL07先通过旧规则校验，再原字节备份；旧run完整存入 `legacy_fl07_runs`，仅该现场替换为新数字卡，其他关卡、队伍、经济不变。新run ID带 `/24`，对应故事指针同步更新；新题提示不继承旧题提示标签。失败保持原文件与未安装候选，重试提交同一候选。

24点以三步以内的操作记录保存棋盘；每次验证从原始四张卡重放，卡不能重复使用或凭空生成。数值用约分后的整数分子/分母计算，不用浮点容差判24。

## 首领恢复与学习边界

FL17的一次提交包括玩家转移、符石扣除、当回合敌方回应和下回合阶段。恢复时通过轨迹重算校验，不能重复交换B/C。三盘同步后仍要由玩家发出“合力反击”。

FL18的有效侦察、消耗、次数和阶段一次提交；候选从有效观测重新计算。撤销同时回退这些字段，固定真身不变。历史观测另存，不能充当当前破壳依据；利用历史情报重新规划会留下 `replanned_after_observation`，不自动计作主动提示，也不扣RPG奖励。侦察回响20不算胜利，错误合击保留实际花费与结果供撤销。

学习记录只陈述本次完成、提示层、支持工具、尝试、撤销和有效轨迹。没有能力分、智力标签、学习效果百分比或“已掌握全部分支”。记录字段保留用于存档兼容，界面不再展示统计面板、练习建议或分步对照；同参数重玩保留既往帮助来源。

## 通关与旧档兼容

普通关的完成判定等于解开机关本身：货运把货物送达且趟数符合限定（FL11四件上行货对三块配重、恰好三趟且必有一趟两件同篮，FL13两趟）；转移敲响门环后的回响与目标吻合；灯架先把三对合称都量过、再把三架重量调到三对合重都成立；机器装法同时符合两页账簿；24点四张卡全部合并后精确等于24（FL07）；FL06投入后辨认出真机；邮路先估三层邮袋的数量、再收齐全部路线并正确归袋（FL08），或先猜最优位置、预测四处各留几条、逐处揭示对上后选中保留送法最多的落石点（FL09），或收齐全部不碰面的路线对（FL10）；守门人对局获胜（FL12）；石径走到10并只换一步修到9（FL14）；两次称量的结构能区分九颗晶体（FL15，称量时自动推导答案表并点名分不开的晶体）；试齐全部宽度、比较方案后选中真正面积最大者（FL16，五种方案入列表且围定3×6）。作者过程证据（倒放卡、时刻连线、光带分套、预测与驳回、40次分类、九答案表、策略表、终点集、长度减少量）已从通关条件移除；其中仍保留为可选探索的部分（如FL05的输出预测）不挡路。FL09/FL16/FL08 的"先猜后验"、FL04 的"先合称"、FL15 的具名"分不开"提示属于同一条思路：趣味来自先预测、再试验、最后得到确认。FL07 已替换为24点：1、4、5、9四张卡恰用一次，选择两张卡和运算逐步合并，只有最终精确24才完成；支持分数、负数、顺序交换、撤销、重摆与重开。FL10 存下路线对时会播放两封信同时行进的动画，碰面时按坐标点名。FL14 每走一步显示当前位置再走 N 步的可达集合（奇偶不变）。FL12 的守门人回应带性格台词。FL05 的预测是可选押注，不押也能通关。

存档校验允许 `active` 挑战的棋盘其实已经满足完成条件（旧严格规则下的残留现场）。恢复这类挑战时立即结算一次，奖励幂等不会重复；`complete` 标记仍然必须由规则成立，坏的结算记录继续被拒。

## 操作与资源

所有主要动作都有点选入口和标准键盘焦点；货运另有1–6选物件、方向键放置与Space松闸。数值可按加减按钮，或输入后按Enter明确提交。H请求主动提示，第三层及后续请求按当前棋盘/证据给下一步或恢复建议，实际文本随活动/暂存/完成记录保留并可回看。Z撤销，Esc取消/返回；走近途中也可Esc取消。设置支持音量、静音与缩短重复演出。

伙伴的观察签、前后记录、同源整组搬运、分组带、路签和影子探路只执行玩家自己的选择。整组不合法时整次拒绝。主线仍有基础工具，不依赖特定队伍。路签在当前路径、记录列表与手记可见；普通机关的可见同行者也使用该挑战冻结的队伍。

新像素资源、实际尺寸、alpha检查、切片与脚底锚点见 `assets/runtime/forest/actors.json` 和 `art/forest_release_assets.json`。图集按实际内容确定区域，不直接假定生成提示里的格子与脚底完全准确。原素材、旧源码、历史场景、字体许可和各版玩家存档保留。

## 验证入口

规则与持久化测试使用 `tests/forest/session_test.gd`、`p3_test.gd`、`p4_p5_test.gd`、`p6_p7_test.gd`、`p8_test.gd`、`review_repairs_test.gd`。它们通过真实命令结算18关并检验反例、奖励经济、档案恢复和故障重试。

窗口测试使用同目录的 `p2_playtest.gd`、`p3_playtest.gd`、`p4_p5_playtest.gd`、`p6_playtest.gd`、`battle_playtest.gd`、`p8_playtest.gd`、`review_repairs_playtest.gd`。此前关卡可用明确标注的命令夹具准备；被测新玩法向真实Godot视口投递鼠标/键盘输入。首领测试分支在测试专用会话中选择，不修改生产规则。

新流程规则/事务验证使用 `story_test.gd`，覆盖整章两种邮路顺序、四支线、回访、失败重试和迁移。`story_playtest.gd` 从默认生产入口用真实视口操作完成第一幕，覆盖1280×720普通播放、960×540全段静音跳过、暂停/失焦通知、停下读对白、结算与对白推进保存失败重试，以及支线完成返回原机关。`story_chapter_playtest.gd` 以真实按钮走到结局，机关由命令夹具解出，覆盖各幕后果绘制、营地成长并重开、FL09重玩另一最优位置后恢复原主线画面。历史机关窗口夹具显式设置 `story_enabled=false`，保留旧入口以隔离验证数学交互；它们不证明新的剧情导航。

全部自动化档案位于独立 `/tmp/pixel-forest-*` 路径。本轮记录与截图在 `docs/playtest/narrative/`（历史记录在 `docs/playtest/forest-release/`）；精确检查结果以候选清单为准。Godot进程退出0并不足以判定通过，还要检查断言汇总与脚本/资源错误日志。

窗口自动化通过测试专用可见 NO_FOCUS 原生窗口隔离桌面干扰；本机系统事件权限缺失时，runner 会跳过前台恢复的礼貌握手并继续执行（打印提示），其余断言不变。超时会终止并回收本项子进程。实际 OS 焦点切换仍需人工试玩。

真人思考时间、儿童适龄性、实际学习迁移、触屏设备、其他平台与安装包发布尚未由这些自动化检查证明。
