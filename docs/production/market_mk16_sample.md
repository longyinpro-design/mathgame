# MK16 给森林寄回一份礼物 — v1 样板契约

2026-09-20，第五幕「公平不只是一样多」的可选支线（`chapter_catalog.gd` 登记 `act:5`、`side:true`、`after:"MK12"`，灯会前最后一班红船那一晚）。题目与契约出自 `docs/production/market_chapter.md:240`（本关规则文件头部即引用这一行）：恰好 3 种不同纪念物、总重 ≤ 7 斤、必带绿叶章与信纸。只新增 MK16 一套文件（规则、世界、场景、入口 `game/market_mk16.tscn`、启动器 `启动千灯集市MK16样板.command`、无头/实窗检查与本契约），`kit_world.gd`、`level_host.gd`、`chapter_catalog.gd`、`chapter_progress.gd`、`market_hub.gd`、`hub_world.gd`、`market_bridge.gd`、`save_repository.gd`、`assets/**`、`art/market-kit-v1/manifest.json`、MK01–MK15 与共享测试脚本一律未改。

## 目标

- 大码头的货板上摊着四样纪念物，重量直接写在牌上：`绿叶章 2 斤`、`信纸 1 斤`、`杯 4 斤`、`铃 3 斤`（`WEIGHTS`）。红船只在 7 斤以内接单，一样纪念物只有一件，礼物要恰好 3 种。
- 必带的两样各有各的理由：绿叶章代表森林（「得让他们知道种子是谁种的」），信纸用来写回信；第三样才是玩家的偏好。两条都成立的礼物 `[绿叶章, 信纸, 杯]`（2+1+4=7，正好压线）与 `[绿叶章, 信纸, 铃]`（2+1+3=6，还余 1 斤）在 `SOLUTIONS` 里并列，`validate()` 也只认这两份包裹。
- 设计陷阱就是折羽先想到的那一笔：杯和铃都想带，`2+1+4+3=10 斤`，红船不接。台面上第 4 样在放的那一刻就被拒，拒的话用玩家自己摆下的数字说话。
- 独有回报：**偏好改变森林的回信，不改变主线奖励**。`reply_lines()` 头两句按寄出去的那一样走（白杯 →「那只白杯我们认得，量过春雨的那一只」；铜铃 →「铃一响我们就知道，集市的灯船开了」），后两句「种子已经抽枝 / 灯会那晚留一盏给集市」两条分支相同；`REWARD` 那句 `主线奖励不变：群岛回执册 +1 页` 与分支无关。本关不写森林存档、不发森林奖励。

## 机制与入账时机

- 幕序 `arrival → approach → ready → puzzle → loading → delivery → complete`，动画三段 `approach 1.6s / loading 3.0s / delivery 4.4s`（`ANIMATIONS`）；开场三句（扣扣 → 小岚 → 折羽）逐句「继续听他们说」推进，第三句已经把「杯和铃都想带」摆到玩家面前。
- 四个字段分清「摆上了台面」与「真的寄出去」：`table` 只是打包台上的草稿（放/取各一步，可撤销），`advance()` 在 `puzzle` 通过验收后一次性把 `gift = table.duplicate().sort()`、清空台面、并按 `present_of(gift)` 写下 `"cup"` 或 `"bell"`；`sent` 只在 `loading → delivery` 那一步置 1，红船真离岸才算寄出，也寄不出第二次。台面上的计数、每格空位、总重全部由 `Rules.total()/on_table()/slot_of()` 现算，画面不存第二份。
- 秤只念玩家自己摆下的数字：`table_plaque()` 一处出口同时供牌面与审计（`打包台 · 绿叶章2 + 信纸1 + 杯4 = 7 斤 / 上限 7 斤`），压线那一趟它照旧写「上限 7 斤」，不喊「刚好」也不喊「危险」。
- **柜面不判分**：`place()` 在两种情况下拒收（同一样第二份、放上去就超 7 斤），措辞用的是玩家自己那一串数——`杯 放不上去：绿叶章2 + 信纸1 + 杯4 + 铃3 合起来 10 斤。\n红船只在 7 斤以内接单。`、`信纸 已经在打包台上了：同一样纪念物不会有第二份。`、`打包台上已经有 3 样：先把一样放回货架，再放 铃。`；提交那一刻 `shortfalls()` 才说缺哪条承诺，一次只报第一条并附「（还有 N 处没有归位）」——`纪念物要恰好 3 种：台面上只有 2 样（绿叶章2 + 信纸1 3 斤）。\n再从货架点一样：先把杯放上台面。`、`包裹里没有绿叶章：那是森林的东西，得让他们知道种子是谁种的。`、`包裹里没有信纸：没有能写字的纸，森林收到礼物也没法回信。`。没有训斥模态，被拒之后台面一件货都不动。
- `loading` 的 3.0 秒是一趟连续动作：前 40%（`WRAP_AT`）三样各自滑进 `parcel_seat()` 淡出，之后包裹（`parcel_medium`）从打包台沿弧线抬上红船甲板（`CARRY_END 0.9`）；`delivery` 的 4.4 秒里红船从 `boat_red` 往两船中点 + (70,−26) 驶出、缩到 0.4 倍宽、淡到 0.62 透明度，progress 过 0.45（`REPLY_AT`）后打包台上留下 `receipt_blank` 的五行收讫（含 `吊牌 · 白杯` 与 `红船 · 已离岸`）。系在最外面的那一件始终是玩家挑的那一样，从码头、船上到回执一路带着它。
- 每步操作先原子落盘再生效（宿主 `commit()`），写盘失败弹「重试保存」，重试才发布这一笔——动画不会替玩家先把礼物寄出去。撤销快照只存内存且只含 `table`（`snapshot()`），交货之后的撤销一律被 `restore()` 拒掉。「重摆」的确认是 `把选中的那一样放回货架？\n必带的绿叶章和信纸留在台面上。`，`cleared_state()` 真的只收回玩家那一点偏好，台面上本来就只剩必带两样时它返回空、连撤销步都不产生——问过的推理与已经想清楚的两样都不被没收。
- 放货/取回用世界自己的钟（`landed/lifted` + `PLACE_TIME 0.34`）；基类 `transient` 的落地锁对 kit 关卡不生效（MK02/MK03 已记，见交付文档），所以两种基类下画面一致，检查里每一步都先把动画读完再点下一步。

## 存档字段

- 独立存档 `user://profiles/market-mk16-1/save-v1.json`，schema 由 `scripts/market/mk16_rules.gd::validate()` 把关；`configure()` 只在 `save_path` 为空时填默认值，试玩注入的 `/tmp` 路径不会被盖掉。
- 八个字段：`sample="market-mk16-1"`、`stage`、`beat`（0–2）、`table`（0–3 个互不相同的纪念物编号）、`gift`（封好的那一单，升序）、`present`（`""`/`"cup"`/`"bell"`，集成方要读的键）、`sent`（0/1）、`hint`（0–3）。
- `validate()` 拒读并把原文件交给 `save_repository._protect()` 保留的情形：非字典、外来的 `sample`、未知 `stage`、`beat`/`hint` 越界、`table` 或 `gift` 里有未知编号/重复/超过 3 样、`present` 非字符串或 `sent` 非 0/1 的整数、台面或包裹合计超过 7 斤（这条与 `shortfalls()` 同源，改坏的存档休想蒙过去）。
- 语义层面再拒：`stage!="arrival"` 却 `beat!=2`（凭空跳步）、`arrival/approach/ready` 台面上已有货、`puzzle` 却带着已封的包裹、`loading/delivery/complete` 台面上还有货 / 包裹不是那两份有效礼物之一 / `present` 与包裹对不上、非打包的幕里 `gift` 非空或 `present` 非空串、`(stage ∈ [delivery,complete]) != (sent == 1)`（没上船却记成已寄出，或已上船却写 0）。JSON 把 1 读成 1.0 由 `Content.normalize_numbers` 归回整数。

## 操作与键盘

- 鼠标热点：货板四样 `shelf_0..3`（`68×54`），放上打包台后同一个动作改挂在 `slot_0..2`（`70×58`，跟着格位走，所以再点一次就是放回货板）；红船本身是提交闸口 `boat`（`132×86`，`advance` 与底部「封箱上红船」同一条路）。开局 5 个目标、摆放中途仍是 4 + 船，每个都 ≥48 逻辑像素且带中文 tooltip（`绿叶章 2 斤 · 在货板上，点一下放上打包台` / `… 在打包台上，点一下放回货板`）。
- 键盘：`1/2/3/4` 对应货板上那一排四样（放上/取回同一个键）、`Space` 封箱上红船、`Z` 撤销、`H` 请扣扣提醒、`Esc` 暂停动画；动画中另有「暂停动画 / 跳过当前动画」。
- 镜头：`zoom_stages=["puzzle","loading"]`，两幕贴近打包台与货板（1.10、偏移 −64/−43，宿主 `update_camera`），`approach` 渐进、`delivery` 后半程拉回整片港口好让船驶出去。
- 提示三级（`hint_texts()`，白板内框 798×56、每档最多两行）：必带的两样与货板上写着的 2/1/4/3 斤 → 必带两样已经 3 斤、第三样最多再挑 4 斤 → `2+1+4=7 与 2+1+3=6 都过得了秤`，并点明「杯和铃都想带？两样一起就是 10 斤，红船不接」。三级都不替玩家放货、不减奖励、不画高亮。
- 落点全部读 manifest 的 `dock` 站位再加算术：台面三格 = `grid(packing −(74,0), 步距 74, 3)`，货板四格 = `boss_foot + (−330,−43)` 起、步距 88，扣扣与秤 = `boss_foot + (120,0)`，离岸目标 = `boat_red` 与 `boat_blue` 的中点 +(70,−26)。

## 边界与已知限制

- **没有新裁图**：纪念物只有两件是 kit 拆件（`paper_roll` 信纸、`brass_bell` 铃），`parcel_medium` 包裹、`receipt_blank` 收讫纸、`transport_boat_red/blue`、`navigation_lantern` 也都来自清单；底景是 dock 的 `grand-dock-clean-v1.png`。**白杯不在 kit-v1 里**——它是 MK01 那张机制图源表 `assets/source/market/mechanisms-source-v1.png` 的 `Rect2(376,176,249,179)` 子图，引用现成图块而不是新裁美术。**绿叶章全部由引擎画**（三层圆 + 两片 `draw_colored_polygon` 的叶子 + 一茎），因为清单里没有徽章件；系在包裹外的那截绳是一支 `draw_line`，kit-v1 也没有扎绳/礼带件。
- 领航灯的发光点用 manifest 的 `attachments_px.light_center` 与 `anchor_px` 换算（`dock` 场景给了这个挂点），不像 MK12 那样要抄别关的常量。
- `dock` 场景没有 `koukou_stand` 站位，所以扣扣的脚点与货板都从首领站位 `boss_foot 767,603` 推出来（这是复用，不是新的港口设定）；她同样只有 `tie-parcel/waving` 两个离散姿态。衡伯与船老大只在台词与拒收措辞里出现，画面上没有人物拆件。
- 数学真值（检查穷举四样的 16 个子集过 `shortfalls()` 比对）：只有 `[0,1,2]` 与 `[0,1,3]` 通过验收；`place()` 已经把「第 4 样」与「放上去就超 7 斤」挡在台面之外，`shortfalls()` 里那两条超上限的话是同一套措辞的兜底——真被改坏的档在 `validate()` 就被拒读。缺少必带项的 4 样子集（如 `[0,2,3]` 9 斤、`[1,2,3]` 8 斤）各被点名一次，另一样不缺的项不被牵连。
- **没有失败台账**：`sent` 只有 0/1，被拒不记次数、不记错在哪，改摆放再寄即可；这是有意的支线定位。若后续要收集「按上限选物」的过程证据，应在 `chapter_progress.gd` 一侧补读取，而不是往本关存档里加字段（多出来的键会被 `validate()` 判为改档）。
- 中文一律显式换行：`plaque()/words()` 不会折行，所以每条拒收与差处说明都控制在两行、白板 826 宽以内（检查按整宽/半宽估字并逐条量过）；收讫那五行共用一个左起笔（`packing` 往左 46、上方 −132…−42，全部由 `letter_rows()` 一处给出），不压货板（x 437 起）也不压秤边的扣扣，审计按 `receipt_blank` 的真实纸框量过：两条分支共 10 行，最宽的一行占到纸面 82%；回执面板 `Rect2(660,176,470,190)`、内框 442×166、15 号字，实窗量过它容得下自己那六行。
- 打磨轮（逐关细节复核）在本关修掉六处，全部是几何与读数、一条断言都没有放宽（船上吊牌那条的阈值仍是 8%，只是量的那块换成了包裹真正画出来的矩形）：① 打包台那块读数横牌原先按台面中线 (216) 左右对称摆，左沿落在世界 x 4，而 `puzzle` 是 1.10 贴脸镜头、可见区从世界 x 58.2 起——牌上前 44 像素的字永远在窗框外；现在从世界 x 80 起头，镜头里正好是屏幕 x 24，与顶上那块关卡名左沿对齐，宽度按 15 种摆法逐句量过（最宽一句 318 像素）从 424 收到 340。② 红船泊位在清单给的 (460,227)，那是海平线附近的水面，包裹与吊牌从封箱到离岸全程躲在宿主台词板底下（`09/10/13` 三帧里包裹一格都没露出来，两条分支在审计框里只差台词的字，差 5%/6% 低于阈值）；挪进两条栈桥之间的水道之后逐帧扫 78 帧，包裹被台词板盖住的比例最大 **0%**，船上那一块两条分支差 14%。③ 船形热点原先是 `target(foot+(0,46),132,86)` 那块 132 见方，船挪下来之后它正好压在打包台读数牌（世界 y 397..425）上，玩家点牌子的右半下等于点「封箱上红船」；现在贴着吃水线以上那截船身 `Rect2(foot+(-72,-78),(144,84))`，并补上「五种摆法的热点两两不相压」与「读数牌底下不藏任何热点」两条穷举。④ 演出那一格的底栏原先报「已选 0/3 · 共 0 斤」——封箱后台面确实空了，可宿主每一幕动画都会画 `status_line()`，于是这句话把正在裹进包裹、正被红船带走的那三样说成什么都没有；现在 `PACKED` 三幕改报「已封箱 3 样 · 共 7 斤／6 斤」，两条分支各自报自己真正寄出去的那个数。⑤ 收讫纸五行用了两套左边界（标题 −40、正文 −46），一张小纸上像漏排了一行；统一到 −46 并把五行收进 `letter_rows()` 一个出口，绘制与审计读同一份。⑥ 落货那 0.34 秒里格位先有一片影子（`contact()` 用满不透明度，货还在半空），看着像这一格本来就空着；影子改成按 `placed_progress()` 淡入。
- **dock 这条水线天生贴着台词板**：清单把 `boat_red` 放在 (460,227)，那是海平线附近的水面，而宿主台词条钉在屏幕 (338,98,826,86)、带阴影到 191，1.10 镜头换算到世界是 y 128.2..212.7——船身 165 高、包裹 52 高、吊牌再加 40，谁把货放在这条船的甲板上就整个被板子吃掉。本关因此把泊位往岸里挪（`BERTH_SHIFT (-52,143)` → 世界 (408,370)，背景实测 x 359..460 在 y 270..375 全是水面，两条栈桥之间的那道水沟）；同一张底景的 MK10 量到的也是这块板（船在任何一档镜头下都被切掉约一半），换船位是本关一级的解法，`art/market-kit-v1/manifest.json` 的站位没有动。
- 入口 `game/market_mk16.tscn`（航图上由「尚未制作」转为待点亮的支线，开门条件 MK12 完成；`chapter_progress.gd` 只读本关存档 `stage=="complete"` 才补记灯火），或双击 `启动千灯集市MK16样板.command`。从航图进来完成后给「返回千灯航图」，单独启动本关给「回千灯航图」（`Rect2(690,646,280,54)`）。
- 无自动求解、无高亮答案、无提示罚分、无失败重播；两条分支的出口文案与主线奖励完全相同。
