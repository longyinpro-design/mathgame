# GW05 · 七拍能做完吗

2026-09-24。按 [GW01契约](workshop_gw01_sample.md) 同一套三年级奥数难度与制作原则实现。核心思考是「最早时刻与下限、安排顺序」：先算出抛光机不可能早于第7拍完工，再让钻孔带按抛光带需要的顺序喂料。不是原章节里的基础分组轻关，也不声称已通过儿童难度实测。

## 可玩契约

三件工具都在第0拍就绪，都须先钻孔再抛光。一台钻机、一台抛光机，每台一次一件，不能中断；机间暂存不限制。

| 工具 | 钻孔 | 抛光 |
| --- | ---: | ---: |
| A | 3拍 | 1拍 |
| B | 2拍 | 3拍 |
| C | 1拍 | 2拍 |

抛光共 1+3+2=6 拍，且最早也要等第一件钻完才能开工，所以第7拍已经是下限。让抛光机一刻不停：钻 C 0–1、B 1–3、A 3–6；抛 C 1–3、B 3–6、A 6–7，正好第7拍完工。整数时刻下只有这一套7拍计划——单纯先做钻得最久的 A，抛光机只能干等，达不到下限。

- 完成时刻由两条带上的顺序现算，画面不替玩家记时刻；同一台机上的工序不能重叠，抛光也不能早于这一件钻完。
- 接受所有达到下限的合法排法，不硬编码示例顺序。
- 四档主动提示依次为：两台机各要忙6拍 → 抛光最早何时开始 → C先做好能接上谁 → 给出完整两轨示范。默认不显示解，也不自动填关键中间量。

玩家先把三件在钻孔带上排一遍顺序，再排抛光带。两条带都排满才允许试运行，没排满时先说清缺几件，不进演出；试运行错排也能看到这一套实际几拍完工、卡在哪一条约束，宿主只拦「没排满」。跑完对照下限，主动确认才进入剧情，也可中途取回重排。

## 操作与存档

- 启动 `启动齿轮工坊GW05样板.command` 或 `game/workshop_gw05.tscn`。
- 鼠标完整可玩；1/2选钻孔带/抛光带，Q/W/E把 A/B/C 排到当前带末尾，点带上的块取回重排，R取下当前带最后一件，Z撤销，X确认重排，H主动提示，Space试运行。保留Tab/Enter焦点操作。
- 重排、重玩有确认。撤销与重排保留提示与尝试次数；每次改动保存成功才生效。
- 新独立存档 `user://profiles/workshop-gw05-1/save-v1.json`，不读写、不删改其它关卡档案。持久化两条带的顺序、阶段、对白停点、提示级别、尝试次数；完成时刻由顺序现算，越界工具号或错长度判为损坏档。
- 沿用SaveRepository事务、失败重试和损坏档保护。单独临时测试档不接触玩家进度。

## 场景与后续

保留已认可的装配间背景与钻机、抛光机、工具源图；小岚由宿主常驻现场。两条工序带横贯画面，从第0拍到第12拍逐格对齐（最糟排法先做 A 要到第12拍才完工，超出画面的拍数不画）；工时牌挂在右侧，完工时刻与下限由引擎绘制。手动逐步停顿便于比较顺序，失焦和模态暂停表现。

修理街的折窗依次打开。嗒嗒发现「先找做完的下限」比「凭感觉排」更快。只完成GW05，不扩展GW06、跨岛解锁或伙伴加入。

## 验证

规则测试独立枚举钻孔带与抛光带的全部合法顺序组合（含半带），用独立的逐拍模拟器重演每一套排法，验证唯一解（钻 C-B-A、抛 C-B-A，第7拍完工）与每套的下限判定。窗口测试覆盖1280×720、960×540的输入、错误试运行、取回重排、换带、撤销、保存失败重试、重载、发现卡及损坏档保护。实际命令与候选身份见 `docs/playtest/workshop-gw05/verification.json`。

这些检查证明规则与交互实现；小学三年级学生的实际挑战感、理解和学习效果仍须真人试玩。
