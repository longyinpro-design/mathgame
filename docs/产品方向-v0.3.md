# 数字群岛：数学伙伴 RPG — 产品方向 v0.3

日期：2026-09-08。

用户明确方向：Prodigy 的 RPG 世界 + Pokémon 的收集养成 + DragonBox 的数学即玩法 + AI 动态剧情/自适应难度。用户认可 v0.2 的难度层次，指出画面、动画、交互与独立游戏品质仍有明显距离。

本文件记录产品方向与建议范围；本轮进行了官方资料对照，不代表完成竞品实际试玩、视觉逐帧审计或下述新系统实现。

## 定位与核心循环

面向既定小学阶段玩家的原创数学伙伴 RPG。探索群岛，发现并结识伙伴，运用可操作的数学能力修复世界、完成遭遇挑战，培养伙伴并打开新的探索路线。

探索 → 发现事件/伙伴 → 观察规则 → 操作数学能力 → 场景与角色反馈 → 结识/培养伙伴 → 新能力改变探索方式。

保留两阶段约束与迁移的设计思路；目前的三角阵只承担一种机关类型。完整产品需要世界、遭遇、伙伴与成长之间的循环。

## 四项在本项目中的职责

- RPG世界：有道路、可进入地点、NPC日常动作、遭遇、任务结果与可回访变化。文字辅助表达目标，主要行动发生在场景对象上。
- 伙伴养成：首次相遇/帮助/结识、跟随、互动、图鉴、技能与一次可见成长。不同伙伴提供分组、平衡、镜像等不同操作方式；玩家仍需完成推理。
- 数学玩法：分拆、合并、均分、交换、平衡、旋转等操作直接影响能量、护盾、路线与机关。必要数字由引擎准确绘制，动画有因果含义。
- AI：在作者定义的世界事实与剧情节点内选择/表达事件，根据跨次操作与迁移证据选择下一次挑战和提示。AI不直接决定答案、奖励数值、存档状态或已开始谜题的规则。

例：一场石灵遭遇需要把14格能量分给两面护盾，右侧比左侧多4。玩家直接搬动晶体，形成5与9后，伙伴分别释放对应能量；错误分配通过护盾充能和失衡状态表现。数值、条件及通关由确定规则验算。这是候选玩法示例，正式纳入前还需把动作、图形表示和失败反馈做成可玩的样板。

## AI动态剧情与自适应设计边界

- 剧情有作者定义的开端、关键事件与结局。AI可根据玩家已见事件、当前伙伴和选择改变NPC措辞、支线顺序及氛围事件；不改写既定角色身份或已发生事实。
- 自适应以知识点/操作类型为单位。使用帮助、错误类型、跨情境迁移与重复表现作为证据；不从一次答对或操作速度推断掌握。
- 在下一次遭遇调整条件数量、推理步数、图形支架或内容参数；当前挑战开始后规则固定。
- 题目参数经过求解器或枚举验证，学习模型选择可用难度层；语言模型可解释或提出候选，不能绕过判定与验证。
- 保留作者编写的剧情与挑战，使AI服务不可用时仍能完成主线。
- 接入外部AI前明确供应商、费用上限、发送字段和可用性要求；当前未调用付费推理服务，也未发送儿童数据。

## 建议下一交付：一个完整、精制的RPG样板

目标范围建议：一个森林区域，含营地/林道/遗迹三个连通小场景；三种原创伙伴，其中一种可结识入队并完成一次成长；一条主线、一次可操作的数学遭遇、一个环境机关；一个规则受控的自适应分支。15～20分钟为待试玩验证的目标。

制作顺序：

1. 确定探索画面、遭遇画面、伙伴界面的视觉稿，以及角色尺寸、视角、像素密度和动作规格。
2. 先打磨一段60～90秒的真实操作：移动/接近/互动/施法/命中或失败/伙伴反应/奖励。验证角色、美术、镜头与声音能形成完整反馈。
3. 扩成一个可结识伙伴、完成挑战并回到营地的循环，再扩展到上述样板范围。
4. 在稳定的剧情节点、知识点及验证过的难度层上接入自适应和AI表达。

不以增加地图数量、对话量或粒子数量代替品质验收。当前 v0.2 原型与其难度证据保留，作为规则和流程基础。

## 表现验收建议

- 角色至少具备待机、移动、互动、施法、受影响、胜利反应；伙伴有可辨认的独立反馈。
- 石头、能量、护盾等使用独立运行时素材和明确动作过程；主要操作通过对象拖动/点击完成。
- 一次动作具备准备、执行、结果、恢复的节奏，配合对应声音；重要演出有镜头关注点。
- 主要场景有可操作前景、角色活动层、背景深度；关键环境变化不依赖文字宣告。
- 对话精简，信息可通过物件状态、角色动作和可回看的笔记理解。操作目标与当前反馈保持可读。
- 正确性、存档验证之外，加入实际设备上的动作/声音检查与目标玩家试玩。首次读懂目标、主动探索、对伙伴的兴趣和迁移表现分别观察。
